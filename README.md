# PEAK 回忆录 — Replay Lab 0.8.36 实验版

独立维护仓库：[luyongyi/peak-memories](https://github.com/luyongyi/peak-memories)。开发和测试方式见 [开发说明](docs/development.md)，一键构建／发布见 [发布说明](docs/releases.md)。仓库包含 Mod 源码、合成测试、文档及原创封面；游戏资源和私人录像保留在本机。

独立 DLL，入口在 **PEAK 游戏主菜单**。本地录制与回放无需服务器；轨迹上传为可选功能。
进入关卡后自动缓存最近最多 120 秒，**F6 随时保存片段**；完整录制是独立开关，可以同时使用。
在主菜单「回忆录 → 录制方式」开启完整录制，或用 **F4** 开启／关闭；关闭时封存当前录像，保留片段缓存与设置。
从回忆录选择录像，自动加载原场景，使用本机原版模型、历史装扮与记录的真实骨骼姿态重演。观看时不再录制。

普通物品以任意被录制玩家周围 **40 米**为详细采集范围，配置项为 `Recording.ItemCaptureDistance`（米，`0` 关闭距离休眠）。已识别且被游戏固定的普通静物保存首次快照后，由事件唤醒；拿取、投掷、受力、真正变化的物理同步和状态变化后进入活动采集。静止且没有持有、真实动作或未结束事件时保存末态并休眠，玩家仍在近处也可以停止几何采样。未知行为或可运动刚体保留限额轮转检查；生物、真正推进的动画和持续物理活动单独处理，灯光与特效独立采集。休眠对象仍保留在回放中。检查间隔内未通知的外部脚本变化不能补出。

### 0.8.36 上传去重与静止区间

已成功上传的封存录像按录像身份、目标地址及导出版本记录本机回执，再次选择时跳过轨迹解析和发送。中断的分包保留已确认状态，只发送尚未确认的包；缓存损坏或录像修改会重新准备。缓存命中的完成页可主动「重新上传」，只重置这一份录像的确认记录。移动录像目录视为新来源，不沿用旧路径的缓存。

上传格式 `trajectory-v2` 将坐标不变、采样间隔相同的连续点压成无损区间，保留每个原采样时刻和全部必要事件。服务器展开后继续使用原 `trajectory-v1` 的身份、分关和热力逻辑。网站服务器必须先支持 v2，再安装新版 Mod；旧上传格式和已有轨迹继续读取。录制与回放本体格式、采样和跳转路径不因此改变。

### 0.8.35 轨迹实测与解析边界修复

使用真实录像和实际 Mod DLL 对照完整导出：22.15 分钟／72.05 MiB 录像三轮中位耗时由 16.00 秒降至 1.85 秒；43.06 分钟／1.45 GiB 旧录像单组对照由 92.81 秒降至 29.87 秒。新旧全部轨迹 JSON 摘要一致，坐标、事件和元数据没有变化。测量使用独立 .NET 8 进程，包含导出压缩和落盘，不代表 Unity Mono、主线程耗时或游戏帧率。

追加测试发现并修复了跳过字段仍接受 JavaScript 非法 JSON 值的问题；49 项轨迹、1,271 项回放协议、15 项上传检查通过。真实导出包通过本地 Web 接收、存储一致性及重复上传检查；Web 索引读取另以最多 16 路小文件读取优化，已独立提交 PR。完整方法、数据和限制见 [轨迹实测报告](docs/trajectory-validation-0.8.35.md)。

后续原生 Unity/Mono 对照中，22.15 分钟录像由旧版 58.14／58.75 秒降至 2.96／2.51 秒，完整输出相同；新版大录像约 100.50 秒，取消后重试及重复上传通过，但仍有两次超过 100 ms 的帧间隔。0.8.35 已恢复安装，存档／配置未变；Web 优化已合并并部署上线。经用户授权清理 37 份旧发布／失败残留，服务器可用空间恢复约 34 GiB，保留新版和四份回滚，玩家资料未删。详见 [游戏内验收及部署记录](docs/trajectory-native-0.8.35.md)。

### 0.8.33 雪堆、雪球与轨迹准备优化

补录原生 `FakeItem` 静态采集物的显隐：雪堆取走后隐藏，原生拒绝拾取时恢复，倒序跳转保留当时状态。首次只读取根位置和显隐，之后由事件唤醒；不逐帧遍历这些对象的模型、骨骼或材质。静态目录与变化状态跨页共享，Schema 27 保留独立跳转页和 1 GiB 按需缓存。

雪球滚动增长由原生已经应用的模型／碰撞体尺寸变化唤醒，地面按原有最高 5 Hz 观察，回放平滑重建；相同尺寸通知合并，静置后继续休眠。旧录像没有记录的雪堆隐藏事件或中途尺寸无法补回，需要新录制验证。实现与实测范围见 [雪堆／雪球修复记录](docs/snow-replay-0.8.33.md)。

上传前的轨迹准备复用一次校验的索引，独立页面最多 4 路后台解码，并限制批次的索引估算解码量；按原时间顺序生成轨迹。通常在首遍同时收集元数据和轨迹，省去第二次全量解码；超预算时保留原有完整成员分包回退。按用户要求，本次追加优化只编译和静态审查，未执行新的性能或游戏测试，未宣称加速倍数。细节见 [轨迹准备优化](docs/trajectory-preparation-0.8.33.md)。

静态水豚及游戏自身已经禁用动画的已核验食人花可停止几何采样。食人花启用中的待机有真实骨骼运动，咬人、松口与回正仍采集。Schema 26／容器 v4 将大静态生物目录和身份顺序跨页共享，并省略已知为空的数组；所有共享与压缩仍在后台，独立跳转页和 1 GiB 按需缓存保持原有预算。详见 [0.8.31 修改与原生验证](docs/event-reference-capture-0.8.31.md)。

最终 DLL 的 379 次原生姿态对照通过；另跑五关性能路线，33983 帧／587 页完整保存读回、20 次跨关反向跳转恢复播放，缺失为零。森蕈／雾沼稳定完整页增长约 1.98／2.85 MiB/min，上一版同路线约 2.98／4.67；平均采集调用约 0.467／0.433 ms，海岸变化小且 CPU 未下降，偶发长帧仍在。首次候选的目录绝对时间错误已修复并补非零录制起点回归；报告保留失败证据、统计口径与未覆盖范围。

### 0.8.30 低频观察与原生动画引用

活动生物和地面活动物品的常规昂贵读取降至 5 Hz，回放按独立真实观察时间平滑，实际动作与显隐边界立即记录。玩家骨骼及持有物品沿用原频率，队友模型沿用网络同步。乌鸦已核验的待机／飞离、青蛙地面待机和 EarlyWorm 已核验动画使用游戏资源引用与时间锚，稳定时跳过骨骼、形变和外观的重复遍历。声音、羽毛、爆炸及烹饪变化继续由各自状态／事件轨复现。

连续物理包、风力通知和燃料数值不再冒充新的动作事件；静置后的采样会结束，短动作细节窗口不无限续期。Schema 25／容器 v4 继续使用独立跳转页与 1 GiB 按需缓存；未知资源保守回退。5 Hz 未知物理姿态的中间运动属于近似，完整策略、实测与范围见 [低频引用验证](docs/sparse-reference-capture-0.8.30.md)。

最终原生同路线雾沼稳态由 10.10 降至 4.63 MiB/min，接受帧平均采集调用由 1.19 降至 0.53 ms；静置物品时间及乌鸦纯相位校准复用旧骨骼／外观。12,806 帧、227 页完整读回，6 次跨关／反向回跳缺失为 0；独立原生动画视觉候选 354 次对照通过，最终求值器 IL 一致。偶发长帧仍在，未据此声称 FPS 提升。

### 0.8.26 原生资源引用与采集读取缓存

声音、特效和模型继续由稳定标识解析游戏原生资源，录像不包含音频 PCM、网格顶点、纹理像素或着色器资源文件；时间、位置、音量、状态、运行时外观和真实活动骨骼仍按需要记录。本轮缓存每个声音源的不变片段元数据，并在同一次采集批次共享材质描述，减少主线程重复访问 Unity 属性；声音动态字段仍按原有最高 20 Hz 时钟观察，材质变化在下一批次重新核对。

保留 Schema 23／容器 v4、旧版 v1–v4 读取、独立跳转页和 1 GiB 按需缓存。进一步拆分资源字典的 v5 实验已回退：同源全量重写仅额外节省 0.342%／0.583%，没有明确配对解码收益。最终 DLL 已完成原生海岸到雨林验证：68.12 秒、4001／4001 帧、3,883,061 字节，8 次跨关跳转完成，两个孢子特效副本均有可见粒子；69 页全量读取通过。主回归 1202 项、片段元数据 6 项和原生外观 59 项等测试通过，未据此声称 FPS 提升。资源边界、完整对照和剩余验收范围见 [0.8.26 技术记录](docs/native-resource-references-0.8.26.md)。

### 0.8.25 原生事件复现与分帧跳转准备

新录像的粒子特效记录原生资源、出生／停止事件、发射参数、随机种子和必要的发射器姿态；回放用游戏资源重建视觉，不再默认读取或保存每个粒子的状态。静置发射器的模块保留初态和真实参数事件，持续动画与运动另按活动程度观察。箱子、行李、气球和互动机关补齐原生生命周期边界，真实动作与短特效仍即时记录。原生声音池的创建／播放／停止事件唤醒采集，已知空闲池免去持续查询。

未进入的地图变体和关卡继续由原生归属隔离；本版还识别 `segmentParent` 外、但处于同一原生 `Biome` 内的静态场景对象，避免未来关火炬提前进入录像。远距离回跳只按目标处仍需播放的声音准备资源，每帧最多触发一次原生声音载入。跨关跳转还把地图根切换分到缓冲期间的多个渲染帧，每帧最多执行一次昂贵的原生切换；准备时以画面遮罩和提示覆盖未完成的场景，回放控件仍可操作。同关跳转仍直接应用，连续改选目标时按当前场景状态重新准备。页面继续按需读取，解码缓存上限仍为 **1 GiB**。单次 Unity 原生调用和全局内存回收仍可能产生短卡。

新录像为 Schema 23，继续读取兼容旧录像。原生续档样本约 60 秒、4.31 MB；上一版同存档另一次约 60 秒、5.88 MB。两次玩法状态和时机并非完全相同，不能直接推算整场体积或 FPS。未来关火炬未进入新录森蕈录像；最终 DLL 的跨关测试观察到两次孢子爆炸出生、两种原生特效的可见粒子和八次跨关回跳。同源 43 分钟旧录像的六次远跳全部恢复播放，就绪约 0.356–0.725 秒；地图切换的播放提交阶段最高约 0.31 ms，但缓冲阶段的单次原生切换仍达约 47 ms，测试中仍有短卡。详情见 [0.8.25 技术与验收记录](docs/native-event-capture-0.8.25.md)。

### 0.8.24 自动完整录制的首帧失败恢复

自动完整录像改在首个通过验证并进入滚动缓存的帧上创建文件，并将该首帧直接写入。恢复存档期间首帧暂态异常不再消耗当前场景唯一的自动启动机会；文件创建失败、手动关闭及已经开始录像后的失败仍保留停止规则，避免每帧重试文件操作。

已安装并完成原生「继续冒险」、海岸点火到雨林、六次跨关回放跳转测试。原存档及录制设置未变，临时测试插件已移除。续档原始故障本次未复现；仍发现首次初态补齐慢、网络物品归属不全及部分特效能力指标的限制。实测结果见 [0.8.24 验证报告](docs/continue-adventure-capture-0.8.24.md)。

### 0.8.22 非玩家活动采样统一最高 30 Hz

周期性全场扫描已移除，无GC重叠的采集最大耗时降低；补齐内容后的采集平均、全局GC次数及渲染帧P99仍高于旧版，不能据此声称总开销下降或全部卡顿消失。新增箱子外观轨实测平均0.048 ms、最大0.222 ms。GC重叠调用耗时并非GC独占耗时，也不能直接归因于某条采集轨；此Unity运行时没有可用的逐线程分配计数。这是短时固定场景对照，不代表所有地图或多人负载。

验证包括1000项合约检查、真实Schema15录制34页／1870帧的全量及反向读取、最终DLL新录像8次前后暂停跳转，以及9组粒子模块61帧采集→保存→解码→6次重建。模块覆盖原生资源及受控的水花、摆斧、催眠球和粒子管理器入口，并精确检查幽灵球发射面、自定义粒子空间与蜂群力场的世界姿态；营火／后处理模块完成同样6次跳转和退出恢复。提示音仅验证两次原生GUI调用的事件采集、保存及回放资源解析，未做听感或真实灵魂柱玩法验收。

同一最终DLL的旧孢子片段完成6轮往返，7次爆炸均恢复30/30粒子，暂停时相位与粒子时间不推进。新录像每次跳转检查20个活动箱、134个渲染器和164份材质；颜色按Unity自身MPB读写往返作精确比较，最大约5.96×10⁻⁸的gamma读回量化差异不代表着色值变化。本次箱子没有动态灯光样本，不能据此声称所有灯光变化已实测。

录制前已存在的循环火焰／烟雾只能在有界历史内近似重建，新录像8跳中的7组均显示但保留近似标记。受控模块没有触发玩家实际点火、罗盘施法或传送门通关；部分子动画／脚本回调与未出现动作仍未实机逐项验收，不能声称游戏百分之百复现。

### 0.8.9 孢子爆炸与覆盖审计

- 修复出生落在两次采样之间的一次性粒子爆发被预滚跳过：只使用真实相邻样本和原生相位恢复出生，不用跳转目标姿态填补缺失历史；保留按需读取和分帧预算。旧录像已有孢子爆炸数据的片段也能修复显示。
- 孢子陷阱改为原生触发协程实际完成爆炸／停用后通知采集，避免提前消费状态变化，导致地雷约一秒后才消失。旧录像已经录下的延迟不能改写为真实时序。
- 对当前游戏程序集及实际资源重新核查后，确认尚未全覆盖所有独立生物、道具附加效果和世界机关。已有身体采集不等于附带粒子、射线、声音、文字都完整；具体已支持路径、明确缺口和待实机验收项见 [0.8.9 完备性审计](docs/replay-coverage-audit-0.8.9.md)。本版没有把未记录的行为伪造为原始录像。

### 0.8.8 跳转后连续播放短卡

- 旧页完整解码直接读取类型化数据，去掉每帧中间 JSON 对象树。规范记录先检查完整语法，再直接转换数值，减少临时字符串与装箱；非规范语法保留原解析路径。特效历史只提取所需字段。已有数据格式、数值精度、人物关节独立时间戳和历史帧不可变性保留。
- 每页读取器有界复用完全相同的短向量和完整物体节点，比较浮点位并保留正负零差异；缓存冲突只替换引用，不修改已解码的历史帧。人物二进制关节的独立采样时钟不参与节点复用。
- 同一录像的完整页、特效历史及快速缓存共用一个独占租借的文本缓冲池，避免大型页首记录每次重新扩容产生约 32 MiB 临时数组。池只按需保留一块最多 16 MiB 的字符缓冲，不保存画面对象；并发读取各自租借，取消和异常归还，关闭回放释放。它属于读取工作内存，与 1 GiB 解码页缓存分别计数。
- 预热下一段实际需要的两页关节索引；当前页已有完整真实采样时释放不必要的前驱依赖，减少跨页重建和等待。关节可采样范围在后台建索引时计算，播放时直接查询。
- 复用读取调度、HUD 插值、数据校验及特效资源查询的临时存储，移除物品、生物、绳索等呈现循环内的闭包分配。缓存仍按需载入，上限 **1 GiB／64 页**。
- 性能报告记录当前录像文件名，以及包含读取等待在内的短卡帧、播放时钟和全局回收计数；保留最近 64 次慢帧和 128 次超过 16.67 ms 的 CPU 调用及其时间位置，细分声音启动、定位等路径。另保留最多 128 次慢声音启动的加载前后状态、原生加载类型和回放时刻，区分首次同步加载。嵌套调用不能相加，回收计数是相关性证据，不能直接当作回收耗时。

### 0.8.7 跨页读取、后台分配与等待提示

- 正常播放提前按需读取游标前方页面，优先满足人物和环境的后续采样，减少到页面边界才停钟等待的问题；暂停与新跳转会调整预读目标，继续保留 **1 GiB／64 页**缓存上限。
- 观看回放期间不再自动转换旧录像页面。已有快速旁缓存继续读取，原录像不改写；首次冷读旧页仍需解码。上一版额外转换会产生大量临时分配，且新块在当次播放不会使用。
- 特效历史使用独立投影解码，跳过人物、物品、生物等无关轨道，保留真实发射器时钟、种子及历史姿态。
- 读取等待提示独立于底部菜单，菜单收起、F9 关闭和镜头操作时仍可见，数据就绪后消失。隐藏菜单不再逐帧拼接长诊断文字。
- 诊断增加跨页重复等待的实际时长、内存回收重叠计数与托管堆大小；回收发生时的轨道耗时不能直接归因于该轨道自身。离线对照不等于 Unity 实机帧率验收。

### 0.8.6 连续跳转后的恢复与卡顿排查

- 修复粒子回跳时使用旧完成相位反复重启预热、恢复无法结束的问题。新跳转替换过期任务，暂停时继续完成当前目标。
- 粒子恢复批次固定目标和时钟锚，高速粒子不再因目标不断前移而始终隐藏；后续追赶保留已模拟的真实历史状态，暂时落后时明确提示。预算耗尽后不再继续读取与索引粒子历史。
- 粒子复制、网格特效、箱子与绳索构建、箱子动画图及风暴预热纳入共享分帧预算，过期副本分批回收；材质、纹理、着色器目录和外观恢复增量处理。
- 自动保存跳转后的读取状态、目标姿态就绪时间、播放时钟及各轨道耗时；读取长时间未完成后另存就绪报告，关闭回放时保留最后诊断。报告位于游戏目录 `BepInEx/PeakReplayLab/Performance`，F9 仍可手动保存。
- 页面缓存继续按需使用 **1 GiB／64 页**上限。两份真实完整录像的 132 个不同跳转／跨页目标离线读取均成功；这不等于 Unity 内的画面与帧率验收，仍需实机验证。

### 0.8.5 快速跳转与分批构建

- 目标人物和环境的真实采样就绪后即可呈现，不再等待粒子历史；必要的页首连续性、瞬移与拓扑切断仍保留。关节索引按已缓存页面复用，有界回收。
- 新完整录像使用约 1 秒的独立压缩页面，并单独保存轻量粒子发射器历史。新版读取旧完整录像时，只为访问过的旧页面生成可删除的快速旁缓存；打开录像不转换整场，下次打开可以使用已生成的小块。旧页第一次冷读仍需解码原页。
- 复杂物品、生物、气球和放置物按节点、渲染器和骨骼绑定分批构建；完成目标姿态后显示。按目标相机与手持物优先级调度，不同轨道轮换使用共享预算；兼容模板实例有界复用，过期半成品分批回收。
- 页面缓存继续按需使用 **1 GiB／64 页**上限，不预分配。粒子历史未到时暂停对应预热，不用目标位置伪造旧发射器轨迹。F9 回放诊断新增最近跳转的姿态就绪耗时；这项耗时不等于全部模型与特效完成时间。
- 新完整录像的容器索引为 V2，新版继续兼容 V1 完整录像和已有片段。原生单次调用仍可能超过软预算，Unity 实际帧率与大型场景表现需实机验证。

### 0.8.4 回放跳转与生物覆盖

- 同一渲染帧内的时间轴拖动只处理最后一次请求；分页连续在后台读取，按需加载目标及附近页面，最近页面缓存上限 **1 GiB／64 页**，减少来回跳转时的重复解码。不会预分配 1 GiB 或一次读取整场录像。页读取不再反复校验整份索引，关节索引仍在后台构建。大型录像首次进入未缓存的时间段仍需解码，不能保证瞬时完成。
- 物品、绑头气球、生物、放置物和粒子预热共享分帧预算，优先恢复人物与物品；读取新位置期间停止为旧位置补建。外观资源目录按场景共享、排除回放自建材质，释放最后一个副本时清空；渲染器显隐只在实际变化时写入。
- 新增火山原生 `Condor` 老鹰的骨骼与状态采集／复现。修复森蕈小僵尸 295 个渲染器超过原外观上限导致整条动作帧丢弃的问题，外观异常不再连带丢失有效骨骼。
- 雾沼青蛙身体与跳跃原本由 `MobItem` 轨道采集；补齐原生 200 点舌头线条，使用独立纯线条轨道，不重复绘制青蛙身体。
- 继续读取已有兼容录像。旧录像没有录下的老鹰、僵尸动作与青蛙舌头无法补造，需要安装新版后重新录制。F9 性能报告增加当前回放的实际渲染帧统计。

根因、验证证据和实机待验范围见 [0.8.4 跳转与生物核查](docs/playback-seek-and-creatures-0.8.4.md)。

### 0.8.3 多人队伍与死亡前轨迹

- 录制、录像读取和轨迹导出不按固定人数截断，兼容突破原版四人限制的联机 Mod。实际数据仍受文件、内存和磁盘容量保护；大队伍的轨迹按数据量分包上传，不丢弃后加入的成员。

- 用原生胜利状态记录真正的登顶证据，任意一人登顶代表整个队伍登顶。队员各自的路线完整性仍分别保留，死亡或断点不能补造完整线路。
- 已有录像可重新导出其已记录的信息；旧版本人数截断时没有录下的成员，无法从旧文件恢复。录制频率和最多 10 Hz 的轨迹采样保持。

- 已有 Schema 14 完整录像可以重新导出恢复其已记录的切关状态，无需重新游玩。不增加录制频率或游戏内扫描。

- 新录制在地图就绪后一次保存原生关卡根与进度点的地图地标：世界厘米 XYZ、稳定关卡键／对象名，以及根的世界旋转和缩放。独立轨迹包的可选 `map.alignment` 只复制这些白名单字段；地标必须与录制的入口／出口 Z 一致。网站须用同构建的源地标核验初始位置，不根据玩家起点猜偏移。已有录像仍可读取和投稿；只有 Z 门限和布局哈希的旧录像不能补造三维地标，缺少足够证据时不会叠加。

## 缓存与内存

默认 60 Hz 目标，最多 120 秒，保守内存计量预算 256 MiB；不预分配 256 MiB。
超出时间或预算就淘汰最旧数据；预算不足时保存的片段会短于 120 秒，F9 会提示。
暂停游戏不会把相同姿势反复写满缓存。进入新的真实地图会替换缓存；返回主菜单后尚可按 F6 保存上一局留下的缓存。
**退出游戏会丢弃未按 F6 保存的片段，不做片段退出自动保存。** 已开启的完整录制则收尾单文件流；建议先回主菜单等封存提示再退出。正常退出最多等待 1.5 秒，强退／异常留下的 `.partial` 当前不能直接播放。

以下为 **0.3.0 历史合成基准，不能代表 0.3.1 游戏性能**：60 Hz、256 个静止物品及 48 个箱子、每人四层动画/双片段、八格库存和六个握持定位点的 .NET 8 测量。

| 人数 | 保留时长 | GC 后保留托管内存 | 保守计量 | 配置预算 |
| --- | --- | --- | --- | --- |
| 4 | 120 秒 | 约 89 MiB | 约 137 MiB | 256 MiB |
| 8 | 120 秒 | 约 160 MiB | 约 255 MiB | 256 MiB |
| 16 | 约 63 秒 | 约 158 MiB | 约 256 MiB | 256 MiB |

这些是**独立程序的合成数据结果，不是游戏进程实测**；不含游戏场景、GPU 资源、录制 API 的临时分配、文件读取和播放分身。
保存使用后台压缩，复用只读样本，不立即复制整段；但保存未结束时，旧样本和新缓存可能同时存在，峰值可能接近两份样本再加序列化开销。
因此 256 MiB 是滚动样本的保守计量上限，不是整个 Mod 的操作系统内存硬限制。
大量持续移动物品会比静态物品占更多内存；大型 Mod 房间可提高预算，但保存时仍可能有额外峰值。
详细方法见 [内存基准](docs/memory-benchmark.md)。

## 本版重演范围

- 默认采集所有已同步玩家，保留真实 Photon 用户 ID；缺失时使用房间 ActorNumber / ViewID，不随机匿名化。
- 记录位置、分级采样的完整骨架局部位置／旋转／缩放、面朝方向、动作、体力/额外体力；每个节点保存自己的真实采样时刻。
- 记录皮肤、脸、帽子、服装、配饰、绶带和勋章索引（低频变更检查），以及骸骨/蘑菇变身、昏迷/死亡眼睛状态（快速检查、变化时留新状态）。
- 按录像中的场景名加载本机地图，不重新查询今日地图。记录关卡激活状态及昼夜数据，拖动时恢复相应部分。
- 新录像按真实骨骼轨道播放；跟随镜头、自由镜头、时间轴、0.25/0.5/1/2 倍速。
- 倒地／翻滚保存最终显示骨骼姿态，不记录关节力矩或重跑布娃娃物理；仅支持新版录像。

**尚不完整重建敌人、任意非物品投射物、全部机关、天气、特效灯光、粒子碰撞或音频混音器 DSP。** 已加入独立绳索/钩爪/锚头、原生粒子/爆炸模型与游戏音效轨道，但有资源、预算和客户端可见性边界；不录语音。物品模型、实际轨迹、开箱、烤熟外观和使用事件不是完整的玩法仿真。
新录像记录上半身层、手势和物理共同作用后的最终骨骼，不靠重建 Animator 层来猜姿态。低帧率造成的采样间隙、录像中未出现的骨骼，以及其他 Mod 在采集之后的修改仍无法凭空恢复。
地图载入是原场景和关卡开关的恢复，不是完整动态世界倒带。
远端玩家数据以本机所见为准，含网络同步延迟，不是服务器权威录像。原游戏不发送队友通用的精确使用进度，面板会显示“未同步”，不会用 0 冒充空闲；接收到的实际使用/消耗网络事件仍可记录。

片段最多 16 名不同参与者、7,201 帧、512 MiB 解压后数据；最多 60 Hz。每帧最多 1,024 个物品和 1,024 个箱子，每对象最多 256 节点。
Schema 6 每帧另外最多 256 个绳索族实体、512 组特效和 128 个游戏音效 voice。固定状态共享并差分；增加动态轨道会占用预算，不能用旧版本合成内存表承诺本版完整 120 秒。
必须匹配游戏版本、Steam Build ID、游戏程序集标识和关卡分支；游戏更新后旧片段可能无法播放。
动画用稳定名称/元数据定位，不依赖上一次进程的实例 ID；发现重名歧义或缺失会提示近似动画，不冒充精确匹配。
旧足迹日志以及 0.1.0 的调试 NDJSON **不能直接导入**本版回忆录。

## 文件和两套 Mod 的关系

- 已保存片段：`PEAK/BepInEx/PeakReplayLab/Memories/*.peakreplay`。
- 完整录像：`PEAK/BepInEx/PeakReplayLab/Recordings/*.peakrun`。
- 回忆录底部的「打开文件夹」会用系统文件管理器打开当前分类的保存目录；目录尚不存在时会先创建一个空目录。
- 配置：`PEAK/BepInEx/config/cn.mylus.peakreplaylab.cfg`。
- 排障：`PEAK/BepInEx/LogOutput.log`，搜索 `PEAK Replay Lab` / `PeakReplayLab` / `回忆录`。

`.peakreplay` 为压缩 NDJSON，含玩家名字和标识，只保存在本机；新 DLL 没有上传接口。
只有明确保存才创建片段文件，先写唯一 `.partial` 文件，完成后改名，避免覆盖已有回忆。
必须等成功提示再退出进程；强制退出可能留下不可播放的 `.partial`，列表不会展示它。
配置和 BepInEx 排障日志不属于录像文件，仍可正常写入。

**原 PeakTrailRecorder 保留，正常游戏两套并行。** 原 Mod 仍按原配置记录和上传足迹；新 Mod 不更改其配置或 DLL。
观看回忆录时临时停用旧 Recorder 组件，避免将观看场景作为新局上传，返回主菜单后恢复。
不再需要本实验版时，关闭游戏并移走 `PeakReplayLab.dll` 即可，片段和旧 Mod 不受影响。

## 播放隔离

视觉分身仅复制 Transform、渲染组件和一个受控 Animator，不复制整个 Character prefab，不添加玩家逻辑、AI 或碰撞体。
播放使用手动 PlayableGraph，关闭动画事件、根运动和 IK；材质采用独立副本。
离线场景加载仍借用游戏原生本地角色初始化资源，该角色在播放时隐藏；这不等于在好友房间中生成新玩家。

观看期间启用 Harmony 保护：阻止该离线回放触发存档写入/删除、成就统计和正常局次推进。
保护方法缺失时新 Mod 停用，不影响原 Recorder。
取消加载要等待 Unity 未完成的加载返回，切回主菜单后才解除保护。
禁用插件时独立恢复组件继续处理返回；退出进程时仍保留保护，避免退出回调持久化观看场景。
第三方 Mod 的不受时间控制脚本不保证暂停，隔离与恢复仍需实际游戏验证。

仓库根目录执行：

```powershell
dotnet build PeakReplayLab.slnx -c Release --nologo -warnaserror
dotnet run --project tests/ReplayContract/ReplayContract.csproj -c Release
dotnet run --project tests/ReplayViewContract/ReplayViewContract.csproj -c Release
```

输出：`artifacts/bin/PeakReplayLab/release/PeakReplayLab.dll`，netstandard2.1。
构建不自动安装，不分发原游戏程序集或提取素材。维护者为新版本运行 `pwsh -File scripts/release.ps1 -Draft` 一键编译、测试、打包、上传草稿并等待 GitHub 复核；改用 `-Publish` 在复核通过后公开实验性预发布。继续验证现有 0.7.4 草稿用 `pwsh -File scripts/release.ps1 -Resume -Tag v0.7.4 -Draft`。详见 [发布说明](docs/releases.md)。

协议测试可独立运行，不依赖游戏资源；覆盖 60 Hz 时钟、缓存淘汰、对象增量/删除/反向查找、片段起点快照、事件时间重定位、库存/箱子数据、压缩读写、取消、版本匹配及损坏输入。**不能替代 Unity 内验收**。

另有 26 项 `ReplayViewContract` 使用明确的 Unity API 测试替身，直接编译生产 `ReplayView.cs` 与原生控件复制代码，验证原生摄像机保留、闭眼遮罩抑制、仅人物状态 Volume 隔离、异常回滚、退出恢复及原生 CanvasGroup 复制。它们检查状态操作，不模拟 Unity 的实际画面、GPU 或完整生命周期。

待验收重点：

- 不按 F6 时没有新录像；F6 后有成功提示，缓存继续；重启后仍可打开。
- 原场景、多人位置和历史装扮匹配，分身不透明/黑脸/T-pose；骸骨变身可辨认。

- 底部抽屉默认只显示拉手，上拉、下拉、点击及 H / View / Select 都可切换；暂停时动画正常，隐藏按钮不被鼠标或手柄选中；右键镜头观察和切换窗口不留下拖动状态。
