# PEAK 回忆录 — Replay Lab 0.8.3 实验版

独立维护仓库：[luyongyi/peak-memories](https://github.com/luyongyi/peak-memories)。开发和测试方式见 [开发说明](docs/development.md)，一键构建／发布见 [发布说明](docs/releases.md)。仓库包含 Mod 源码、合成测试、文档及原创封面；游戏资源和私人录像保留在本机。

独立 DLL，入口在 **PEAK 游戏主菜单**。本地录制与回放无需服务器；轨迹上传为可选功能。
进入关卡后自动缓存最近最多 120 秒，**F6 随时保存片段**；完整录制是独立开关，可以同时使用。
在主菜单「回忆录 → 录制方式」开启完整录制，或用 **F4** 开启／关闭；关闭时封存当前录像，保留片段缓存与设置。
从回忆录选择录像，自动加载原场景，使用本机原版模型、历史装扮与记录的真实骨骼姿态重演。观看时不再录制。

### 0.8.3 多人队伍与死亡前轨迹

- 录制、录像读取和轨迹导出不按固定人数截断，兼容突破原版四人限制的联机 Mod。实际数据仍受文件、内存和磁盘容量保护；大队伍的轨迹按数据量分包上传，不丢弃后加入的成员。
- 上传轨迹只保留存活期间的真实位置，死亡位置作为该段终点；幽灵期间不上传移动轨迹。复活后另起一段，不连接穿越死亡或传送的路径。
- 用原生胜利状态记录真正的登顶证据，任意一人登顶代表整个队伍登顶。队员各自的路线完整性仍分别保留，死亡或断点不能补造完整线路。
- 已有录像可重新导出其已记录的信息；旧版本人数截断时没有录下的成员，无法从旧文件恢复。录制频率和最多 10 Hz 的轨迹采样保持。

### 0.8.2 篝火切关与轨迹完成判定

- 轨迹导出复用录像已有的原生关卡状态。点燃篝火进入下一关后，不再等玩家跨过下一关标题提示地标才记录完成。
- 精简轨迹增加关卡切换和存活玩家的检查点事件，保留原有坐标、10 Hz 筛选、地标和断点。游戏进入了哪一关与每人的连续路线是否完整分别展示，死亡、迟加入和传送不能替本人补造完整线路。
- 已有 Schema 14 完整录像可以重新导出恢复其已记录的切关状态，无需重新游玩。不增加录制频率或游戏内扫描。

### 0.8.1 地图地标与路线位置核验

- 地图就绪时一次记录关卡根和原版进度地标的世界坐标、旋转和缩放，随轻量轨迹白名单上传。网站用同版本地图的源地标核验位置；不以玩家第一帧作为地图原点。
- 位置校正由至少三个分散、不共线的地标共同确认；不一致的地图保留投稿并等待核验。旧录像的布局哈希若与同版本原版布局完全一致，可验证原位路线；缺失的三维地标不补造。
- 录制姿态频率、10 Hz 轨迹筛选和 Schema 14 保持。地标只在建立录像上下文时读取，不新增逐帧扫描。

### 0.8.0 片段与完整录制并行

- 完整录制开启或关闭，F6 都可保存最近最多 120 秒为 `.peakreplay`；最近缓存受已有内存预算限制，未保存内容退出后丢弃。
- F4 只切换完整录像写入器，开启时开始 `.peakrun`，关闭时封存；不会清空或重建已有片段缓存。完整录制开关持久保存为 `Recording.ContinuousEnabled`，旧 `Recording.Mode` 仅作为首次迁移初值。配置迁移、资源变化与 688 项验收见 [独立录制开关](docs/recording-controls-0.8.0.md)。
- 两种文件继续分别保存在 `Memories/` 与 `Recordings/`，只有封存的完整录像支持「上传轨迹」。采集复用同一份已录数据，不另加高频扫描。

### 0.8.0 完整录像上传轨迹

- 仅在「完整录像 → 详情」提供「上传轨迹」。从封口完成的 `.peakrun` 后台逐页筛选；120 秒精彩片段、录制中的文件及异常 `.partial` 不支持上传。
- 上传前显示目标站点、每人姓名、人数、坐标数、难度和实际压缩大小；点击确认才发送。每人最多 10 Hz，坐标量化到厘米，单独 gzip 白名单包，不发送原录像、Steam ID、骨骼、物品、外观、特效或声音。接口默认为 `https://peak.mylus.cn/api/route-uploads`，配置项 `Routes.UploadEndpoint`；开发时可用 loopback HTTP。
- 新录像 Schema 14 增加启动时固定的地图／难度／关卡边界和每人状态证据，继续读取 10–13。利用现有采集读取，角色中心坐标最多 10 Hz，状态变化立即记录；不另建扫描器或网络直播。原录制与回放姿态频率保持。
- 新录制在地图就绪后一次保存原生关卡根与进度点的地图地标：世界厘米 XYZ、稳定关卡键／对象名，以及根的世界旋转和缩放。独立轨迹包的可选 `map.alignment` 只复制这些白名单字段；地标必须与录制的入口／出口 Z 一致。网站须用同构建的源地标核验初始位置，不根据玩家起点猜偏移。已有录像仍可读取和投稿；只有 Z 门限和布局哈希的旧录像不能补造三维地标，缺少足够证据时不会叠加。
- 服务端按个人、关卡筛选完整路径，未通关的完整录像也可投稿；缺起点、传送、死亡或断裂的关卡不自动算完整。旧录像难度和个人过关证据无法补出，保留为未知。
- Web 首页「进入地图」后默认显示纯地图；点击顶部「返回」旁的「路线与热力」，再在「线路图层」切换「大家的路线」或「热力图」，直接叠加到对应关卡的现有 3D 地图；支持难度、每人显隐与高度层。有效投稿自动审核；匹配不到对应地图版本时等待地图，不叠旧地图。热力按每条完整路线经过格子计一次。

部署、验收范围和容量限制见 [完整录像轨迹适配](docs/trajectory-upload-0.8.0.md)。服务端与 Web 源码在 [peak-trail](https://github.com/luyongyi/peak-trail)。

### 0.7.4 回放姓名、瀑布与蜂鸣

- 姓名直接跟随已回放的头部姿态，保留帽子顶部净空；回放期间隐藏并暂停原版姓名更新，退出恢复原来显隐，避免模板锚点停在空中和两处名字同时出现。
- 原版瀑布 shader 使用回放时间流动，支持暂停、倍速和前后拖动。退出撤销渲染时钟接入；水雾继续由已有特效轨道管理。旧录像没有保存原始流水纹理相位，能恢复流动但无法保证逐帧纹理花纹一致。
- 蜜蜂及其他原生游戏音效恢复匹配资源的自定义距离曲线和混音设置，声音池复用先重置配置。缺失或冲突曲线会明确提示并按已录距离近似衰减。
- Schema 13 与录制频率保持，已有兼容录像可使用这些修复。

根因证据、验证结果与游戏内待验项目见 [0.7.4 回放呈现验收报告](docs/replay-presentation-0.7.4.md)。

### 0.7.2 录制性能修复

- 队列保留一帧显式计量基线，避免后台写完后下一帧重新遍历全部场景数据。基线、队列与正在写入的帧共用原有 128 MiB 限额；360 帧限制与主采样目标 60 Hz 保持。停止、故障或基线占用阻碍真实新快照时会释放缓存。
- 静态地雷采用一次基线、爆炸事件立即更新和 1–1.5 秒错峰完整性核查；未激活生物不再每 0.2 秒读取完整骨骼与材质，激活／隐藏立即刷新，活动骨骼最高 30 Hz。
- 物品运动与外观读取分离，材质全量检查使用独立 0.5–0.75 秒截止；原生变更通知、颜色、烹饪与点亮立即刷新。动态视觉属性最高 30 Hz，并要求真实动态控制器资格，静态手持物品不会因通用 shader 属性被提升频率。缓存组件、名称、网格标识及共享材质列表；实际动态灯保持源采样率。
- 环境连续状态 20 Hz，方向、启停、周期重置及雾原点等离散边沿立即读取；目录按类别错峰补漏。新增实际观察时钟，独立环境时间轴保留静止采样锚、事件边沿、跨页、裁剪与回拖。
- 新写 **Schema 13**，继续读取 Schema 10／11／12；旧版 Mod 无法读新版录像。环境时钟需持久化，避免仅凭数值变化时刻错误提前播放运动。
- F9 和持续录制停止时，会在 `BepInEx/PeakReplayLab/Performance/` 保存 JSON。报告包含各 CPU 阶段平均／P95／P99／最大耗时与分配、全局 GC 次数，以及实际渲染帧在录制开／关两组中的 FPS 与 1%／0.1% low。各组仅保留最近 8192 帧，明确排除切换后的 2 秒暖机与封存过程；样本不足的 low 值为未知。阶段计时存在嵌套，不能相加视为总成本。

验收证据、性能数字的口径与实机待验范围见 [0.7.2 性能验收报告](docs/performance-acceptance-0.7.2.md)。

### 0.7.1 持续录制队列与静态陷阱

- 修复 `queue-overflow` 的共享快照重复计量。写入队列按实际保留的对象引用计数，包含正在序列化的帧，完成或失败后释放；上限保持 128 MiB／360 帧，真实超限仍明确停止并保留文件。队列诊断增加实际触发字节、帧数与峰值。
- 真实故障文件含 312 帧。按 60 Hz、后台首段写入停顿约 1 秒复现：旧计量第 12 帧拒绝，虚高估算 133,148,006 字节；新版 312 帧全部写完，峰值 51,837,036 字节，未写帧为 0，完成后队列归零。原未完成文件哈希不变。
- 静态孢子陷阱与动态生物分别使用有界目录，陷阱最多 8192、动态生物最多 256。静态只保存原场景路径、根变换和显隐；未变化数据复用，不遍历整棵模型树。回放优先使用原模型，爆炸前状态需要时才建立无脚本视觉副本；旧完整姿态陷阱录像继续可读。
- 准入对照原生单次触发、生成特效和自身停用事件，补齐 `Jungle_SporeMushroomExplo` 与 `VFX_PoisonExplo`，排除没有触发逻辑的 `SporeShroom` 模型子树。格式保持 Schema 12，仍读取 Schema 10／11。

修复证据与实机边界见 [0.7.1 队列溢出排查](docs/queue-overflow-0.7.1.md)。

- 记录森蕈／雪山原生风区的风向、强度、开启状态、切换倒计时、持续时间和已持续时长，并按录像时钟呈现原生风雨／风雪及停风后的渐退。暂停、回拖和切换观察镜头不重新抽签风向。

### 0.6.3 底部回放抽屉

- 回放控制台默认收起，只留屏幕底部中央的细胶囊拉手。上拉或点击展开；下拉、点击「收起」或按 **H** 隐藏进度条和整块控制台。松手时根据拖动位置与甩动方向自动吸附，0.25 秒动画使用非缩放时间，暂停回放也能操作。
- 按钮、字体、配色和描边沿用本机游戏资源，拉手使用游戏已有的 `ProceduralImage` 圆角组件。展开时拉手跟随面板顶部；收起后不遮挡原生状态条和物品栏，悬停才显示操作提示。
- 手柄 **View / Select** 切换抽屉，**B** 在展开时收起、完全收起后返回。方向键可选择拉手并用 **A** 展开。**F9** 打开诊断时自动展开；空格暂停、Tab 切换玩家和回放镜头操作在收起时仍有效。
- 隐藏及动画过程中的面板不接收鼠标、键盘或手柄选择；右键观察和窗口失焦会结束拉手拖动，不重写光标状态。退出回放仍恢复原游戏输入。

### 0.6.0 分级关节与紧凑编码（开发历史）

- 该版本使用 Schema 10；0.6.1 继续兼容读取。已移除更早人物动画、六点握持回退和旧 Schema 解码分支。
- 本机 128 个节点仍全部保留绑定：P0 49 个（身体主链、全部 24 个手指骨骼、人物根）按实际渲染帧、目标 60 Hz；P1 9 个（脚部细节、面部和帽骨）30 Hz；P2 70 个（服饰和结构父节点）10 Hz。实际旧录像离线试算发现中指／小指 30 Hz 会遗漏快速手势，因此全部手指采用最高优先级。未知新增骨骼默认 P0。未到期的节点跳过姿态读取及分配。
- 人物根保存世界姿态，其余节点保存父节点局部姿态。低频衣服每个回放渲染帧都随父骨骼运动；节点自身的形变按独立真实采样时间插值，避免先停住、再在一帧内追赶。静止时仍保存真实观察时刻，避免后续动作被提前拉长。
- 时间轴跳转不依赖上次播放。分页末尾缺少低频节点的下一次真实采样时，跨页预读至当前页末后 0.5 秒，兼容单帧小页；读取缓存最多 64 页／256 MiB 解码估算，索引在后台建立。人物消失、拓扑变化、瞬移与长捕获间隔切断插值。
- 姿态在后台编码：位置使用 0.0001 米网格，子节点旋转用 47 位 smallest-three 四元数编码（装入 6 字节）；人物根旋转及全部缩放保留原始 float 精度，防止较长父子偏移放大误差。完整基线保存路径，后续保存节点编号、字段差分和采样时间。窄整数溢出升级表示，避免截断；对绝对值量化，避免长录像累积漂移。
- 抓握、攀爬、倒地等状态切换强制采样，切换期间 P1 短时提高频率。旧人物 Animator 片段不再采集或重演。箱子等物体仍按原生动画时间轨回放。
- 继续使用一局一个 `.peakrun` 和有界后台写入／分页读取。没有一分钟原始对象缓存。精彩片段的时间原点转换也会同步转换各关节采样时刻。

旧单人录像 66.717660 秒／3924 帧／128 节点，经开发用离线还原为局部姿态并按最终 49/9/70 分级，再由正式编码器写入及读回：17,440,989 → 2,746,881 字节，减少 84.25%；7 个页面完整，原文件哈希未变。非关节轨道在根旋转／缩放精度修正前完成逐帧语义校验，全部一致；最终仅改动关节字段，没有重复该项检查。按同样内容密度外推约 2.47 MB／分钟、148 MB／小时、296 MB／两小时（十进制 MB），不能视为新游戏实测或多人容量保证。原格式未记录的攀爬／着地等强制提频事件无法完整重建。

该样本局部位置编码最大误差 0.0856 mm、局部旋转最大误差 0.0062°；父子层级组合与分级插值后，世界位置最大约 0.273 mm、世界旋转最大约 0.0205°。0.1 mm 是局部量化网格，不是世界空间误差承诺。详细离线报告见 `../local/checks/joints-0.6.0/measure-final.json`（本地检查数据，不随 DLL 发布）。

该版本 Release 编译无警告／错误，474 项 ReplayContract、19 项 ReplayViewContract、11 项 NativeLoadingContract 通过；包含关闭回放时延迟释放读取取消令牌的确定性竞争回归。编译、数学插值、编码往返和损坏输入测试可以验证数据路径；游戏中的服装外观、快速手势及多人帧率仍需用新版录像检查。

### 0.5.0 完整人物关节轨道（开发历史）

- 当前本机人物身体蒙皮有 120 个骨骼，包括双手的 24 个手指骨骼；18 个物理身体部位已包含。再加螺旋帽 2 个骨骼和必要祖先／根节点，运行时目录为 128 个节点。按实际模型建立目录，支持最多 256 个，不以物理枚举数量冒充骨骼数量。
- 保持 60 Hz 目标，在人物原生更新后的 LateUpdate 读取最终位置、旋转与缩放；空手、持物、手势、观察与倒地都记录。不限制为持物时的六点，不重新模拟关节力或游戏物理。
- 新录像直接驱动完整骨骼，位置插值、旋转球面插值。父节点先于子节点应用，避免还原手后再转动肩膀；新轨道不叠加旧基础动画。拓扑改变按记录时间切换，时间轴跳转不依赖之前的播放历史。旧六点握持轨道也补上了与基础动画的平滑交接。
- 新文件为 **Schema 9**。节点身份及未变化字段用无损增量存储，完整录像每个内部页仍有独立基线；旧 Schema 2–8 继续可读，未录下的关节无法补回，需重新录制。旧 DLL 不支持新录像。
- 骨骼增加了录制、文件和内存开销；256 MiB 滚动预算保留，达到预算时片段可能短于 120 秒。持续录制仍仅保留当前／前一帧，写入队列与按需解码页面均有上限。F9 显示实际采样频率和总关节数，回放诊断会报告未匹配节点。
- 「打开文件夹」入口保留。实际游戏动作平滑度与多人帧率需用新版新录像验收；离线合同测试不等于 Unity 画面验收。

### 0.4.7 删除录像

「回忆录 → 选择录像 → 删除录像」进入原生二级确认页，显示具体文件、时间、时长和大小；默认焦点为取消。精彩片段、完整录像，以及没有继续写入的损坏/未完成录像都可以移走。正在读取、保存、封存或回放时不允许删除。

确认后将**这一份文件**移至 `BepInEx/PeakReplayLab/Trash/<时间-唯一编号>/<原文件名>`，不是 Windows 回收站，不会永久删除，也不会自动清空。误删可退出游戏后将 `.peakreplay` 移回 `Memories/`，将 `.peakrun` 或 `.peakrun.partial` 移回 `Recordings/`（不要覆盖同名文件），再刷新列表。文件仍占磁盘空间；这一版暂不做导出、批量删除或界面内恢复。

文件核对与移动在后台执行；确认前关闭页面不会移动，确认提交后即使返回菜单也会继续完成。文件在确认后被修改/替换、被其他程序占用，或路径指向链接/库外位置时，操作会失败并保留提示，不会降级为永久删除。只支持当前 Windows 本地磁盘，不支持网络路径和跨卷移动。

## 缓存与内存

默认 60 Hz 目标，最多 120 秒，保守内存计量预算 256 MiB；不预分配 256 MiB。
超出时间或预算就淘汰最旧数据；预算不足时保存的片段会短于 120 秒，F9 会提示。
暂停游戏不会把相同姿势反复写满缓存。进入新的真实地图会替换缓存；返回主菜单后尚可按 F6 保存上一局留下的缓存。
**退出游戏会丢弃未按 F6 保存的片段，不做片段退出自动保存。** 已开启的完整录制则收尾单文件流；建议先回主菜单等封存提示再退出。正常退出最多等待 1.5 秒，强退／异常留下的 `.partial` 当前不能直接播放。

以下为 **0.3.0 历史合成基准，不能代表 0.3.1 游戏性能**：60 Hz、256 个静止物品及 48 个箱子、每人四层动画/双片段、八格库存和六个握持定位点的 .NET 8 测量。

| 人数 | 保留时长 | GC 后保留托管内存 | 保守计量 | 配置预算 |
| --- | --- | --- | --- | --- |
| 4 | 120 秒 | 约 89 MiB | 约 137 MiB | 256 MiB |
| 8 | 120 秒 | 约 160 MiB | 约 255 MiB | 256 MiB |
| 16 | 约 63 秒 | 约 158 MiB | 约 256 MiB | 256 MiB |

这些是**独立程序的合成数据结果，不是游戏进程实测**；不含游戏场景、GPU 资源、录制 API 的临时分配、文件读取和播放分身。
保存使用后台压缩，复用只读样本，不立即复制整段；但保存未结束时，旧样本和新缓存可能同时存在，峰值可能接近两份样本再加序列化开销。
因此 256 MiB 是滚动样本的保守计量上限，不是整个 Mod 的操作系统内存硬限制。
大量持续移动物品会比静态物品占更多内存；大型 Mod 房间可提高预算，但保存时仍可能有额外峰值。
详细方法见 [内存基准](docs/memory-benchmark.md)。

- 默认采集所有已同步玩家，保留真实 Photon 用户 ID；缺失时使用房间 ActorNumber / ViewID，不随机匿名化。

- 按录像中的场景名加载本机地图，不重新查询今日地图。记录关卡激活状态及昼夜数据，拖动时恢复相应部分。
- 新录像按真实骨骼轨道播放；跟随镜头、自由镜头、时间轴、0.25/0.5/1/2 倍速。
- 倒地／翻滚保存最终显示骨骼姿态，不记录关节力矩或重跑布娃娃物理；仅支持新版录像。

**尚不完整重建敌人、任意非物品投射物、全部机关、天气、特效灯光、粒子碰撞或音频混音器 DSP。** 已加入独立绳索/钩爪/锚头、原生粒子/爆炸模型与游戏音效轨道，但有资源、预算和客户端可见性边界；不录语音。物品模型、实际轨迹、开箱、烤熟外观和使用事件不是完整的玩法仿真。
新录像记录上半身层、手势和物理共同作用后的最终骨骼，不靠重建 Animator 层来猜姿态。低帧率造成的采样间隙、录像中未出现的骨骼，以及其他 Mod 在采集之后的修改仍无法凭空恢复。
地图载入是原场景和关卡开关的恢复，不是完整动态世界倒带。
远端玩家数据以本机所见为准，含网络同步延迟，不是服务器权威录像。原游戏不发送队友通用的精确使用进度，面板会显示“未同步”，不会用 0 冒充空闲；接收到的实际使用/消耗网络事件仍可记录。

片段最多 16 名不同参与者、7,201 帧、512 MiB 解压后数据；最多 60 Hz。每帧最多 1,024 个物品和 1,024 个箱子，每对象最多 256 节点。

必须匹配游戏版本、Steam Build ID、游戏程序集标识和关卡分支；游戏更新后旧片段可能无法播放。
动画用稳定名称/元数据定位，不依赖上一次进程的实例 ID；发现重名歧义或缺失会提示近似动画，不冒充精确匹配。
旧足迹日志以及 0.1.0 的调试 NDJSON **不能直接导入**本版回忆录。

## 播放隔离

视觉分身仅复制 Transform、渲染组件和一个受控 Animator，不复制整个 Character prefab，不添加玩家逻辑、AI 或碰撞体。
播放使用手动 PlayableGraph，关闭动画事件、根运动和 IK；材质采用独立副本。
离线场景加载仍借用游戏原生本地角色初始化资源，该角色在播放时隐藏；这不等于在好友房间中生成新玩家。

观看期间启用 Harmony 保护：阻止该离线回放触发存档写入/删除、成就统计和正常局次推进。
保护方法缺失时新 Mod 停用，不影响原 Recorder。
取消加载要等待 Unity 未完成的加载返回，切回主菜单后才解除保护。
禁用插件时独立恢复组件继续处理返回；退出进程时仍保留保护，避免退出回调持久化观看场景。
第三方 Mod 的不受时间控制脚本不保证暂停，隔离与恢复仍需实际游戏验证。

## 构建与验证

仓库根目录执行：

```powershell
dotnet build PeakReplayLab.slnx -c Release --nologo -warnaserror
dotnet run --project tests/ReplayContract/ReplayContract.csproj -c Release
dotnet run --project tests/ReplayViewContract/ReplayViewContract.csproj -c Release
```

需要 .NET 10 SDK（构建 `.slnx`）和 .NET 8 runtime（运行测试），以及本机已安装 PEAK/BepInEx。
非默认游戏位置加 `-p:PEAKGameRootDir="D:/SteamLibrary/steamapps/common/PEAK/"`，保留尾部斜杠。
输出：`artifacts/bin/PeakReplayLab/release/PeakReplayLab.dll`，netstandard2.1。
构建不自动安装，不分发原游戏程序集或提取素材。维护者为新版本运行 `pwsh -File scripts/release.ps1 -Draft` 一键编译、测试、打包、上传草稿并等待 GitHub 复核；改用 `-Publish` 在复核通过后公开实验性预发布。继续验证现有 0.7.4 草稿用 `pwsh -File scripts/release.ps1 -Resume -Tag v0.7.4 -Draft`。详见 [发布说明](docs/releases.md)。

协议测试可独立运行，不依赖游戏资源；覆盖 60 Hz 时钟、缓存淘汰、对象增量/删除/反向查找、片段起点快照、事件时间重定位、库存/箱子数据、压缩读写、取消、版本匹配及损坏输入。**不能替代 Unity 内验收**。

另有 26 项 `ReplayViewContract` 使用明确的 Unity API 测试替身，直接编译生产 `ReplayView.cs` 与原生控件复制代码，验证原生摄像机保留、闭眼遮罩抑制、仅人物状态 Volume 隔离、异常回滚、退出恢复及原生 CanvasGroup 复制。它们检查状态操作，不模拟 Unity 的实际画面、GPU 或完整生命周期。

待验收重点：

- 不按 F6 时没有新录像；F6 后有成功提示，缓存继续；重启后仍可打开。
- 原场景、多人位置和历史装扮匹配，分身不透明/黑脸/T-pose；骸骨变身可辨认。
- 跨关卡片段拖动前后，对应关卡能够显示；未记录的动态世界不误报为精确恢复。
- Esc/F7/End 及加载中取消都返回主菜单，镜头、输入、时间和原 Recorder 恢复。
- 观看不会修改真实存档或产生新的足迹局次；下一局正常可玩、可记录。
- 底部抽屉默认只显示拉手，上拉、下拉、点击及 H / View / Select 都可切换；暂停时动画正常，隐藏按钮不被鼠标或手柄选中；右键镜头观察和切换窗口不留下拖动状态。
