# 电影镜头模块

该目录是可独立维护的共享源码模块，主项目导入 `PeakReplayCinema.projitems`，最终仍只有 `PeakReplayLab.dll`。不引入第二个运行时插件或程序集。

## 源码边界

| 层 | 责任 | 依赖 |
| --- | --- | --- |
| `Core/` | 不可变机位、绝对时间插值、四种预设、有界 JSON 方案与原子保存 | .NET、Newtonsoft.Json；无 Unity 或回放类型 |
| `Unity/CinemaController.cs` | 编辑状态、手动接管、按已提交回放时间采样镜头 | 只读回放位置与时间、相机接管接口 |
| `Unity/CinemaEffects.cs` | 私有运行时 Volume/Profile、调色、景深、能力降级与精确恢复 | Unity/URP；不访问轨道或录制器 |
| `Unity/CinemaEditorUI.cs` | 原生风格的四页编辑器、构图参考 | 只发命令、只读状态；不调用游戏逻辑 |
| `Integration/` | Plugin 的可消除 partial hooks、录像身份读取与方案路径 | 宿主启动/关闭、文件身份；不解码录像 |

录制器、滚动缓存、持续写入器、归档编解码及轨迹上传均不引用电影模块。宿主新增的 `IReplayPresentationExtension` 只是可选显示扩展；普通回放默认没有扩展实例。

只在用户按 F8 或点击电影按钮后创建编辑器和后处理资源。关闭、场景切换、回放结束、插件卸载和初始化失败均释放资源。扩展异常由宿主隔离并恢复普通回放，不暂停采集服务或修改共享游戏资源。

## 单 DLL 构建与对照

```powershell
# 包含电影模块，默认行为。
dotnet build src/PeakReplayLab/PeakReplayLab.csproj -c Release

# 完全排除该模块的源码。partial hooks 在编译时消除。
# 独立输出目录避免覆盖上一份可安装 DLL。
dotnet build src/PeakReplayLab/PeakReplayLab.csproj -c Release -p:EnableCinema=false "-p:ArtifactsPath=$PWD/artifacts/base"
```

增加新电影效果时，在该目录实现，通过命令/状态 DTO 接入；不要往 `Capture`、`RollingCapture`、`FullReplayWriter` 或普通录像格式里添加电影字段。

## 时间、输入与恢复

自动运镜只采样 `PlaybackSession.Time`。读取等待期间保持机位；不使用 `RequestedTime` 或累计真实帧时间推进镜头。不同关卡的关键帧不插值。重复 Seek、暂停和倍速播放具有相同机位。

手动转向或移动会停止自动运镜，保留原轨道。滚轮继续用于第三人称距离或游离速度；FOV 单独调整。文字输入期间不解释电影/普通回放快捷键；F8 和紧急返回仍可退出。

后处理使用电影专属的运行时配置与隔离层，保留原生环境 Volume，不编辑共享 Profile。退出恢复进入时的相机姿态、FOV、镜头模式、暂停状态、姓名/HUD/控制台显隐和 URP 后处理、深度选项、Volume 层、触发器与更新方式。景深不可用时明确提示，机位和普通回放继续工作。

## 独立镜头方案

保存为 `<录像完整文件名>.<方案名>.camera.json`，可以为同一录像创建多套方案。只读取录像头尾各最多 64 KiB、长度和最后修改时间，在后台形成本机绑定指纹；不重新解码或完整哈希大录像。移动保持元数据不变的录像可继续匹配；修改时间变化后不沿用旧指纹。

方案上限为 2048 个关键帧、2 MiB。加载验证版本、指纹、有限数值、参数范围、重复时刻和重复 JSON 字段。先完成临时文件并同目录原子替换，不截断原方案或写入录像。

镜头位置、朝向、FOV 和手动对焦距离随关键帧变化；滤镜、景深模式、画幅参考和显隐是方案级设置。当前画幅仅是参考框，不改变相机比例或导出裁切。纯画面隐藏全部参考线和编辑 UI，用于外部录屏；没有内置视频编码器。

## 编辑与恢复

`CinemaController.Editing.cs` 管理最多 64 步撤销／重做与保存点；连续滑块输入合并，失败操作不会写入历史。关键帧可点选、拖动改时刻、复制及精确设置 XYZ、角度、FOV 和焦距。移动前通过宿主的只读缓存接口核验目标关卡；未缓存时先把回放拖到目标处读取，避免猜测跨关卡路径。

`CinemaEditorUI.Editing.cs` 以固定池最多 160 个标记和分页列表显示最多 2048 帧，不逐帧创建销毁控件；密集标记按像素聚合，选中帧额外保留。数字表单保留尚未提交的输入，失焦会取消正在拖动的标记。

`CinemaProjectFiles` 提供当前录像的方案列表、仅新建的原子复制、重命名和独立恢复文件。自动副本每 10 秒在后台按活动文档保存到 `<普通方案路径>.recovery.camera.json`，不覆盖正式方案。没有正式文件的新草稿也能在方案页发现。保存／丢弃会先协调进行中的后台写入，强制释放时尝试保留最终修改。

F8、编辑器返回、Esc 或返回录像库遇到未保存修改时显示保存／放弃／取消；取消继续编辑，写入失败保留确认框。切换目标方案后选择保存，会先写回原活动方案再加载目标。恢复确认先缓存并验证副本，避免保存步骤清理副本后丢失恢复来源。异常关闭只能恢复上一次已写入副本，无法保证尚未落盘的最后几秒。

## 验证

`CinemaContract` 测纯 Core；`CinemaEffectsContract` 测真实后处理生产源码的恢复与隔离策略；`CinemaControllerContract` 测控制器的真实时间采样、接管、保存及生命周期。后两者用 API 替身，不能替代 Unity 的渲染或性能验收。原回放的 ReplayContract / ReplayViewContract / ReplayNameplateContract 继续独立运行。

测试伴随插件 `tools/CinemaSmoke` 只用于本机已存在录像的短验收，不随产品 DLL 发布。它检查游戏内调色/景深配置、暂停跳转确定性、真实 F8 退出恢复，并留下画面供人工检查。原录像、配置与快速存档逐文件核验。
