# Protected cinematic smoke companion

This explicitly enabled test plugin is not part of the product or release package. It uses reflection to exercise the actual installed Mod and its cinematic command interface, so the final candidate DLL is not a compilation dependency. The test opens an existing recording through the normal replay theatre, does not copy/link it, and does not start a recording. It claims a unique `cinema-smoke-` plus 16 hex digit plan and recovery path before editing, then immediately saves the initial key so automatic recovery belongs to that active test plan. It also claims fresh `-copy` and `-renamed` test filenames. Cleanup accepts only those exact generated paths and completed matching hashes.

Build from the repository root:

```powershell
dotnet build tools/CinemaSmoke/CinemaSmoke.csproj -c Release
```

After installing the intended candidate and closing PEAK, launch with PowerShell 7 and explicit private paths:

```powershell
& tools/CinemaSmoke/launch-smoke.ps1 -Label cinema-example-01 -Recording 'C:/private/existing.peakrun' -OutputRoot 'C:/private/cinema-smoke'
```

Use `-Probe` when the companion was built in another staging workspace. `-GameRoot` can select the legitimate local installation. The launcher does not install or replace the production Mod. It installs only the exact test companion, backs up the existing quicksave and configuration files, launches a 1280×720 graphical process, and starts a hidden exit monitor. The companion requires `--peak-cinema-smoke` and complete recording/output/save-proof arguments before doing anything. Both the probe and monitor enforce at most 180 seconds. A timeout or forced exit fails the test.

The probe blocks config, quicksave, achievement and Steam-stat writes throughout shutdown. It checks grading/DOF runtime capability, creates a Slide preset plus a key, adjusts FOV/Warm/manual focus, invokes the actual 镜头/景深/调色/关键帧/方案 tab buttons and returns to 运镜, previews, and repeats a paused seek to compare the actual native camera pose. It saves, changes grading and saves over the same sidecar, deliberately changes the in-memory key count/FOV/preset, verifies that dirty Load requires confirmation, then discards those deliberate edits and checks that the saved keys, first pose, focus and Warm settings return.

The editing checks select the first key, move its time, undo/redo, undo back to the saved clean document, duplicate it and undo. The probe seeks and settles the duplicate destination before editing, then settles back at the selected key: production segment checks deliberately use already loaded replay evidence. An eight-number precise pose edit must reach the native camera with the expected position, pitch/yaw/roll, FOV and focus after several frames. The probe checks dirty Close leaves the editor alive, Cancel resumes editing, Undo returns to the saved clean state, and Save-and-continue on a pending Load writes then reloads the saved edit. Automatic recovery must appear within fifteen seconds with its expected unsaved grading value while the normal file stays unchanged. A second unsaved change is discarded to restore that recovery, which must remain dirty; loading the formal plan and saving must remove recovery. Copy, load-copy, rename and the catalog are then checked on fresh test names. The same original controller remains alive throughout these checks so F8 can still be compared with the first camera snapshot.

Before the command-based edits, a separate marker gesture checks the native UI event path. The first marker's actual overlay screen center is raycast with the current EventSystem; `marker-raycast.json` records the first twelve hits and handlers. The top hit must route pointer-down to that marker. Unity `ExecuteEvents` then sends pointer-down, potential-drag, begin-drag, drag, end-drag and pointer-up to the production component. The moved time must match the nonconflicting same-segment destination, exactly one undo entry must be created, and one Undo must restore the saved clean document. `MarkerPointerPassed` describes this software pointer injection; it is not physical mouse or OS input evidence.

Finally the probe injects an F8 press/release through Unity InputSystem, checks exact URP/FOV restoration, closes replay and quits from Title. Screenshots cover all six tabs, precise editing, the unsaved confirmation, normal view, preview, load and restored view. Reports use plain numeric arrays rather than serializing Unity objects. `BatchEditingPassed`, `RecoveryPassed` and `ProjectManagementPassed` separately describe the new assertions; they do not replace visual inspection or physical-input testing.

Inspect `summary.json`, screenshots, `sidecar-proof.json`, `owned-files-proof.json` and the separate `disk-protection-proof.json`. Runtime flags do not prove image quality: visually check the 1280×720 editor, color/blur, transparencies, UI exclusion and restored appearance. No FPS or full-route claim is made. The probe cleans its generated files on both successful and failed exits; the exit monitor can finish cleanup after a forced exit only when each exact generated filename, source recording, regular-file/link checks, containing directories and completed SHA256 proof match. It never deletes through a symbolic link or junction. A mismatched file is retained and fails protection checks. The monitor also removes the companion only after the original process exits and its exact SHA256 still matches. It may restore config comment headers only when all non-comment settings are identical; substantive differences are preserved and reported as failure. It never deletes a new save or rewrites a changed save. Backups, recording paths, screenshots and raw logs are private and must not be included in a product package.

After F8 restoration, the companion uses `InputSystem.QueueStateEvent` to verify one backend-sized scroll notch changes the production third-person distance by 2.5 m, C enters free flight, and RMB + W moves the real camera while replay time stays paused. The mouse state points above the drawer to avoid legitimate UI scroll consumption. Flight distance is compared with the production speed and clamped frame delta; keys and mouse buttons are released, C returns to third person, and failure/finish paths also release injected state. Evidence explicitly identifies runtime injection, not OS or physical hardware input.

For actual mouse/keyboard inspection, pass `-ManualSeconds 75` (0–120, default 0). The expanded automatic checks take additional time, and the total 180-second bound still applies; 120 manual seconds may exceed that bound. After automated restoration and input checks, the editor reopens, loads the owned clean test plan, and `phase.json` becomes `ManualHold`; protection guards stay active. `manual-state.json` publishes read-only camera/editor telemetry every 250 ms. A tester may finish early by creating `manual-finish` inside that exact session output directory. Before finishing, use the real UI to undo manual edits back to the saved clean state or discard them through the editor. Do not change the target name, create other plans or save manual changes unless intentionally preserving their files for inspection. The probe stops updating ownership hashes when manual inspection begins. At the end, if the editor is still open, its state and actual document must both be clean, its target must remain the owned main plan, and its saved file must still match the last verified hash. Only then does the probe explicitly Save that clean document to remove any recovery created during UI testing and record that completed write. It never undoes tester input or approves a manually changed formal file; an unmet condition fails the run and leaves unverified files for inspection. Finally it disposes the editor, closes replay and quits. Automated `Passed` covers the scripted assertions; manual actions need separately recorded observations.
