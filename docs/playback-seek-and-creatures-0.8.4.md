# 0.8.4 回放跳转与生物核查

## 根因与修改

时间轴拖动原来在每次 UI 值变化时立即重建当前呈现；分页读取每完成一页都需等下一次主线程轮询才继续，新页又使关节索引构建反复取消。现在每渲染帧合并拖动到最后一个请求，单后台 worker 连续读取所需页，使用一次验证的只读元数据快照，关节索引在后台建立并复用仍有效的结果。最近解码页按容量回收，当前所需窗口优先，限制为 64 页、1 GiB 解码估算；不将整场录像读入内存。

按用户后续要求，回放页面缓存从 256 MiB 提高至 **1 GiB**。这只是已访问页面的保留上限：仍只读取当前目标及插值／粒子历史所需的相邻页面，不预分配内存、不为填满缓存额外读取远处页面；超过字节或页数上限时回收最久未使用的旧页。录制片段缓存的独立预算保持原值。

首次遇到的物品／放置物原来在一次 Apply 中同步创建。现在物品、气球、生物、放置物和特效共享每渲染帧最多 4 次创建、192 次粒子预热步及 4 ms 准入截止；人物与物品优先，暂停时继续补齐最新位置，读取新位置时不再补建旧位置。该截止只能阻止后续工作，无法中断单次 Unity 模型创建，也不代表整个回放帧只有 4 ms。连续播放已有粒子的正常模拟及其他逐帧呈现成本另计。

每个外观副本原来单独扫描并缓存全局材质、纹理和网格，还可能把回放自己的材质当作原生资源。现在同场景共享后备资源目录，回放材质通过弱引用标记排除，场景变化失效，最后一个使用者释放时清空。物品构造失败会释放已创建的模型及外观目录。当前渲染器不再每帧先关闭后打开，只写实际显隐变化。特效缓存先回收离开时间段的副本再接纳新资源；跨页重新解码的相同粒子种子按值比较，避免无意义重启。

## 生物证据

证据来自本机 `Assembly-CSharp.dll`、反编译代码和合法安装资源的只读核查。

| 对象 | 已确认缺口 | 修复 |
| --- | --- | --- |
| 火山老鹰 | 原生 `Condor` 没有进入生物白名单 | 接入生命周期、骨骼、外观与状态，纯视觉回放，暂停隐藏原生更新 |
| 森蕈小僵尸 | 原生模型 982 节点、295 个渲染器，原外观上限 256 导致采样异常，整条动作帧不发布 | 节点保持 1024 上限；渲染器提高至有界 512；外观失败独立重试，有效骨骼继续发布 |
| 雾沼青蛙 | 身体与跳跃已有 `MobItem` 动态采集，`LineRenderer` 舌头未录；原生 `BezierRenderer` 输出 200 点 | 单独记录世界空间舌头线，不复制身体或 AI；青蛙最多 256 点，蜘蛛仍最多 128 点，解码按生物类型校验 |

录像仍使用 Schema 14 已有的生物／线条字段，新增原生资源种类和有界长度。新版继续读已有支持格式；旧版 Mod 不认识新增生物种类或较长舌头，不应用于新版录像。旧录像实际缺失的生物数据无法恢复，需要重新录制。

## 验证口径

Release 构建、数据回读、缓存预算和外观生命周期使用独立测试验证；测试不运行 Unity 渲染。真实完整录像反复跳转只读测试属于 .NET 离线读取测量，不是游戏 FPS，具体本机记录保留在 `local/checks/seek-0.8.4/`。

本次 Release 构建 0 警告／0 错误。8 组独立检查共 809 项通过：ReplayContract 664、NativeAppearance 41、ReplayView 26、NativeLoading 11、ReplayNameplate 9、ReplayAudioSpatial 8、Trajectory 35、TrajectoryUpload 15。新增检查覆盖生物完整文件多页回读、青蛙／蜘蛛解码边界、最近页命中与容量回收、后台连续读取、共享目录释放和 295 个渲染器的重复显隐写入。

以下真实录像数据是在本轮初版 **256 MiB** 缓存预算下测量，不能当作调整为 1 GiB 后的新实测：用一份 11.35 MiB、299.4 秒、31 页的真实录像，顺序运行旧版与新版，各在相邻两窗口之间跳转 20 次；16 ms 轮询等待可采样状态。旧版读取 24 页，新版读取 6 页（减少 75%）；平均就绪时间 167.90 → 68.87 ms。排除首次冷读后均值 106.9 → 1.93 ms，新版从第 3 次起的 18 次回跳均没有额外解码。新版最多缓存 5 页／215.07 MiB，始终只有一个读取 worker；释放并执行 GC 后托管内存约 19.20 MiB。该结果说明邻近回跳的缓存命中有效，不能外推为 Unity FPS 提升或所有跳转耗时。

初版 256 MiB 预算下，跨多个相距较远的大窗口时，每个解码窗口接近原预算，无法同时保留，真实远隔窗口的 20 次跳转仍需重复解码，改善有限。后续提高至 1 GiB 可保留更多已访问窗口，首次进入未缓存段仍须解码。未发现这组离线测试有随跳转次数单调增加的保留内存，仍需实机排查 GPU 与 Unity 原生内存。

F9 报告增加当前回放的 `PlaybackFrames` 和 `PlaybackDiagnostic`。播放帧统计只计正在播放且未缓冲的实际渲染帧，跳转／暂停后排除 2 秒暖机，保留最近 8192 帧；1%／0.1% low 仍需至少 100／1000 帧。这不包含 GPU 归因。

尚需游戏内用新录制分别确认老鹰飞行、僵尸动作、青蛙跳跃与舌头，以及同一录像反复跳转后的帧率、粒子预热和退出恢复。首次访问大型录像未缓存段仍可能等待重页解码，不能将后台读取优化视为消除全部卡顿的实测结论。
