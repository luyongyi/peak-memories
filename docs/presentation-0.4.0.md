# 0.4.0：绳索、特效、游戏声音与名字

## 问题与验收口径

此前回放主要复制角色、物品和箱子视觉。绳索/锚头是独立实体，钩爪线是 LineRenderer，粒子与音源也不属于普通物品网格；因此“物品被录下”并不意味着其使用效果已被录下。这是采集/呈现轨道缺失，不是补几个贴图能解决。

0.4.0 加入 Schema 6 的 `Ropes`、`Effects`、`Audio` 三个独立轨道；名字从已有 `ActorFrame.Name` 显示。加载原场景和原版素材，但不再次执行射击、伤害、随机掉落、消耗、网络 RPC 或碰撞施力。原游戏源码、音频、贴图和模型不嵌入 DLL 或录像。

实现已进入实验版；**本页不是“完整游戏级回放已经验收”的声明**。本机游戏没有为这次修改启动，编译与协议测试不证明实际画面、声音和 FPS 正确。

## 录什么、怎么播放

| 对象 | 录制事实 | 播放来源 |
| --- | --- | --- |
| Rope | 实际分段姿态/尺寸、41 个最终视觉骨骼、附着、截断、可见性 | 原生 skinned mesh/material，按记录驱动；不二次解算绳物理 |
| JungleVine / 桥面 | 实际节点、视觉姿态、下垂/长度/抖动参数 | 对应原生网格与变形材质 |
| 钩爪、飞行锚头 | 原 LineRenderer 的真实折点和宽度、锚头从发射到固定的姿态 | 原生线材质和锚头网格，不用首尾直线猜路径 |
| 粒子 | 原生资源身份、实际 seed、播放相位/停止喷射、发射器轨迹 | 纯粒子系统复制原模块和素材，按录像时钟求值 |
| 爆炸 | 实际出现/移除、轨迹/缩放、原生爆炸球动画相位及 shader 参数 | 纯网格和手动 PlayableGraph；不是再调用爆炸脚本 |
| 悬浮炮 | 炮口粒子、独立 AntiSphere 的出现/移除及实际 TRS（含缩小消失） | 原生反重力球网格/材质，不执行其施力或碰撞脚本 |
| 游戏音效 | 实际选中的原生 clip、每次播放身份、起止/游标、位置、音量、音调、循环 | 单独 AudioSource；没有 PCM、麦克风或队友语音 |
| 玩家名字 | 当时记录的真实名字和头部位置 | 游戏名字字体，独立文字 Canvas，无原生 UI 的玩法逻辑 |

角色和动态轨迹目标仍是 60 Hz，受实际渲染帧与网络数据约束。音效游标用时间锚点，源状态以约 20 Hz 加播放事件更新；并非每秒录 60 份音频数据。小于一个采样间隔的短音效使用有界待处理队列保留观察到的播放事件。

## 缓存、查找与隔离

- Schema 6 首帧包含完整状态，后续字段差分；共享未变数组/状态，裁剪时统一换算时间锚点，保留窗口开始前已存在的对象和循环声。
- 滚动样本仍使用 256 MiB 默认保守预算；超限淘汰旧帧，不承诺任意人数/绳索/烟雾密度下都有 120 秒。
- 不在 60 Hz 全场查找粒子/绳索。事件登记配合低频兜底；静止绳索共享形状，运动/拓扑变化后再更新。
- 回放只创建纯视觉与声音组件，不克隆携带 `Awake`、伤害、Photon、碰撞或消耗脚本的完整活 prefab。
- 播放中隐藏原世界的对应呈现、抑制重复原声；退出恢复原来的 enabled/mute 等状态。暂停和拖动不播放音效，滑块停止后短暂防抖再继续，避免重复炸响。
- 原生加载音频淡入结束后才冻结场景时间；回放音源仍经过游戏的 Master/SFX 混音器音量设置，仅避开 Listener 的过场淡入，不改全局音量、不绕过 Listener.pause。F9 同时输出混音器 LoadingFade 与 Listener 状态用于排查无声。
- 资源缺失/不支持、超限或重建失败会提示；失败不应逐帧重复构建/刷调用栈。视觉缓存有界，不随反复前后拖动无限积累。

## 明确边界

- 原生粒子 seed 和时钟重建不是逐粒子录像。粒子碰撞、Trigger、外力、Lights 等会影响玩法或额外对象的模块不运行；外部发射形状/子发射器无法安全匹配时提示不完整。组内子粒子由独立脚本/动画改变激活、相位或材质的情况尚未逐项覆盖，不能宣称所有子粒子都精确一致。
- 粒子的世界空间烟迹需要历史发射器位置。seek 使用有界预滚，单效果最多覆盖约 12 秒；每渲染帧所有效果合计最多 192 次预滚步、4 次新建，每组每次最多 64 步，未完成暂时隐藏并提示，暂停时也会继续准备。窗口之前的轨迹不存在，过长烟迹会近似并提示。Shader 全局时间、独立灯光和全部特殊材质动画未做到确定性重放。
- 游戏音效不包括语音；不完整复刻混音器 DSP、特殊距离曲线、音频设备/编码差异。倍速伴随音调变化，短音效起止受观察帧精度约束。
- 未重建所有敌人/机关/天气，也未改成全身布娃娃或完整原生 AnimatorController。角色动作仍为基础动画与有限手部锚点，不承诺所有第三方 Mod 动作一致。
- 老 Schema 2–5 正常读取，但它们没有这些呈现轨道。需用 0.4.0 重新录制，不改写旧录像伪造缺失数据。

## 游戏内验收清单（待执行）

1. 新开一局，先按 F9 留下空闲采集基线。使用悬浮炮，检查蓄力/炮口与独立悬浮球；原声音应只响一次。
2. 放绳/发射绳枪，观察飞行锚头、成形、贴墙/绕障、固定与攀爬后变形；使用钩爪检查整条线及端点，而非仅手中物品。
3. 点燃炸弹、使用火焰物品、点燃火箭背包并等爆炸/烟花；检查粒子、烟尾、原生爆炸模型及相应声音。保存前等一次静止阶段，检查 F9 模块耗时。
4. F6 保存后回主菜单进入片段，逐项对照。检查本人与朋友名字、装扮、物品与效果位置。远端数据以当前客户端实际可见/同步状态为准。
5. 从事件后倒拖到之前，再正向播放；对象应按时间出现/消失，声音不得在拖动中连响，暂停不得继续累积烟或播放循环声。
6. 在片段中段直接进入、跨过多个事件、改变速度、反复 seek；没有无界创建、持续报错、复制掉落或额外伤害。
7. Esc 回主菜单、重新正常游戏，原相机、名字、声音和旧足迹 Mod 应恢复；真实存档不受回放影响。
8. 退出并重启 PEAK 再打开同一片段，核验资源定位不依赖上一次进程实例。收集 F9 日志与缺失资源提示，才据此判定具体效果已验收。
