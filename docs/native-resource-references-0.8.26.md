# 0.8.26 原生资源引用与采集读取缓存

日期：2026-10-13。本轮按“游戏已有资源由回放直接调用，录像保存身份和必要变化”的方向核查声音、特效、物品、生物与外观。保留 Schema 23、完整录像容器 v4，读取器继续接受 v1–v4。最终 DLL 的原生海岸到雨林采集及跨关回跳已完成；离线对照、合约和自动化原生测试不代表完整听感、视觉或 FPS 验收。

## 资源引用的实际含义

回放已经复用游戏内的音频片段、原生模型、网格、材质、纹理、着色器及可核验的动画。录像保存稳定资源标识，播放时在当前游戏中解析，再把记录的状态应用到回放副本；不保存音频 PCM、网格顶点、纹理像素或着色器资源文件。

这里的“指针”是可跨启动保存的资源标识，不是进程内存地址。游戏重启后内存地址会变化，资源必须重新解析；游戏更新或资源被移除也可能使旧引用无法解析。资源标识省掉的是资源本体，发生了什么、在何时何处发生，以及资源的运行时变化仍需记录。

| 内容 | 复用游戏资源 | 仍需保存的录像信息 |
|---|---|---|
| 声音 | 原生 `AudioClip` 标识，包含名称、样本数、频率和声道数 | 播放／停止事件、时间、位置、音量、音高、循环与播放相位等。音量或位置持续变化时保留低频实际观察。 |
| 粒子特效 | 原生特效资源 | 出生／停止、随机种子、运行时模块初态与变化、移动发射器姿态。默认不保存逐粒子轨迹；跳转在有界预算内恢复相位。 |
| 物品、箱子、机关 | 原生物品或场景对象标识 | 出生／消失、拿取／放置、开启、显隐、真实状态及必要运动。静置保留末态，由新事件唤醒。 |
| 生物 | 原生模型与已核验的待机动作 | 激活、休眠、抓捕等状态边界及动画时钟。原生待机按绝对录像时间求值；真实活动姿态继续采样。 |
| 箱子等原生动画 | 已核验的原生动画片段 | 动作开始、相位、速度与完成状态。无需为已知固定片段重复保存每个动画节点，但无法核验或受玩法脚本驱动的运动仍保留实际结果。 |
| 外观 | 网格、材质、纹理和着色器标识 | 颜色、渲染队列、材质替换、显隐、`MaterialPropertyBlock`、局部灯光等真实覆盖；共享资源不代表运行时属性永远不变。 |
| 环境 | 当前关卡的原生场景与日夜资源 | 切关、雾、日夜、风、熔岩、灯光等实际变化及时间。持续变化仍按已有低频时钟观察。 |
| 玩家与真实活动骨骼 | 原生角色模型、装扮和骨骼结构 | 实际骨骼姿态与采样时刻。非玩家活动最高 30 Hz；本地玩家使用配置频率，队友跟随原生网络同步频率。 |

声音在远距离跳转后也解析原生片段，并只准备目标时刻仍需播放的声音。页面与声音准备、跨关地图分帧准备沿用 0.8.25 的路径；没有为复用资源而从头重放所有历史事件，按需读取与 1 GiB 解码缓存上限保留。

## 本轮保留的主线程优化

声音采集增加每个源的片段元数据缓存。对同一个已准入的原生片段包装对象，名称、样本数、频率、声道数和时长五项原生属性只读取一次；片段包装对象替换时重新读取，未成功验证的描述不会缓存。普通观察只取一次 `source.clip`，动态音量、音高、位置及播放相位等字段只在既有最高 20 Hz 时钟接受该次声音采样后读取，不重复读取后再丢弃。

合约测试对同一片段进行 10,000 次稳定观察，五项元数据 getter 合计仍为 5 次；替换片段、无效时长或频率等边界另行核对。这证明受测缓存的原生属性读取次数下降，不直接等于游戏内总采集耗时同比下降。

外观采集把同一次 `captureEpoch` 内共享材质的着色器标识、材质名和渲染队列描述复用给其他观察者，避免同一批次因多个模型共用材质而重复跨 Unity 边界读取。下一个采集批次重新观察，保留运行时着色器／队列变化；动画材质只读取需要的描述。失败读取不缓存过期结果，独立材质覆盖、`MaterialPropertyBlock` 和其他动态状态仍单独保留。

`AudioClipMetadataContract` 6 项、`NativeAppearanceContract` 59 项通过；后者包含本轮新增的 4 项批次描述缓存测试，覆盖共享读取、下一批次变化、按需读取和失败后重试。没有扩大永久缓存到可变材质属性，也没有新增全场扫描或提高采样频率。

## 共享资源字典实验与回退

本轮还尝试容器 v5，把重复的声音／特效资源描述进一步拆成共享字典。最终选择完整回退该格式改动：已有去重和压缩下，真实文件的额外收益很小，配对解码没有显示明确提升。当前保留的代码仍写容器 v4，不要求用户转换或重录旧文件。

以下为同一源录像全部帧的离线重写，两侧保留相同 Schema 23、采样时刻、动作与状态。它们不是先后两次游戏游玩的录像体积对比；重写包含一次性头部、目录及索引，也不等于原始文件自身的字节数。

| 同源完整样本 | 唯一帧／页面 | 既有 v4 重写 | v5 八页复用门槛实验 | 实验额外减少 |
|---|---:|---:|---:|---:|
| 海岸到雨林，68.07 秒 | 4,006／69 | 4,375,894 字节 | 4,360,916 字节 | 14,978 字节，0.342% |
| 森蕈续档，60.10 秒 | 3,493／61 | 4,769,611 字节 | 4,741,799 字节 | 27,812 字节，0.583% |

两组均按逆序读取全部页面，逐字段及独立特效历史比较一致；包含页面重叠验证的帧数分别为 4,074 和 3,553。这个结果说明实验没有改变这两份样本保存的数据，不能据此声称所有未出现玩法都已验证。

回退后又用最终读取／写入代码全量重写两份相同输入，分别得到 4,375,894 和 4,769,611 字节，且完整录像 SHA-256 与实验前的 v4 输出各自完全一致。本轮保留的缓存优化不改变录像编码，因此不预期单靠它降低录像体积。

较早的 v5 候选另做同进程配对解码：每份录像抽取 12 个分散页面，预热后交替进行 3 轮、36 对载入。没有得到明确的解码收益；这些时间包含自然 GC，属于 .NET 离线页面载入，不能视为 Unity 主线程、冷盘读取或游戏 FPS。最终实验要求音频完整状态至少在八个独立页基线中相同才建立共享块；其全量实验仅用于上述体积和一致性核对，没有把重写总耗时当作独立解码性能。

原始审计记录保留在仓库本机 `local/checks/resource-references-0.8.26-20261013/`：`transition-full-before/rewrite.json`、`transition-full-after-eight/rewrite.json`、`resume-full-before/rewrite.json` 和 `resume-full-after-eight/rewrite.json`；较早配对解码分别位于 `transition-paired-initial/paired-decode.json` 与 `resume-paired-initial/paired-decode.json`。私人录像和本机绝对路径不随本文分发。

## 保留边界与待验收内容

“资源引用＋事件”适合游戏已有且输出可核验的资源。动态灯光、天气、随机进程、受物理作用的移动和真实骨骼不能统一只存一个资源名；必要状态、时钟、种子或实际样本必须保留。回放副本不直接调用会伤害玩家、生成真实物品、改变存档或触发网络消息的玩法回调，只恢复已采到的可见和可听结果。

已验证上述路线的原生采集、事件和跨关回跳；其他地图、多人组合、主观听感、连续帧率及长录像远跳仍未在本轮逐一复测。本页不沿用 0.8.25 的游戏内成绩作为 0.8.26 新代码的实测结论。旧版已存在的单次原生资源载入、地图切换和全局 GC 短峰值也没有因资源标识缓存而获得消失保证。
