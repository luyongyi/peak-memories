# 生物逐类归因与事件／资源引用优化方案

分析对象为已安装的 0.8.30，MVID `1dcb4c4c-65b7-4645-aa20-4c7bb456ea65`。本轮只读分析现有录像和本地源码，没有修改正式 DLL、采集策略或游戏安装。H 各区域完整稳定页覆盖约 57–58 秒；G 雾沼覆盖 118.75 秒，均排除到达、建档和切关。

下表中的百分比采用实际写入的压缩前 UTF-8 字节，包含窗口内新共享整实体块和跳转历史，不展开窗口前已存在的共享初态。它们不是 CPU 或精确磁盘类型占比。物种实体数由稳定窗口中的不同 Key 统计，引用条目数不能当作采样次数。青蛙身体及舌头在结论表合并为同一物种，不能把两条轨道的 20 个实体加成 40 只青蛙。

## 乌鸦剩余高占用的直接原因

0.8.30 已解决相位校正时重复读取 44 个节点的主线程问题，但存储端的完整快照提升策略仍把相同内容重新装进新块：

1. 原生 Animator 时钟为浮点数；2 ms 的相位误差阈值约每 1–2 秒产生一次新时间锚。
2. 新锚点改变整实体 JSON 及 hash，即使根、骨骼、外观、动作种类都未变。
3. 第二次相同页基线命中 deferred promotion 后，后台将当前整实体保存成新共享块，其中仍包含完整 44 节点和外观。
4. 因而“没有重新读取骨骼”并不等于“没有重新写入骨骼”。上一轮收口没有彻底处理这条存储路径。

G 的 46 只乌鸦在 118.75 秒新增 **1,344 个**完整共享块，压缩后 **3,404,246 B**。每只乌鸦各块中的根姿态、Nodes、Visuals 各自均只有一种内容；其中仅 Nodes 原始值就有 13,112,007 B，Visuals 字段 2,541,504 B。

进一步保守比较相邻整块，仅删除 SampleTime 与原生动画 AnchorTime／ClipTime，其他所有字段仍参与指纹：**1,303 块**完全一致，合计压缩后 **3,300,497 B**，占该稳定窗口实际磁盘增量的 **35.35%**，折合约 **1.59 MiB/min**。H 同样确认 664 块、1,682,135 B、约 35.90%／1.67 MiB/min。神殿终段 352 个新增乌鸦块全部符合这种仅时钟变化的重复，共 890,809 B，占该窗口磁盘增量 24.40%。

这些是当前重复完整块的实际规模，不是承诺可净省同样大小：替代的时间补丁、页引用和必要初态仍有成本，实际收益须用同源重写及读回验证。

## 建议执行顺序

### 1. 先解决“只变时间却重写完整身体”

对已核验的原生动画实体，把稳定的模型／外观／骨骼检查点作为独立基线；后续只编码根变化、状态、动作引用和小时间锚。禁止相位校准导致重新提升为含全部骨骼的整实体块。分流放在完整 JSON 序列化前，避免后台仍先序列化整棵树再丢弃。

第一阶段可沿用现有 Schema 25／v4 的直接叶引用与绝对页补丁能力，保持共享块自身不嵌套另一个 $Shared；不需要重跑游戏 AI，也不需要降低真实动作采集频率。此阶段保留现有校准阈值，只改变重复包装与写入，便于同源逐页证明视觉数据等价。

验收：同一只乌鸦连续 300 次纯时钟校正不能带来 300 份完整 rig／外观；发生换资源、拓扑、外观、显隐、实际动作和根变化时仍建立必要检查点。对 H/G 录像作隔离输出的同源重写，全部页独立逆序读回及事件历史比较一致，再跑原生路线确认主线程未增加工作。

### 2. 乌鸦普通待机／飞离真正改为事件记录

| 时刻 | 采集端最少记录 | 回放端工作 |
|---|---|---|
| 首次出现 | 实体ID、资源／外观基线、栖点TRS、Idle初相位／随机偏移、速度 | 按绝对录像时间循环原生 Idle |
| 确认起飞 | 真实起飞时刻、Fly资源、初相位／速度、必要检查点 | 由原生 Fly clip 恢复翅膀、身体及飞行位移 |
| 关闭／销毁 | 实际结束时刻／显隐事件 | 在真实时刻结束视觉 |
| 外观／根／资源发生变化 | 仅变化字段或新的必要基线 | 应用新状态并切断跨事件插值 |
| 必要相位校准 | 小标量时间补丁 | 调整求值时钟，不替换身体基线 |

普通等待不持续采集骨骼或重复写相同动作。原生 RPCA_FlyAway 先 yield 一帧后才 Animator.Play，所以 RPC 只标记待确认，实际 Fly 状态出现才确认起飞。原生资源长 3 秒，但实际逻辑约 2.5 秒后销毁，必须记录真实终止，不能把 clip 长度当作实体寿命。

Fly 未写关键帧的六处旋转（左右腿连接、左右肩、上下喙）仍需继承检查点；首版保留一次完整起飞检查点最稳妥，后续再验证缩成六处修正。声音和羽毛实际出生／停止继续使用独立事件。

对已审计的普通状态，可把 5 Hz Animator 深查询降为事件后的有界确认，加低频错峰安全检查；先保留必要的小标量相位校准，完成长时间 Idle 漂移对照后再放宽仅待机的相位精度。事件 hook 只置 dirty，查询 Unity 状态仍在主线程，序列化和哈希在后台。喙开合、速度／控制器替换、动画混合和未识别状态须保守回退。

进一步的嘴部优化应核验原生 RavenMouthOpen 动画，用“资源＋相位＋5 Hz 权重曲线”代替整身 44 骨骼口型回退；经独立原生语音驱动视觉比较前，保留现有回退能力。

青蛙有一处具体的代码疑点：当前静息条件要求 `!inWater`；本地原生 WaterRaycast 对 Map 层射线命中任意 transform 都可能置 inWater=true，Water 标签仅决定浮力分支。因此该字段不能未经诊断直接解释成“正在水中”。需要在只读诊断中关联实际命中标签／浮力和根速度后修准入；不能简单删掉水保护或宣称现有20只都静置。

### 4. 集中压缩固定目录和轨道包装

森蕈优先处理的结构性开销是 384 株静态孢子机关、72 只待机蜘蛛等每页重复的成员引用和 CreatureOrder，而不是再降低已停止的骨骼采样。目标是共享固定目录／顺序，页里只保留目录引用及真实出生、移除、状态变化；活动小包用整数实体ID，避免反复携带长Key、Kind、Resource、SourcePath。空更新字段可按协议省略，解码端以明确默认／不变语义恢复。

集合目录引用超出现有单实体共享类型时，应独立设计并版本化，不能直接把共享引用嵌入旧整块绕过约束。每个目标页仍需独立恢复实体集合、动作时钟、视觉基线及历史入口；解析必须有界、无循环，保持现有页／内存预算和旧录像读取。

## 必须守住的验证要求

- 检查频率与写入频率分开：检查一次不等于写一次；只写实际变化或有用的观察端点。
- 停采区间要显式保留 hold 语义或唤醒前的最近稳定端点，避免下一次运动从几秒前开始插值。出生、销毁、换资源、显隐及动作边界切断插值。
- 回放在纯视觉副本上求值资源，避免原生行为脚本再次生成物体、交互或影响游戏状态；随机偏移与真实状态起止必须记录。
- 在长待机、起飞一帧延迟、直接跳入飞行、反向跳、暂停、复用实体、口型与异常控制器场景中复测。对比各物种 geometry／node visits、Animator checks、时钟补丁、完整块／叶块／元数据字节及主线程分位数。
- 不放宽1 GiB按需缓存，不要求从录像开头补跑事件，不通过漏掉真实动作和特效换取体积下降。未核验资源及物理路径继续保守回退。

建议先完成第1项并做同源等价重写，再推进乌鸦事件化和其他生物静息门；固定目录版本化作为单独后续步骤。当前已确认的乌鸦重复完整块规模约1.6 MiB/min，可以作为下一轮收益核对基准，最终体积以实施后的原生稳态测试为准。
