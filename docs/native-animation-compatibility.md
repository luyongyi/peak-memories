# 原生角色动画兼容性：证据与验收计划

核查日期：2026-09-25。本文件是后续原生 Controller 验证的设计记录，**不是已完成的游戏内验收报告**。

## 当前状态

当前角色回放仍使用原生 `AnimationClip`、手动 `PlayableGraph` 和纯视觉分身；没有启用原生角色 `AnimatorController` 替换方案。录像不包含游戏模型、贴图或动画资源，播放时从本机同版本游戏解析资源。

本轮先处理现有片段混合及文件中重复字段；完整 Controller 播放须通过下面的独立验证后才能启用。文件格式压缩和动画播放器选择是两件事，不能以协议测试通过推导出 Unity 动画正确，也不能承诺文件体积或 FPS 的固定改善幅度。

## 已核实的静态证据

### 本机 API

检查对象是游戏安装目录的 `PEAK_Data/Managed/UnityEngine.AnimationModule.dll`，不是另一个 Unity 版本的在线文档。

- 文件大小：225,200 字节。
- SHA-256：`305E0395C6FE28D36B0612C12F3BC83F7A93A3DBE1997B085A5A416BC9E80F12`。
- `AnimatorControllerPlayable` 提供读取当前/下个状态、过渡信息、参数与层权重，以及 `Play`、`PlayInFixedTime`、`CrossFade`、`CrossFadeInFixedTime`。
- 此 DLL 中两个 `CrossFade` 系列的重载最多四个参数：目标状态、过渡时长、层、目标状态时间。没有指定“当前过渡已经进行到多少”的参数。
- `ResetControllerState` 恢复默认状态，可选是否重置参数；它不是任意内部状态快照的反序列化接口。

因此，记录 `current state + next state + transition progress` 很有用，但**不是公开 API 能逐位恢复完整状态机的证明**。中断过渡、同步层及内部混合历史必须单独验收。

### 本机 Scout 资源

只读检查 `PEAK_Data/resources.assets` 中本次安装的 `Scout` AnimatorController（本机 Path ID `2438`）。这些 ID 仅用于复核本次安装，不应成为跨版本录像的稳定身份。

| 项目 | 本次资源中的事实 | 对回放的影响 |
| --- | --- | --- |
| 动画层 | `Base Layer`、`Throw`、`Item`、`Head`、`Reach`、`Point`、`Myres Music`，共 7 层 | 不能把所有层的 clip 平铺后统一归一化 |
| 层模式 | 7 层均为 Override；未配置 AvatarMask，IK Pass 均关闭 | 无 Mask 不表示每个 clip 都绑定全身，仍需保留逐层覆盖语义 |
| 默认层权重 | 序列化值为 `0, 0, 1, 1, 1, 1, 1` | Base 层运行语义不能按序列化的 0 静音；其他层读取实际运行权重 |
| Head 层 | clip 只绑定 Head 骨骼 | 扁平混合可能错误削弱基础全身动作 |
| 参数 | 48 项：19 Float、23 Bool、2 Int、4 Trigger | 参数表由所有层共享，不应每层复制一份 |
| Trigger | 其中 3 个是 `--INPUT--` / `--MISC--` / `--ITEM--` 分隔名称；实际动作 Trigger 为 `Kick` | 不应把分隔项误当真实动作；仍按资源目录识别类型 |
| 状态行为 | `m_StateMachineBehaviours` 为空，行为索引与范围也为空 | 当前 Scout 没有已证实会执行的 StateMachineBehaviour |
| AnimationEvent | 基础 Controller 的 129 个 clip 及检查到的覆写 clip 均无事件 | 仍保留关闭事件的防御设置；不能据此允许复制玩法组件 |
| 跳跃与落下 | 检查到的跳跃状态/叶子无镜像、Cycle Offset 为 0、状态速度为 1 | 不应另猜一个镜像或速度修正去“美化”跳跃 |
| 落下 BlendTree | `Velocity Y` 的四个阈值为 `-20, -10, 0, 1`；两个叶子引用同一个 Down clip，但编译时长不同 | 同名 clip 的不同叶子不能仅按名称合并时间 |
| 其他速度 | Movement 使用 `InWater` 速度参数；LedgeGrab 固定速度 0.75、PunchFist 为 0.7 | 不能假定所有状态和叶子共享相同播放时钟 |

三个覆写 Controller 均引用同一个 Scout：`Scout_MushroomMan`（Path ID 2784，17 项替换）、`Scout_NoHeadBob`（2785，12 项）、`Scout_Zombie`（2786，21 项）。它们没有在本次检查中引入额外状态行为。Controller 身份/覆写变化仍需进入录像，不能只保存基础资源名。

游戏程序集确有 `DisableIKBehavior`，但它**没有挂在上述 Scout 资源上**。不能把“程序集里存在此类”写成当前 Scout Controller 必然抛错的结论；游戏更新后应重新检查。

### 参数与最终姿态来源

原生 `CharacterAnimations` 不只根据一个“走/跳”枚举播放动画。它向 Animator 写入平滑后的移动、冲刺、观察、地面倾斜参数，以及蓄力、跳跃、攀爬、抓取、抛掷、表情等状态。正常起跳先经过约 0.1 秒蓄力，然后施加跳跃力；落地后清除跳跃状态。

还有其他写入方：

- `ItemAudioManager` 根据实际物品设置吃、喝、治疗、解毒、道具专用使用参数及消耗结束状态。
- `CharacterGrabbing` 设置 `Kick` Trigger。
- 表情等行为会直接 `Play` 状态；仅重放参数不会必然再次触发这类显式跳转。
- 原生动画图在物理步中手动评估，随后身体通过关节、力矩和位置弹簧跟随目标姿态。最终显示不是纯 clip 姿态。

候选采集应读 Animator **实际求值所使用的参数/状态**，避免只记录按键后在回放端重新执行平滑。还需核实采样与原生图评估的先后顺序，防止把本次 Update 的参数与上次 FixedUpdate 的状态错误配对。60 Hz 录像采样不等于原生动画每秒恰好求值 60 次。

这里只摘要行为事实，不在仓库复制游戏反编译代码或资源。

### 已确认的额外 Mod 边界

本机安装的 `PeakFlipJump` 使用原生表情序列触发 BackFlip，后续冲量来自游戏原生物理流程；它没有直接生成一套绕过 Animator 的自定义骨骼动画。`PeakSpinModel` 则在原生 `Character.SetRotation` 后额外叠加模型 yaw，当前回放按观察方向重建朝向，没有覆盖这段额外旋转。因此原生 clip 的混合修复不等于复现全部物理弹性或旋转 Mod 效果。仅凭 Mod 已安装/启用，不能认定它们就是此次前跳异常的原因，仍需确认片段里是否实际触发。本轮没有修改、停用这些 Mod，也没有实现上述额外兼容。

## 候选最小轨道（尚未启用）

| 内容 | 存储建议 | 不可省略的原因 |
| --- | --- | --- |
| 游戏/Controller/覆写目录、参数类型与名称 | 文件级目录，帧中用索引；校验游戏构建与资源身份 | 避免每帧重复字符串，也避免把旧 hash 用在不同 Controller 上 |
| 位移、朝向与必要的持物定位 | 保留目标 60 Hz；不补造低帧率期间不存在的帧 | 原生动画不会替代真实路线与物品位置 |
| Bool、Int、Trigger、显式 Play、层权重与 Controller 切换 | 带顺序和时间的变化记录 | Trigger 可在采样前被消费，单次读取参数快照可能看不到 |
| Float 参数 | 缓存参数目录，记录实际值的无损差分；以后再验证误差受限的简化 | Input、Sprint、Floor Lean 等平滑值常连续变化，不是天然稀疏事件 |
| 每层状态锚点 | current/next 完整状态 hash、未取模 phase、速度、层权重、过渡标识/时长/单位/进度 | 保留循环次数、变速和过渡上下文，防止 seek 后重新从起跳第一帧播放 |
| 快照 | 周期完整状态；保存窗口首帧独立基线 | 120 秒内存窗口可能从跳跃或过渡中间开始 |

7 层共用一份参数表。缓存参数 hash、类型和数组，不每帧枚举并分配参数目录；状态查询也应避免逐 clip 字符串分配。差分减少文件写入，**不自动减少 Animator Getter 或图求值的 CPU 成本**。

第一轮 Controller 验证应保留现有基础 clip 轨道作对照/回退。是否能在将来移除重复轨道，必须在 seek 与兼容性通过后决定；当前不承诺新格式只保存少量动作事件。

## 有界 seek 与 120 秒裁剪策略

以下是待验证的设计约束，不是当前播放器已实现的行为：

1. 顺序播放根据录像时钟推进视觉图，不跟随墙钟自由运行；暂停、单步和速度变化都使用同一录像时间。
2. seek 先查找目标前最近的可恢复锚点，再按记录的评估顺序重放参数/状态变化。可以从每 1 秒快照开始验证，但“有快照”不等于“中断过渡可完整恢复”。
3. 对预滚同时设置时长、求值步数和每渲染帧工作量上限；这些上限以实机计时确定。到达上限仍不能恢复时，明确回退或提示，不无限循环、不在一帧补跑整段录像。
4. 目标恰在过渡中间时，优先使用能证明有效的较早锚点。公开 API 无法恢复的历史混合不能伪装成已精确恢复；验证期回到已有 clip 轨道，并标注近似。
5. 滚动窗口淘汰旧数据前，必须保证剩余首帧可独立解码。依赖窗口外事件的参数值、层状态、装备、物品/箱子终态都需折叠到首帧基线；必要预滚历史应单独有界保留，而非悄悄依赖已淘汰帧。
6. 保存时统一重定位事件/锚点时间，保持相对关系；先前已开始的动作允许以早于首帧的锚点或等价首帧 phase 表达。不得把正在进行的跳跃当作首帧新触发。
7. Controller 不匹配、有歧义或缺少状态时，只能回退到文件里**确实存在且可解析**的 clip 轨道；没有回退轨道就明确不支持，不能猜测历史动作。

纯数据测试可以验证边界查找、时间重定位、步数上限、事件顺序和缺失数据分支；它不能证明 Unity 内部状态机、骨骼或过渡已正确还原。本次没有添加一个以模拟状态机冒充 Unity 兼容性的测试。

## 必须保持纯视觉隔离

候选播放器仍只建立 Transform、必要渲染组件和受控 Animator，不复制完整 Character，不添加网络、AI、刚体、关节、碰撞体、道具使用或音频逻辑。

检查到的动画曲线可以写 GameObject 激活状态（包括音效辅助对象），以及 `AnimatedVariables`、`Bodypart`、`AudioLoop` 等组件字段。**关闭 AnimationEvent 不等于隔离所有动画副作用**：分身上不得为了消除缺失绑定警告而补装这些玩法组件。还需验证动画曲线不会意外隐藏必要的视觉子树。

禁止为获得“更原生的起跳”调用 `JumpRpc`、开箱、物品使用或原生物理更新。Controller 负责姿态，世界坐标和实际掉落由录像轨道决定。使用同一 Controller 也不会自动复现主动布娃娃碰撞；若以后补充有限躯干残差，应作为单独功能验收，不扩大成默认全身布娃娃记录。

## 游戏内验收矩阵（全部待执行）

同一片段比较“从头顺序播放到 T”和“从前/后任意位置 seek 到 T”。采用相同跟随视角及逐帧截图；记录游戏构建、Controller 身份与首个偏差时间，不记录或公开参与者私人身份。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 单步与暂停 | 原地、行走、奔跑、前跳；暂停后逐样本前进 | 不因墙钟继续动作；蓄力、离地、顶点、下落、落地顺序正确 |
| 前后 seek | 在上述阶段反复向前/向后拖动 | 同一 T 的姿态与顺序播放一致；不残留未来装备/动作，不从起跳开头重播 |
| 过渡中途 | 移动→蓄力→跳跃、落地→移动；中途改变方向/动作 | 无明显姿态突跳；遇不支持过渡明确回退而非假称精确 |
| 同 clip 多叶 | 连续上升、顶点、快速下落 | 两个 Down 叶子的不同播放设置不被同名归并抹掉 |
| 7 层 | 边移动边拿取/使用/投掷、观察、伸手、指向 | 基础身体不被 Head/Item 等覆盖层错误稀释；层权重与绑定正常 |
| Trigger/显式跳转 | 踢腿、表情，并在动作前后 seek | 不漏动作、不重复触发；不调用真实伤害/RPC |
| 120 秒起点 | 游玩超过窗口；令保存起点落在跳跃/使用/过渡中途 | 新文件第一个可见时刻即正确阶段，所有依赖均在文件内；没有伪造起点事件 |
| Controller 覆写 | 正常与去头部晃动场景；独立夹具检查另两种覆写，另测骸骨等外观变化 | 使用实际记录的 Controller，切换前后可 seek；不把外观名称直接当 Controller 身份 |
| 速度/时钟 | 0.25/0.5/1/2 倍速、暂停、模拟低 FPS | 录像时间一致，无双重乘速；低帧率不批量补造采样 |
| 回退 | 人为使候选状态不可解析，保留合法 clip 对照轨道 | 明确降级、画面仍可理解；没有无限重建图或逐帧报错洪水 |
| 重开进程 | 保存、退出、重新启动后观看 | 不依赖上次进程实例 ID、内存 Controller 状态或缓存目录顺序 |
| 隔离与退出 | 反复播放、seek、取消加载和退出，再进入正常游戏 | 没有额外玩家/刚体/RPC、物品消耗或存档变更；相机/输入/其他 Mod 恢复 |
| 开销 | 同片段、同人数、同视角对照旧播放器 | 记录采集与 Playback 的 CPU/分配，以及 Unity Profiler；不能只报告采样 Hz |

发现差异时分别归类：采集时序、状态/过渡恢复、层混合、资源绑定、主动布娃娃近似。不能用“原生 Controller 已接入”作为总体通过条件。

## 只读复核方法

本机 API 可用已安装的 ILSpy 命令行检查；只输出签名，不向公开仓库导出程序集或源码：

```powershell
$gameRoot = 'C:/Program Files (x86)/Steam/steamapps/common/PEAK'
$animationModule = Join-Path $gameRoot 'PEAK_Data/Managed/UnityEngine.AnimationModule.dll'
Get-FileHash -Algorithm SHA256 -LiteralPath $animationModule
ilspycmd -t UnityEngine.Animations.AnimatorControllerPlayable $animationModule |
    Select-String 'public .*CrossFade|public .*Play\(|public .*ResetControllerState|public .*SetLayerWeight'
```

以下是历史资产审计方法，使用本机单独安装的 UnityPy 1.25.3；审计工具和提取数据不属于本仓库的构建依赖。只在内存加载 `resources.assets`，检查 Path ID 2438 的 `read_typetree()`：

- 层：`m_Controller.m_LayerArray`；结合状态/clip 的实际绑定核对覆盖范围。
- 参数：`m_Controller.m_Values.data.m_ValueArray`。
- 行为：`m_StateMachineBehaviours` 及 `m_StateMachineBehaviourVectorDescription`。
- 覆写：2784/2785/2786 的 `m_Controller` 指向和替换表。

游戏更新后重新查找资源名称，不能假定 Path ID 不变。不要提交提取的游戏资源、私人录像、完整日志或反编译源码。

## 启用门槛

先完成现有播放器的低风险修复和无损文件精简；再用独立开关验证完整 Controller；通过上述时钟、seek、裁剪、覆写与隔离检查后，才考虑将其设为默认。首次稳定验证之前保留 clip 对照及回退，不启用未经实机验证的替换，不以合成测试承诺体积或 FPS。
