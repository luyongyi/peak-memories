# 0.8.0 片段缓存与完整录制独立开关

正常游玩时始终缓存最近最多 120 秒，按 F6 保存 `.peakreplay`。完整录制是独立设置：主菜单「回忆录 → 录制方式」可以开启／关闭，游戏内 F4 也可开关。开启后从当前时刻开始写一个 `.peakrun`；关闭时在后台封存，片段缓存继续。再开启产生新的完整录像，不合并此前的录制空档。

同一 `SampleClock` 命中的一次采集先交给滚动缓存，再将同一不可变帧和已有大小估计交给可选完整写入器。没有增加采样频率、第二次场景扫描或另一套人物／物品采集。完整录制关闭、写盘失败及队列拒绝均不阻止后续缓存；F6 保存时仅截取有界引用窗口，时间重定位和写盘在后台完成，不修改仍在写入的原始帧。

完整录制启停不会重建 `RollingCapture`。下一采样本身含完整世界状态，完整文件的首个页面从自己的基线编码；历史动画时钟按新文件起点重定位，保留合法负锚点以维持已发生的动画相位。新文件的 UTC 起点使用实际开启时刻，片段另按自身窗口生成时间信息。

## 配置与迁移

`BepInEx/config/cn.mylus.peakreplaylab.cfg` 新增 `Recording.ContinuousEnabled`。已有该值时沿用；第一次升级时缺失该值，才用旧 `Recording.Mode` 的 `Continuous` 初始化为开启，`Rolling120` 或未知值初始化为关闭。旧键只用于迁移。F4 和原生设置页修改新开关，自动验收的临时覆写仍不修改玩家配置。

保留旧枚举 0／1 作为配置与测试 API 的兼容映射，两种值都允许片段保存，并保留相同的滚动窗口。录像格式仍为 Schema 14，已有兼容录像无需重录。

## 资源与验收范围

滚动窗口原有默认 256 MiB 预算和最多 7,201 帧限制保持。超出时间／内存预算时淘汰最旧数据，片段可能短于 120 秒；F9 显示实际时长。完整录制现在也保留这个窗口，因此其内存占用高于旧的两帧方案。F6 后台保存还会短时持有所选窗口，不能将单个缓存预算当作进程总内存上限。写入队列、完整录像和分页回放的原有限额保持。

性能报告中的 `RecordingFrames`／`StoppedFrames` 现在分别表示完整文件写入开启／关闭，两组都继续滚动采集；不能解释成整个录制功能开启／关闭。统计仍排除封存期间和切换后 2 秒暖机。

Release 编译 0 警告／0 错误。ReplayContract 624、原生控件复制 26、加载 11、轨迹导出 17、上传 10，共 688 项检查通过。其中 7 项并行录制检查使用真实写入器、读取器及合成数据，覆盖重复 F6、完整文件停止／重启、异步快照与前后拖动、旧动画锚点、实际写盘异常、队列溢出和单采集接线。没有用私人录像或连接真实投稿服务。

这些检查不替代游戏内快捷键、原生控件显示、多人内存和 1%／0.1% low 的实机验收。
