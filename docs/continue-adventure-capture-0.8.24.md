# 0.8.24 安装、续档与切关验收

日期：2026-10-13。0.8.24.0 已安装到 PEAK；临时测试 DLL 已移出游戏。保留 Schema 22、完整录像容器 v4、场景最高 30 Hz、队友原生网络频率及 1 GiB 按需回放缓存。

## 修复与原因

此前自动完整录制在首个 capture.Tick 前创建文件。若恢复存档时首帧采集暂态失败，InterruptFullRun 会封存失败文件并将当前场景记为已停止；五秒后滚动缓存可以恢复，完整录像却不会自动重启。

现在固定使用同一个已缓存的 accepted 回调：先完成帧验证和 Buffer.Add，再决定自动创建文件，并把该首帧直接入队。不新增采集循环、热路径委托、对象搜索或逐帧文件创建。文件创建失败、手动 F4 停止和已有录像发生故障的停止规则保留；显式 F4 / 测试起章行为保留。

这是代码确认并修复的失败恢复缺陷。这次使用用户现有存档，0.8.23 和 0.8.24 都正常采集，未复现用户原来的「继续冒险完全不采集」，因此不能断言原故障必然由该缺陷触发。原生就绪条件不依赖 Level_ 场景名，未放宽场景合法性检查。

## 实机结果

使用当前合法游戏安装和正常 Plugin 采集器。续档从主菜单原生「继续冒险」进入 Level_1 森蕈；切关测试另开受保护的离线 Level_0，从海岸通过原生 Campfire.DebugLight / Light_Rpc / GoToSegment 完成实际地图根开关，分别录制约三十秒，再打开同一录像回跳。

|---|---:|---:|---:|---|
| 0.8.23 原生续档对照 | 60.004 秒 | 3488 / 3488 | 6.49 MB | 完整封存，无采集异常 |
| 0.8.24 原生续档 | 60.071 秒 | 3501 / 3501 | 5.88 MB | 完整封存，无采集异常 |

三份录像未写入帧均为 0，超过 500 ms 的采样间隔均为 0。这些是短时验收样本；天气、活动、采样时机不完全相同，不能用上述文件大小推导优化百分比。测试的每秒反射诊断及 JSON 写入有额外开销，不是 CPU / FPS 对照基准。

六次跳转均恢复播放，MissingItems / MissingJoints 均为 0。每次恢复后播放推进约 0.87–1.06 秒。检测设置了至少 0.3 秒的观察等待，因此约 0.31 秒的 SettledSeconds 不是纯跳转耗时。此次目标约为 5–43 秒，未替代四十分钟录像的超远跳验证。旧海岸快照在后续采集后指纹不变。

## 实机发现的剩余限制

- 初始普通准入每场景批次最多 4 个，密集森蕈续档出现明显冷启动窗口：0.8.23 对照中箱子约 4.27 秒、生物约 19.77 秒、物品约 24.97 秒补齐，队列约 27.03 秒清空。首帧只有 1 个箱子，尚无物品和生物初态；0.8.24 复测物品约 24.90 秒补齐、队列约 26.97 秒清空。真实事件有优先路径，但录像开头的静态 checkpoint 仍可能逐渐补入；此问题尚未在本次修改中解决。
- 已知关卡根未见未来关泄漏；对照的 706 个实际 Item（0.8.24 为 700 个）全部属于无地图父级的 independent/global 分支，不能据此证明网络生成物已经全部按关卡隔离。原生生成器返回的 PhotonView 引用可精确溯源，是后续补足方向。ItemSpawnerEnhanced 的 157 条 UI 预热只创建卡片，不产生 Item，未据此误删对象。
- 雨林回放诊断仍有 incompleteEffects=4；缺失物品与骨骼为 0 不等同全部特效视觉完备，需按具体特效继续核验。
