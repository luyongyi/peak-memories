# 0.7.0 环境与动态对象

此版本对照本机 PEAK build 25667990 的实际程序集与 `data.unity3d`。缓存的旧反编译源码不能代替当前绑定；风区、熔岩、蜘蛛、僵尸、放置物及孢子触发资源按当前安装版本核对。

## 环境

`WorldFrame.Environment` 是可空的已知状态。每个录制样本观察 `WindChillZone` 的真实方向、强度、开启、倒计时、持续时间及已持续时间，`StormVisual` 的类型与强度，`DayNightManager` 的雨雪混合与实际全局参数。只在相同事件内部插值，不提前旋转下一阵风的方向。森蕈的 `RootsWind` 引用同一原生风区。

停风后原生遮罩继续按已记录 factor 渐退；粒子依原生强度阈值停止发射并保留活粒子，按录像时钟消退。暂停不推进；离开风区或环境未知时清空。回拖由真实风区曲线和记录的启停倒计时重建，避免 `ActiveFor` 在停风后归零导致尾迹立刻消失。

实际熔岩运动来自 `LavaRising` 和 `MovingLava`，`LavaTides` 没有实现。记录对象位置、开始／结束与已进行时间，并随录像跳转驱动原生表面；`LavaPost` 的缓存高度与缩放时间动画不能作为录像时钟，回放直接同步实际表面高度的表现参数。风、熔岩、雾的原生自动更新在回放期间暂停，结束后恢复。

截图的雪山紫墙来自错误雾球原点：原版切段会调用 `OrbFogHandler.SetFogOrigin`，旧回放只写 `currentSegment`，保留了新场景海滩的雾球。新版记录 `FogSphere` 中心、尺寸、padding、启用、reveal 和原生 origin／移动状态，直接重建材质与全局表现参数，避免 hidden scout 的实时位置驱动雾。原点对应关系使用原 `OrbFogHandler.origins` 数组。旧录像只纠正已知关卡的静态原点，不重演未录下的推进；未知环境也不会沿用前一次跳转的天气或熔岩状态。

## 生物、束缚与孢子陷阱

`ReplayFrame.Creatures` 记录蜘蛛、蘑菇僵尸和孢子陷阱的身份、存在、实际状态和最终骨骼／网格姿态。活动生物 30 Hz、静止陷阱 5 Hz，根显隐每个样本检查；蜘蛛丝另记原生线段。模型只包含允许的视觉组件，不实例化 AI prefab。原版生物回调在实际回放时隔离。

人物 `WebWrap` 保存每层已观察原生束缚网格的 `_Clip`、本地旋转和 VFX 父节点缩放。只调整经过核验的束缚节点，不启动随机 tween，也不改变真实角色数据。旧快照为空时隐藏模板上残留的蛛网。

`Forest_SporeFungus` 与 `Jungle_SporeMushroom` 的 `TriggerEvent.onlyOnce` 调用 `SpawnGameObject.Go` 生成原生 `VFX_SporeExplo`，随后对自身 `SetActive(false)`。新版记录该真实生命周期，补齐原生孢子粒子的发现、生成旁观及资源预载。回拖先重建陷阱的已知显隐，再按原特效轨道模拟，不运行触发器、伤害或爆炸玩法。

## 物品与放置对象

原 `Item` 的手持、掉落、背包状态和一般子网格姿态保留。独立放置资源补充普通／脆弱岩钉、脆弱岩钉手持变体、插旗、便携炉、魔豆藤蔓、云菇和反重力发射球；通过原生生成／组件事件建立有界目录，记录实际视觉节点。反重力球模型由放置轨道独占，特效只保留其粒子，旧 Kind2 球体回放继续兼容；云菇的网格与粒子也由各自轨道呈现。弹跳菇、平台菇、大炮沿用原先轨道。资源路径严格匹配本机白名单，不按录像任意加载对象。物品资产中指向 Item 的掉落、指南书页、香蕉皮和复制物走原有轨道；预览模型和开发测试构造物排除。

原视觉副本遗漏了 renderer 的 layer、rendering layer、光照／反射探针和 anchor 等属性，又会根据 prefab `_Tint` 与烹饪颜色覆盖运行时材料。新版保持原生渲染配置并记录网格与材质身份、队列，以及实际 shader 类型允许的颜色、数值、向量和纹理参数；正确区分全 renderer 与单材质 MPB 的优先级。纹理、材质和网格仅从本机已加载原生资源匹配。新外观已包含烹饪结果，避免重复乘色。旧录像的 `ItemFrame.Color` 是物品 data 中的颜色，并不等于黄脆梅变体的实际材质，不能拿它猜测丢失的色相。

名字保留原 `IsLookedAt.playerNamePos` 在纯视觉层级中的锚点，并以当前可见帽子的 bounds 顶部限制最低高度；文字底部锚定，留屏幕间距。

`ItemFrame.Lights` 与 `SpawnedReplayFrame.Lights` 保留原生灯的颜色、强度、范围、锥角、阴影、遮罩、cookie、色温和开关。已知空数组熄灭副本灯，未知 null 恢复原生模板灯；原场景灯通过共享租约暂停并在退出时恢复，防止双重照明。当前 178 个 Item prefab 中，普通灯笼、精灵灯笼和火把拥有直接 Light 组件；本次补充的 8 类放置资源没有 Light，便携炉通过粒子及自发光材质呈现。快照结构也支持已观察到的放置物灯。

## 数据、预算与验证

Schema 12 编解码显式保存已知／未知环境、蛛网、外观、灯光和生物轨道。Schema 10／11 的解码门限跳过新增字段，保持未知，拒绝把新数据写入旧 schema 后静默丢弃。轨道删除／重新出现、独立页完整基线、精彩片段与整局时间原点转换和有界内存计量均包含新增数据。F9 记录生物呈现／缺失数、环境已知状态、风区和熔岩对象数。

验证包括当前格式往返与未知间隔、旧格式基线、gust／tide 离散边界、完整录像页面反向读取、陷阱消失／回拖、岩钉白名单、材质变体／uint mask、束缚参数及内存释放。实际当前程序集的 37 项环境字段和方法纯元数据检查全部通过，未执行 Unity 方法，证据在 `../../local/checks/environment-bindings/result.json`。编译和合同检查不能验证 Unity 的真实画面；风雪粒子的外观、黄脆梅和反重力绳索颜色、帽子上方文字间距及不同场景的表现仍需进入游戏验收。风暴粒子采用原生资源并按记录时钟重建，未录逐粒子位置或随机种子，跳转预热上限 8 秒。

Release 解决方案编译 0 警告／0 错误，547 项 ReplayContract、26 项 ReplayViewContract、11 项 NativeLoadingContract 与 30 项 NativeAppearanceContract，共 614 项通过。灯光检查包含已知／未知切换、熄灭与倒退读取、32 灯上限、cookie 二维尺寸、数值验证、版本门限和内存计量。
