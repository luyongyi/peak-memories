## 对照方法

基线为 0.8.33，已经包含最多 4 路后台分页解码和通常首遍生成轨迹；候选为 0.8.35，包含 0.8.34 的轨迹选择性解析及本轮非法 JSON 边界修复。因此对照主要反映选择性解析的收益，并非把多线程的全部收益重复归入本轮。

用 [TrajectoryBenchmark](../tools/TrajectoryBenchmark/README.md) 在独立 .NET 8.0.14 进程中加载实际 Mod DLL，读取同一份已封存的真实 `.peakrun`，调用生产 `ReplayTrajectoryExporter.Export`。机器为 Windows，8 个逻辑处理器。计时包含 Export 内部校验、分页、轨迹生成、压缩及写盘；导出内容摘要和结果统计在计时后进行。每次输出到新的私人目录，不修改源录像。

工具在计时前读取一次录像元数据；系统文件缓存未清空，不属于冷启动测试。基线和候选使用相同的工具与运行时。这些结果不是 Unity Mono 性能、游戏主线程卡顿时长、游戏 FPS 或公网上传时间。

## 真实录像结果

| 输入 | Schema／页数 | 旧版 → 新版 | 倍率 | 导出一致性 |
| --- | --- | --- | --- | --- |
| 22.15 分钟，72.05 MiB，1 名玩家 | 26／1,343 页 | **16.003 → 1.852 秒**，各三轮中位数 | **8.64 倍** | 11,925 点、18 个事件，六次完整 JSON 摘要均相同 |
| 43.06 分钟，1,479.44 MiB，2 名玩家 | 15／2,609 页 | **92.807 → 29.868 秒**，单组对照 | **3.11 倍** | 46,350 点、10 个事件，完整 JSON 摘要相同 |

第一份录像的运行顺序为旧、新、新、旧、旧、新。旧版三次为 16.003／15.865／16.330 秒，新版三次为 1.852／1.877／1.851 秒。第二份大录像仅一组旧、新对照，不能当作多轮中位数，也不能据此估计所有旧录像的固定倍率。

| 输入 | 旧版累计分配 | 新版累计分配 | 减少 |
| --- | --- | --- | --- |
| 22.15 分钟录像，各三轮中位数 | 7,706,491,648 字节 | 976,199,088 字节 | 87.33% |
| 43.06 分钟旧录像，单组对照 | 93,926,390,904 字节 | 67,013,397,224 字节 | 28.65% |

累计分配是整个导出期间分配过的总量，经过多次回收，**不是同时占用的内存或常驻内存**。大录像的进程峰值工作集从约 553.15 MiB 变为 499.75 MiB，该指标包括启动，未单独归因于解码。旧录像中主页面仍混存大量数据；跳过骨骼／生物对象解码并不免除页面解压、文本扫描及 CRC 校验。这也是大录像仍需要较长时间、仍产生较多临时分配的原因；本轮没有修改存储格式。

## 测试发现与修复

选择性读取的 JSON 回退路径原先可能接受跳过字段中的 `[1,,2]`、`undefined` 和 `new Date(...)`，因为底层读取器支持 JavaScript 扩展。0.8.35 显式拒绝 `Undefined` 及构造器 token，包含嵌套值；继续跳过无关轨道的对象解码和语义校验。

版本隔离测试工具同步适配 `CreatePageLoader` 新增的可选参数；只为可选参数采用默认值，未知必需参数仍报错。生产普通回放读取没有改为轨迹模式。

| 检查 | 结果 |
| --- | --- |
| TrajectoryContract | **49/49**，含新增 14 项选择性解析检查 |
| ReplayContract | **1,271/1,271**，覆盖常规解码、独立分页、共享资源及旧版兼容 |
| TrajectoryUploadContract | **15/15**，覆盖压缩上传、回执、重传、限流、分包及取消 |
| Mod 与基准工具 Release 编译 | 零警告、零错误 |

新增检查包含 Schema 10／13／14／26／27 与完整解码输出对照、玩家增量继承、显式空值、移除／重入／排序、共享玩家顺序、旧版死亡证据、不解码无关骨骼／共享块、转义属性和 Type 非首字段、非法保留字段及非法跳过 JSON。自动检查不模拟 Unity 渲染。本轮未重新进行雪堆／雪球画面或游戏内上传界面验收。

## Web 修改与实际接收

Web 原先每次上传及路线查询都串行读取全部索引小文件。现在在既有单个 worker 内分批并发读取，每批最多 **16** 个；保持原目录顺序，每次请求重新读取审核状态，不缓存批准、隐藏或删除结果。没有扩大完整轨迹解码、热力计算或上传接口的并发。

Windows／Node 24.18.0，5,000 条合成索引，预热后交替运行五轮：中位索引读取耗时从 **2,418.76 ms 降至 651.14 ms（3.71 倍）**，每轮完整结果及顺序严格相等。这仅测量本机索引读取阶段，不代表整个上传或生产服务器延迟。

Web 相关后端检查 **64/64**，网页静态检查及 GitHub Web CI 通过。另将第一份真实录像的新旧导出包送入本机 `127.0.0.1` 服务：

- 新包接收返回 **201**；存储内容与验证后的真实输入一致。
- 相同内容的旧包重传返回 **200，duplicate=true**，索引仍只有一份。
- 保留 1 名玩家、11,925 个点、18 个事件、6 个阶段。
- 测试使用空地图目录，正确返回 `waiting-map`；不伪造底图匹配。
- 原始包未变，测试临时存储已清理；未访问生产服务或外部地图解析服务。

Web 提交为 `eef0557380e17650bd16899dfed3b91cc364b499`，独立 PR：[Speed up trajectory index reads with bounded concurrency](https://github.com/luyongyi/peak-trail/pull/1)。本轮提交 PR，未合并或部署生产 Web。
