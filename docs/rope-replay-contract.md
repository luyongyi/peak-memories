# 绳索回放：真实形状与精简记录契约

## 状态与范围

0.4.0 已按本契约实现独立 Rope/Vine/Hook/Anchor 采集、Schema 6 归档和纯视觉回放；**实际 Unity 画面仍待验收**。0.3.2 及更旧录像不能补出当时未记录的绳索。本文的原生资源核查及设计约束继续适用，实现与边界另见 [呈现轨道](presentation-0.4.0.md)。

用户要求是：绳索有真实体积，会受到场景碰撞影响；记录当时实际形成的路径，稳定之后共享同一份形状。不能只保存两端，再凭空画线或重新运行物理解算来猜原来的样子。优先复用安装游戏的模型和材质，不逐帧保存网格顶点。

核查对象是本机 PEAK Steam build **25306743**，只读检查了运行时类型和资源元数据。本文不包含反编译源码、模型、纹理或私人录像；游戏更新后要重新核对 API 和资产身份。

## 0.3.2 的缺口（0.4.0 增加独立轨道）

- `ItemCapture.RefreshRegistry` 只登记 `Item.ALL_ITEMS`。手里的绳枪、绳盘可以是物品，但发射或放出的 `Rope` 是独立的网络实例，不等于物品本体。
- `ReplayFrame` 现有角色、物品、箱子轨道不能代表绳段轨迹。角色攀绳时的朝向也不能反推绳形。
- 通用 `VisualReplica` 支持 MeshRenderer/SkinnedMeshRenderer，不支持通用 LineRenderer；即使增加线渲染，也不会自动获得历史路径、材质参数和出生时间。
- 因此“现在能看到绳盘/绳枪”不意味着“已经录下放出的绳子”。

## 游戏实际存在的两类结构

| 类型 | 形状来源 | 形成后是否还会改变 |
| --- | --- | --- |
| `Rope` 动态竖绳、反重力绳、易断绳、直升机绳 | Rigidbody/ConfigurableJoint 组成的真实分段，碰撞影响各段姿态；所有者模拟，远端接收段位置/旋转 | 会。攀爬负重、碰撞、反重力、放绳/收绳、锚点移动或脱落均可能改变它 |
| `JungleVine` 藤索/横向索及部分桥面 | 成功选定的起点、终点、下垂量、中间控制点；生成 50 个曲线采样碰撞节点 | 普通固定藤索可共享成形结果；重建、移动或破坏属于新状态，不能沿用旧形状 |

本 build 未找到独立 `Zipline` 类型；横向滑行相关结构走 `VineShooter → JungleVine`，不能假定它与竖绳共用一个生成器。桥面和藤索还须按实际 prefab/type 区分。

### 动态 Rope

- `Rope.GetRopeSegments()` 根据所有权返回本地物理段或远端碰撞段；应读取这个真实顺序和每段世界位置、旋转，不调用 `GetSyncData()` 假定总能取得完整远端数据。后者读取的是本地 simulation 列表。
- `Rope.MaxSegments` 当前为 40。原生网络数据也传分段位置和旋转，证明不是只同步首尾端点。
- `RopeBoneVisualizer` 使用原生 SkinnedMeshRenderer、41 个骨骼、起始附着点和 `_RopeCutoff` 呈现绳子。其绘制顺序不是直接按段数组从头连到尾：还会处理首段、逆序、中间附着点和末端收缩。
- 普通、反重力、易断和直升机变体使用不同资源/参数。普通 `spacing` 为 0.75，直升机变体为 2.5；不能硬编码成一种视觉比例。
- 当前段 prefab 的 CapsuleCollider 本地 radius=0.5、height=2，段缩放为 `(0.25, 0.35, 0.25)`。根无额外缩放时，对应世界半径约 0.125、高约 0.7；必须同时考虑缩放，不能直接把 0.5 当世界宽度，更不能把碰撞包络宽度当网格直径。
- 所有者段是非 trigger 碰撞体，远端段是 trigger。视觉模型尺寸与交互/碰撞包络并非同一字段。
- `Rope.FixedUpdate` 对反重力绳持续施力，也会对玩家正在攀爬的段施加负重。`BreakableRopeAnchor` 会增加段数并最终脱锚。所以“已锚定”不等于“永远静止”。
- 原生 `RopeSyncer` 在远离玩家时不发送；可攀爬超过 60 秒后还会大幅降低同步频率。远端记录只能忠实于本机实际收到/看到的信息，不能声称记录了其他客户端不可见的真实物理更新。

### JungleVine / 横向索

- `VineShooter` 会尝试随机下垂量并检查路径，成功后发出实际的 `from / to / hang / mid`。不能在回放时再次随机挑下垂量或再次碰撞选路。
- `JungleVine.ForceBuildVine` 使用这组参数生成 50 个二次曲线节点。藤索节点使用 radius=0.25 的 CapsuleCollider；桥面分支使用按资源配置确定的 BoxCollider，不能统一画成细绳。
- 原生网格通过实际 Mesh transform、`_Hang`、`_LengthScale` 等参数变形；生成后的短暂波动由 `SpawnedVine` 的 `_JitterAmount` 表现。
- 最小固定索记录可复用“本次成功构建参数＋资源身份＋世界姿态”。窗口开始前已经存在、没有观察到构建事件的索，必须从真实 collider 节点取得起点快照，不能反向猜一个下垂值。
- `ForceBuildVine` 会删除/新建真实碰撞体；回放不应直接调用这个玩法方法。只复用对应曲线计算、资源和材质参数，或呈现记录的真实节点。

## 最小数据契约

以下是设计字段类别；0.4.0 对应实现见 `RopeReplayData.cs`，不属于 0.3.2 格式：

1. **实体定义**：录像内稳定 key、实例代次、资源/prefab 身份、类型、游戏 build，原生视觉材料及尺寸参数。网络 ViewID 可作来源信息，但不能单独充当跨生命周期永不复用的身份。
2. **起点快照**：窗口开始时存在的所有可见绳索、完整段路径和各段旋转、必要缩放、附着状态、实际锚点姿态、已放出段数、可见/材质状态。初始资源和形状必须自包含，不能依赖 120 秒窗口之前的创建事件。
3. **形状版本**：动态 Rope 保存真实分段 `position + rotation`，另保存必要的附着点/绘制参数；固定 Vine 保存已观测构建参数或真实节点。数组不可变，稳定期间整个版本共享。
4. **离散变化**：出生、挂到绳盘、锚定、脱锚、增减段、形状更新、启用/隐藏、销毁，均有录像相对时间。渲染所需的 `_RopeCutoff`、ghost/normal 切换等不能丢失。
5. **可选交互说明**：若需要标注“谁在攀哪根绳”，保存角色与绳 key/攀爬比例关联；不要凭附近距离猜关联，也不要借此重新驱动物理角色。

只用节点、旋转和资源引用，不存逐顶点动画。40 段位置/四元数按 float32 的裸数值约 **1,120 字节/形状版本**，不包括字段、索引、时间、对象开销和压缩；这个算式不是最终文件大小承诺。普通静止绳不能每秒重复写同一份数据。

## 采集与冻结策略

- **目录**：场景进入时建立一次目录，之后由经过核查的出生/销毁、附着和段数变化事件维护；不以 60 Hz 全场搜索。
- **生成/运动阶段**：在实际物理/视觉更新完成后观测真实段数据，有变化才生成新形状版本。录制频率受真实游戏帧/物理/远端网络更新频率约束，不补造不存在的 60 帧。段数变化必须立即形成新拓扑版本。
- **稳定判断**：所有段位置/旋转在明确误差界内持续稳定，且段数、附着和材质状态不变，才切换到共享模式。精度阈值需实机验证并注明；不能随意简化掉贴墙、绕石的折点。
- **稳定期**：复用最后形状，低频错峰检查兜底。攀爬者加入/退出、锚点/段数变化、收到新远端同步、脱锚或破坏立即唤醒；外部碰撞造成的实际形变也必须触发或被兜底检查发现。
- **变化恢复**：稳定后再次移动就恢复变化采集，不能永久冻结。“成形后记录一次”适用于形状确实不再变化的时间段，不适用于仍有明显受力摆动的绳子。
- **观察口径**：分段碰撞姿态与远端平滑后的视觉骨骼可能略有差异。实现必须明确以真实分段路径为权威，并正确复用原生绘制规则；如另取最终视觉骨骼校准，不能把其当作碰撞历史，也不能同时无必要地存两套完整数据。

## 回放、安全与 seek

- 从本机正确版本的游戏资源创建纯视觉副本，按照记录的路径/旋转驱动原生绳网格骨骼，保留真实厚度、附着与截断效果。不实例化携带 Rope、RopeSegment、Photon、Rigidbody、Joint、交互脚本的活 prefab。
- **记录碰撞后形成的形状，不等于回放必须再次启用碰撞。** 默认不创建/激活游戏碰撞逻辑，不重新施力、不重新碰撞、不调用附着 RPC 或原生生成器。人物按已记录轨迹回放。
- 若日后自由相机或鼠标拾取需要碰撞代理，可按记录的包络在独立回放层创建隔离代理，只供相机/拾取查询；不得与真实角色、物品、机关或绳索物理互动。这是另一个显式功能，不属于本契约默认效果。
- seek 先重建目标时刻存在的实体及其最近完整形状，再插值同拓扑的相邻变化。出生、销毁、段数变化、脱锚等边界不可跨越插值；倒放不依赖先前播放历史。
- 录像裁剪必须保留起点完整状态及资源定义，重排事件相对时间，防止保存时绳子早已形成却在回放首帧消失。
- 未知资源/超限节点/非有限坐标需明确拒绝或标注缺失，不使用任意 prefab 路径，不降级成伪造的首尾直线。
- 已有世界绳索与回放副本应避免双重显示，退出时独立恢复原渲染状态；不要为了避免重影永久销毁原场景对象。

## 下一阶段验收

独立轨道和归档兼容已实现，以下均**尚未完成 0.4.0 Unity 实机验收**：

- 绳枪落点、绳盘收放、绳绕障碍物和贴墙的真实路径；检查粗细、锚点和截断。
- 队友创建的绳与本机创建的绳，含远端同步低频/所有权变化。
- 稳定后挂人、外物碰撞、反重力、易断绳脱锚；确认新形状被记录而非一直冻结。
- 固定藤索/横向索的下垂、桥面类型和初始生成效果，不重新随机生成。
- 120 秒窗口前已存在的绳、成形中途保存、前后 seek、暂停、速度变化、生命周期边界。
- 静止一分钟应共享形状且文件只写变化；不逐帧复制完整骨骼/网格。性能需游戏内 profile，纯数据测试不能证明碰撞和渲染正确。
