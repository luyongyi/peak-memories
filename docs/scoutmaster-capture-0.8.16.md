# 0.8.16 童军长按激活采集与分区域审计

## 本次调整

童军长在游戏中是常驻对象：未出场时仍会更新骨骼，`activeInHierarchy` 不能代表正在参与游戏。采集目录保留轻量身份，待命时不生成生物帧，不读取骨骼、材质和外观；激活后恢复原有 30 Hz 生物动作采样。

激活根据原生目标、发现玩家和传送流程判断。清空目标不立即停止，以保留逃离、抓取和抛人的尾部动作；返回原生藏身点的传送完成后停止。重新出场时补完整姿态和外观，仍使用原来的独立跳转页与共享块。旧录像不重写，Schema 18、容器 4 与读取兼容不变。

原生代码依据：`ScoutmasterSpawner.SpawnScoutmaster` 在房间创建常驻对象；`Scoutmaster.Teleport` / `TeleportFarAway` 经 `Character.WarpPlayer` 移动身体；`Character.WarpCompleted` 在物理传送结束后发出。出生位置与 `Character.ScoutmasterHideySpot` 是两个待命位置。角色根节点不会跟随身体传送，因此首次状态校验读取躯干位置。

实机发现待命身体会继续受重力下落，不能仅靠当前位置与出生点/藏身点的距离判断激活。首次或重新启用时优先读取原生传送历史：主机从未传送且无触发信号时仍待命，已经完成返回藏身点的传送后，即使身体继续下落也停采。传送历史及出生锚点都不可用的晚加入客户端，保留身体位置的保守补判，以免漏掉已经出场的角色；常态采集不重复读位置。

## 纠正上次统计的关卡含义

审计录像为 `run-20261011-135057-2491298c9b4c4201b78dcca04e69893f.peakrun`，长 382.0678 秒，37,061,247 字节。上次“200 个孢子地雷”统计的是整个已加载场景的录制目录，不能解释成海岛第一关出现地雷。

这 200 个对象全部属于 `Biome_2/Tropics/Jungle_Segment`，其中毒孢子与爆炸孢子各 100 个。原生游戏初始化时关闭后续区域的父节点，但采集扫描包含禁用对象；静态陷阱用自身 `activeSelf` 保存未触发状态，所以仍进入每页基线。回放另有父区域显隐控制，这项证据说明提前录入了无用数据，并不证明第一关画面显示了雨林地雷。

录像在 359.5008 秒切换到下一段编号，但雨林根节点到 366.2345 秒才真正启用。此前 370 页含 74,000 条陷阱基线，之后 16 页含 3,200 条；全片没有孢子陷阱状态增量。按当前段编号或玩家纵坐标裁剪都不可靠，必须依据实际启用的区域根、营火和区域变体。

## 各轨道采集必要性

| 对象 | 必要数据 | 可以避免的工作 |
| --- | --- | --- |
| 玩家、正在参与游戏的生物 | 动作、状态、外观变化、出生与退场 | 童军长待命骨骼，本次处理 |
| 未来区域静态陷阱 | 首次区域启用时的状态、触发与爆炸事件 | 区域关闭期间首次重基线与后续探测 |
| 普通静止物品 | 身份、外观首次快照与拿取、移动等变化 | 已采用事件唤醒；仍需分辨实际动画与无显示作用的辅助节点 |
| 箱子与世界互动对象 | 首次可见状态、开合、消耗和显隐 | 未来区域初始重基线；激活后的消耗状态不能直接丢弃 |
| 放置物、绳索、灯光物品 | 放置、运动、成长、亮灭等真实变化 | 未启用对象的重采样 |
| 音效与粒子 | 实际播放、存活的效果及短事件历史 | 已过滤未播放对象；不能按关卡编号截断跨区声音与特效余波 |
| 世界环境 | 地图开关、天气、光照、雾和区域切换 | 部分未启用区域的冷状态可进一步延迟 |

区域优化还须保留多人分处不同区域、上一营火、携带物和投掷物跨区，以及已消耗对象的最终状态。箱子与部分世界互动回放依靠记录认领原生对象，直接删掉停用记录会使独立跳转后原生未打开箱子重新出现。因此本次实现童军长门控，区域准入的其他调整保留为后续工作，没有把所有轨道简单按当前关卡裁掉。

关卡编号也不是固定物种表：同一个进度位置可以是雨林/森蕈、雪山/沙漠、火山/雾沼等不同变体。后续应登记实际 `MapSegment.biome`、区域父节点和营火归属，区域开关变化时只唤醒其目录，避免每帧遍历每个对象的所有祖先。

## 体积与验证口径

旧录像中童军长有 273 个节点、8,700 条骨骼增量；按上次压缩成员内分摊估计约占 9.090 MB（24.53%）。这不是重新录制或重新编码后的实测节约量。新策略从采样源头避免待命内容；真实收益取决于每局出场时间。

激活生命周期回归使用真实增量编码、共享页写入和分页跳转实现，检查待命缺席、首次完整出现、消失、同一身份再次出现，以及倒序独立读取和往返跳转时的骨骼与材质状态。其他原有回归同时运行；本机验证结果随交付包保存。

解决方案按警告视为错误构建通过，0 警告、0 错误；13 组契约共 1252 项通过（比 0.8.15 增加 21 项原生事件门控、5 项编码和跳转生命周期检查）。连续 6000 次待命查询未再次查组件或读取位置；本机 AppDomain 分配计数观察为 0 字节，该计数非主线程独占，未用作跨环境硬断言。
