# 0.8.17 静态孢子陷阱事件采集与跨页去重

## 调整

200 个静态陷阱各保存一次初始状态。正常空闲不再每秒检查位置、旋转、缩放或显隐，也不在每个采集 tick 遍历这 200 个 Unity 对象；只复用已缓存的不可变状态。首次登记和实际游戏事件通过一个可合并的待处理队列采样。初始化异常只做三次有间隔的重试，异常对象不影响其他对象；有新事件时可以再次恢复。

靠近判断继续由原生碰撞触发器完成，没有另加玩家距离扫描，也不会因本地玩家较远而忽略其他玩家触发的爆炸。观察点在原生 `TriggerRoutine` 的 `UnityEvent.Invoke` 完成之后，此时原生特效已经生成，陷阱已执行 `SetActive(false)`。保存一次 armed→consumed 状态变化；重复调用被原生一次性标志拦截，不反复录制消耗状态。毒雾、爆炸粒子仍由独立特效轨道记录其真实生命周期。

区域父节点显隐由世界轨道处理，陷阱自身保存 `activeSelf`。正常进入雨林不会重新生成其位置，因此不需要重采所有陷阱。自定义局设置可能在未来区域首次激活时才使陷阱自身关闭；另外观察 `DisableBasedOnRunSettings.UpdateEnabled` 的实际显隐变化，避免取消轮询后漏记这类设置事件。没有变化则不通知采集。

原生孢子消耗只停用对象，不销毁对象；场景卸载由采集器释放目录。本次不支持其他 Mod 绕过这些原生事件任意移动/删除陷阱，也没有为开发模式中途重新生成整张地图加入全场扫描。

## 为什么原来仍占空间

审计原录像为 `run-20261011-135057-2491298c9b4c4201b78dcca04e69893f.peakrun`，长 382.0678 秒，共 22,600 帧、386 页。200 个陷阱属于后续雨林，两种模板各 100 个，全部没有发生状态变化。

原来的单个静态陷阱完整快照只有 398–431 字节，低于共享机制的 512 字节门槛。因此虽复用了内存对象，保存独立跳转页时仍重复写完整状态：200 × 386 = 77,200 条基线，未压缩合计 32,588,050 字节。

现在只对已经识别的紧凑静态陷阱取消该最小门槛。200 份初态跨页共享，页面保存短引用；消耗后的状态同样共享。继续使用既有容器 4 的完整状态块，没有引用链，也不用从录像开头重播事件才能跳转。散列、序列化、压缩继续在后台保存线程完成。共享目录满时保留原有内联回退，不丢状态。

Schema 18、容器 4、读取兼容、按需分页、1 GiB 缓存及分帧构建预算不变。旧录像不会自动缩小；本次对照只生成独立副本，原录像保持原样。

## 同源体积对照

把同一份旧录像全部解码帧分别交给修改前后的保存器，在相同 .NET 8.0.14 环境重新编码，保留全部玩家、生物、物品、声音、环境和特效数据。没有删除旧录像里待命童军长等其他冗余内容，因此本对照只衡量此次陷阱共享带来的收益。

| 对照 | 字节 | 十进制 MB |
| --- | ---: | ---: |
| 修改前保存器 | 39,779,077 | 39.779 |
| 修改后保存器 | 34,370,359 | 34.370 |
| 减少 | 5,408,718 | 5.409（13.60%） |

新副本恰好含 200 个陷阱共享块，压缩成员合计 61,871 字节。各页面仍需短引用和索引，不能把 61,871 字节解释为整条轨道包含所有页面开销后的总大小。原文件由 Unity 环境生成，大小 37,061,247 字节；不同运行环境的压缩结果不同，不能将其直接与 .NET 重编码的新副本作版本对照。

另外，200 陷阱、60 页、一次消耗的受控夹具，只存 201 份完整状态及一次页内状态变化；含索引和其余夹具数据的文件从 970,034 字节降到 303,231 字节，减少 68.7%。该比例只适用于该夹具，不能代表整局录像。

## 验证

事件目录测试覆盖 200 对象、连续 6000 次空闲 Capture、重复事件、读取期间再入事件、移除及同 ID 重用、异常隔离和限频重试。6000 次空闲调用没有静态读取，当前线程额外分配为 0 字节。共享测试检查倒序独立读取、已消耗状态、爆炸历史、不同对象实例内容去重及共享目录满时回退。

整个解决方案按警告视为错误构建：0 警告、0 错误。13 组契约共 1269 项通过。对两份完整重编码录像的 386 页作倒序独立读取，包含页间重叠共比较 22,985 帧，覆盖全部 22,600 个唯一时刻；所有序列化字段与独立特效历史均一致。

另取跨越整片的 12 个页面，修改前后读取器使用相同 .NET 8 进程中对称隔离的程序集环境，交替顺序测量三轮，共 36 对页面读取。未缓存解码中位数 79.78→81.82 ms，P95 93.30→97.53 ms，当前线程分配中位数 10.09→10.20 MB。此次共享优化主要降低录制体积和采集开销，没有证明页面解码变快；每页仍需解析 200 个小共享块。读取在后台进行，页面缓存命中时不重复承担这段解码。

三轮测量中，候选出现一次 185.996 ms 尖峰，同页其余轮次并未重复出现；原因未定位，不删除该样本。首次触达中位数为 97.20→177.09 ms，但配对中位时间比为 1.040，分布受到初始化和执行顺序影响，不能据此保证冷跳转无退化。完整原始数据保留在交付检查文件中。这些是 .NET 后台解码测量，不是 Unity 主线程耗时、游戏跳转总耗时或 FPS 对照，操作系统缓存未控制。

## 实机结果与交付

使用正常插件自己的采集器，隔离离线 `Level_0`，通过原生 `MapHandler.JumpToSegment` 进入雨林，再分别调用两种陷阱的原生触发入口。两次十秒静置、区域激活及重复触发之后，实际静态读取总数恰好为 **202：200 次初态、1 次毒孢子消耗、1 次爆炸孢子消耗**。其余 198 个对象没有产生新快照；初态与进入雨林后的真实位置、旋转、缩放一致。

新录像保存 1720/1720 帧、31 页、29.7184 秒，0 帧未写入，文件 3,418,922 字节。该短录制包含场景初始化及测试行为，不能按其大小外推整局每分钟体积。它记录了两种原生粒子，并完成五次暂停往返跳转：爆炸前两个原模型各有 4 个渲染器正常显示；消耗后对应模型隐藏；毒雾与爆炸在检查时各恢复 30 个粒子；跳回事前不出现未来粒子。检查包含固定稳定等待，不把脚本测得的检查完成时间当作用户感知跳转延迟。

首轮驱动把现场采集的绝对时间直接传给从零开始的录像时间轴，跳转越界，未计为通过。修正驱动时间基准、核验首末时间差和保存时长后，第二轮采集、回放及状态恢复均通过；生产 DLL 未因此改变。

临时测试 DLL 已移除，游戏已退出，正常录制目录与配置值恢复。进度存档和原始录像 SHA-256 与运行前一致；配置文件仅插件版本说明变化，所有配置值一致。游戏中和交付包均为 **0.8.17**，DLL SHA-256：`6ABC2D1F251150F21180AC0816157770206FA037041399F6767F980BBD60AABD`。旧 0.8.16 DLL 已备份。

离线测试离开房间、返回标题的清理阶段出现游戏原生角色/背包 UI 空引用日志；没有将此次运行报告为“全部日志零错误”。录像完整封存、事件与跳转检查、返回标题和设置恢复均独立确认成功。

本轮实机证明事件次数和这两种陷阱的回放正确，没有做新旧版本游戏 FPS 对照，也没有以几次短录像跳转保证所有大型录像冷跳转完全无退化。
