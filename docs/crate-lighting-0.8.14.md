# 0.8.14：开箱闪变与原生物品颜色

## 修复

连续播放时，旧版箱子路径在动画、外观或灯光未取得本帧工作额度时隐藏整个回放模型；下一帧恢复显示，形成闪变。现在保留已完成的显示状态，先取得动画采样额度，再恢复检查点姿态和采样动画。初次创建、跳转及无效对象仍在完整准备好前隐藏。

灯光恢复取消“先关闭所有灯，再逐个恢复”的中间状态，先恢复本次存在的灯，最后关闭已移除的灯。

旧版把原生 HDR 材质读取出的着色数值统一交给 `MaterialPropertyBlock.SetColor`，产生第二次颜色转换。直接在已有颜色条目上调用 `SetVector` 仍可能保留 Unity 的转换标记；修复先清空复用的属性块，再从受信任的原生参数和记录值重建。HDR 使用原始向量，普通颜色保留原有语义。依据为本机实际 GPU 对照，以及 [Unity 的 SetColor 文档](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityengine/materialpropertyblock/setcolor)。

游戏已有日夜方向光、环境光和 LightVolume 烘焙光照；回放继续使用它们。原生属性块中的局部光照参数在模型创建时保留，`_LocalTopDirection` 同时加入原有外观采样。录制明确指定的纹理或其他属性优先于原生基线，空纹理不会被基线属性块遮蔽。

## 数据与开销

- Schema 18 增加可省略的颜色编码字段。HDR 通过 `GetVector` 采集实际着色值，无论原生代码来自材质、属性块 `SetColor` 或 `SetVector`。
- Schema 10–17 继续读取。旧录像缺少来源信息：按本机原生代码审计，对 `Flag Checkpoint / WavingFabric / _BaseColor` 保留特殊的属性块颜色语义，其余原生 HDR 采用材质数值语义。旧录像中第三方脚本任意更换颜色写法的情况不能从缺失的信息反推；新录像消除了该歧义。
- 不提高采样频率，不添加全场景逐帧扫描，不新增灯、不重复烘焙。着色器类型/HDR 元数据按着色器缓存，原生属性块基线只在模型创建时采集。
- 保留事件休眠、外观共享、骨骼时间压缩、按需载入和独立跳转页。旧格式颜色版本校验在单次读写操作内记住已检查的不可变数组，不在每帧重复遍历相同外观；新格式直接跳过旧版本检查。
