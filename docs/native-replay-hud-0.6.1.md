# 原生回放界面（0.6.1–0.6.3）

## 0.6.3 底部抽屉

控制台默认收起，只留屏幕底部中央的奶油色胶囊拉手。拉手复用原生 `ProceduralImage` 与 `RoundModifier`，按钮、字体、配色和描边继续从游戏资源读取。上拉、点击拉手、H 或手柄 View / Select 展开；下拉、原生「收起」按钮及同一快捷键隐藏。手柄 B 先收起已展开面板，完全收起后再返回；F9 打开诊断时展开面板。

`ReplayDrawerMotion` 使用非缩放时间进行 0.25 秒平滑吸附，支持动画中反向、直接拖动和甩动；松手后选择最近端点，快速向上／向下拖动按方向吸附。指针位置换算到 Canvas 本地坐标，拖动时取消 click，停止移动超过 0.12 秒后不使用旧甩动速度。只有左键事件能驱动拖动；右键镜头观察、失焦或退出会结束拖动。

完全收起后面板停用；收起、拖动与展开动画期间禁止面板交互和射线命中，并将其选择移到拉手。拉手可独立接收鼠标和手柄操作，悬停提示只依赖实际鼠标悬停。面板隐藏不影响录像推进、HUD 数据、空格暂停和玩家切换，也不增加光标写入。控制台位于 HUD 上层，默认收起时原生左下／右下栏完整呈现。

Release 构建 0 警告／0 错误；516 项数据与抽屉运动、26 项视图和原生控件复制、11 项加载检查共 553 项通过。12 项新增检查覆盖边界、快速反向、拖动打断、端点吸附和无效输入；输入模块回调顺序及焦点迁移已按本机程序集和代码复核。未进行 Unity 实机画面与拖动验收。

## 0.6.2 体力条与光标修复

0.6.2 修复了本节实现的两处实机反馈问题。原生 BarGroup 和士气组中的 `CanvasGroup` 继承引擎 `Behaviour`，不是 `MonoBehaviour`；本机 Unity 的 `JsonUtility` 会直接拒绝它，原复制路径因此未创建体力条。现在使用 `NativeUiComponentCopy` 直接复制 alpha、交互、射线、父组忽略及 enabled 状态。其它脚本视觉组件保留 JSON 复制，未知引擎组件明确拒绝，不再将创建失败藏在画面提示中。F9 与首次创建日志包含实际栏位激活和尺寸信息。

用户新录的完整录像已只读检查全部六页：移除五份页边界重复后，3286 个唯一帧全部包含 15 状态 HUD 快照，2211 帧体力大于零，最大体力在 0.95–1 范围；校验值未变，不需要重录这份文件。显示修复不更改 Schema 11，也不改写录像。

另一个问题由原版 `CursorHandler.Update` 每帧锁定鼠标、回放 `LateUpdate` 每帧解锁造成。现在只在实际回放 Presenting 期间跳过该原生回调，保留输入和原版光标按键动画；`ReplayCursorPolicy` 只在右键和应用焦点转换时更新光标，连续操作期间不重写。锁定首帧不读取位移，失焦即释放，再聚焦时要求松开后重新按右键；退出取消焦点订阅并恢复之前的光标状态。

0.6.2 Release 构建 0 警告／0 错误；504 项数据、26 项视图与控件复制、11 项加载检查共 541 项通过。本机真实 Unity DLL 的原生组件 JSON 拒绝路径已复现，七项新控件复制契约包含原生 CanvasGroup 与普通脚本分支；九项新光标契约覆盖连续不重写、焦点、首帧与重新按键。Windows 下分页取消为异步关闭，新增 HUD 随机跳转测试清理临时文件时允许最多两秒完成后台句柄关闭。检查仍不等于 Unity 实机渲染和鼠标操作验收。

回放界面使用本机 PEAK 游戏资源。`NativeReplayHud` 读取 `GUIManager.bar`、三个随身栏、背包及临时手持栏的绑定，仅重建白名单中的 uGUI／TMP／ProceduralImage 视觉组件。原 `StaminaBar`、`BarAffliction`、`InventoryItemUI`、`InputIcon` 的 Update、音效、动画和游戏状态操作均不在副本中运行。

左下 BarGroup 使用原生左下锚点 (70, 160)，物品栏使用右下锚点 (-75, 107)；普通槽位 70×70、背包 100×100，选中时采用原版 1.2 倍尺寸。字体、图标、材质、描边和状态段顺序从实际资源取得。默认槽位颜色读取原 UI 初始化时缓存的默认色，避免继承原场景通电物品的临时染色。食物名称和颜色、燃料比例及按键图标使用原游戏接口。

控制台展开后默认只显示回放操作。展开背包显示随身、包内与临时手持栏，保留已记录的使用进度及近期物品事件；F9 展开诊断。按钮来自 `ModalButtonsField.m_buttonPrefab`，创建前验证其全部组件类型，并替换点击事件。控制台拥有独立 InputActionAsset、EventSystem 和输入模块，结束时恢复此前 EventSystem 的启用状态与选择；Space 只触发一次播放／暂停，右键观察期间 UI 停止接收鼠标点击。

## 记录与兼容

Schema 11 的可选 `ActorFrame.HudState` 保存当前／最大／额外体力、Injury、Hunger、Cold、Poison、Crab、Curse、Drowsy、Weight、Hot、Thorns、Spores、Web、Arrow、Petrify、FlyTrap，以及实际 `petrifyAmount`、无敌、是否可饥饿、无限体力和士气提示。士气只在该玩家实际被原生 HUD 观察时标记为已知。无变化时复用快照，状态数组只在状态变化时复制。

库存新增 `UiFuel`（原版 UseRemainingPercentage）与 `Cooked`，沿用原有库存采样频率。原 Fuel 字段不被误当作 UI 比例。滚动预算、差分编码、页基线、完整录像的读取计量与校验均包含 HUD 数据。

回放数值在同一参与者的相邻已知采样间插值；离散图标保持上一真实采样，跳转直接重建目标时刻。未知与已知零值区分，库存尚未同步时不呈现空背包。Schema 10 精彩片段及完整录像保持可读，完整状态条未知，UI 明确提示重新录制才能补齐。
