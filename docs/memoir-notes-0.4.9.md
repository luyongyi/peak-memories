# 0.4.9 原生便条与终局封面

## 展示与依据

- 一条原生纸张按钮对应一份录像，维持每页四条。左侧为封面，右侧为原有日期、类型、时长与场景信息；点击仍进入详情，不增加嵌套按钮。
- 精彩片段使用窗口内最后观察到的有效区域；完整录像按照首次观察顺序拼接多个斜切面板，往返不无限重复插图。
- 普通关卡从录像里的原生 Segment 和已记录的路线标签对应。终段的 Swamp/Swamp 对应城塞，Volcano/Volcano 对应熔炉；矛盾路线不借用图片。
- 原生顶峰成功撤离才产生顶峰封面；仅经过终段或 Peak 传送点不算。观察到天底后，数据摘要及 UI 两层都排除顶峰。
- 摘要不是完整性或防篡改凭据。播放前仍按现有流程校验文件、版本和场景。

## 资源与性能边界

11 张 PNG 使用明确逻辑名称内嵌 DLL，运行时不会联网或接受录像指定的图片路径。独立仓库现将原创源图维护在 `assets/home-art`，不包含玩家日志。

原图首次用于菜单时解码并缩为 256×384，只缓存小纹理，不保留 CPU 像素副本或 mip 链；退出插件时释放。失败资源缓存失败结果，页面重建不重复刷解码错误。每张约 0.375 MiB，11 张合计约 4.13 MiB GPU 像素数据，另有短暂解码／引擎开销。录制循环不触碰图片。

新录像仅额外维护常数大小的结局标记，复用现有世界分区字段；窗口／整局封面摘要在保存或写入后台生成。角色、手持物、绳索等采集策略不变。

旧精彩片段可以在录像库后台扫描关卡字段，不展开角色／物品对象；有每文件、总读取量和总时限约束。扫描未完整结束、无起始分区、文件变化或超预算时保留中性纸张。旧完整录像缺少摘要时不解压整局，也不根据“地图含有某关”推测走过。

## 实机验收清单

1. 主菜单打开回忆录，观察精彩片段封面、日期、时长，键鼠与手柄选择整张便条。
2. 新录制完整跨关一局，查看斜切面板顺序，确保不是每日可用路线的全图列表。
3. 仅路过顶峰但前往天底：应出现天底、不出现顶峰；从顶峰正常撤离：应出现顶峰、不出现天底。
4. 120 秒片段跨普通关卡、回走、在天底保存，检查窗口与整局不会混为一谈。
5. 翻页、返回、重新打开、删除确认与取消，确认封面不阻挡点击、不改变默认安全焦点。
6. 缺少摘要的旧完整录像应可正常播放，但保持无猜测封面；超预算旧片段读取不冻结主菜单。

编译和数据／布局测试不能证明 Unity 内视觉、音频或帧率表现；仍需上述实机检查。
