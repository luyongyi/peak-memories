# 0.3.2：保留事实轨迹，减少重复状态

## 本轮范围

修复原生动画权重采集，实施无损文件字段差分，完成原生 AnimatorController / seek 的静态兼容性核查。没有引入全身布娃娃、完整原生 Controller 播放、绳索轨道或游戏物理重模拟。

设计原则是：记录真实事件、位置与影响理解的形状；模型、材质和可确定的视觉动作从游戏资源重建。普通物品的装饰性翻滚后续可以按固定时间规则生成，但绳索碰撞成形路径不能按两个端点自由猜测。

## 已确认的问题

- 0.3.1 采集将 `AnimatorClipInfo.weight` 再乘过渡进度，重复计算原生混合。实际片段的起跳过渡中，约 0.7493 / 0.2507 的权重变成平方值，回放归一后约为 0.899 / 0.101。0.3.2 直接保存原生权重；不对旧片段尝试平方根修复，因为旧格式没有足够的状态分组信息。
- 一段本地 58.8 秒、3459 帧样本中，背包只有 17 次变化却每帧写入；装扮没有变化。同一物品后续更新的 96.18% 中，子节点完全相同，却随根姿态再次序列化。这些是该样本的统计，不代表每局都相同。
- 原压缩文件约 1.33 MiB，解压文本约 23.21 MiB。已有 gzip，因此不能把原始重复字节当成最终磁盘节省量，也不能把文件减小当成帧率提升。

## Schema 5

保存端在后台写首帧完整状态、后续字段变化。未出现字段代表继承；明确的空数组代表清空；实体删除与重新出现需独立处理。物品根姿态变化不再强制重写不变的子节点、资源名称和状态字段。

读取端按顺序还原完整帧，保留旧 `ReplayClip.At` 查找语义；回放不需要从时间零重新执行玩法或事件。未变的数组和状态对象尽可能复用，不原地修改已解码的历史帧。初始快照保证 120 秒窗口即使从开箱、持物等过程的中途开始，也有必要的起点状态。

原始参与者身份仍保留；没有随机匿名化。新文件只在 F6 明确保存后生成，不自动上传，不自动迁移/覆盖旧录像。Schema 2/3/4 的读取与旧对象增量逻辑保留。

## 仍需实机检查

1. 新录一段走路 → 蓄力前跳 → 落地，比较姿态过渡。旧录像只能验证兼容性，不能验证新采集权重。
2. 开箱、拾取、切换背包、使用、丢出；向前和向后拖动，检查物品出现/消失、槽位清空、终态和中间位置。
3. 不按 F6 时不写录像；保存时继续采集；F9 分别检查采集与回放耗时。
4. 新旧录像切换、回主菜单、正常新局，确认原足迹 Mod 和其他设置恢复。

完整原生 Controller、六点握持采样替代和绳索捕获是后续独立验证项。本轮不声称已完成这些功能，也不以纯数据测试替代 Unity 画面验收。
