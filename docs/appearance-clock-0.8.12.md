# 0.8.12 外观共享、骨骼时钟与读取验证

本版只生成候选 DLL，未安装回 PEAK，也未启动游戏。原录像保持原文件大小和最后写入时间，移出的旧 DLL 保持原校验值。

## 实现

- 活动物体的外观、灯光和节点基线分别共享。节点变化使用相对于完整基线的绝对值，不沿历史页面追溯；材质、显隐、灯光和拓扑变化照常保存。
- 对象活动后，相同完整状态第二次出现在页首时，提升为完整共享块，之后继续去重。绳索保留完整状态共享，避免拉动后静置仍逐页重写全部绳索点。共享完整对象不再引用其他共享块，引用深度固定为一层。
- 同一时刻只有采样时间变化的骨骼节点成组编码。仅在二进制长度更短时启用，保留真实采样时刻、原有姿态精度和插值规则，不降低采样频率，也不删除静止时的真实观察时刻。
- 共享块在一次顺序读取中收集 gzip 尾部，取消每块提前读取尾部再返回的额外定位。解压长度、压缩边界、CRC、ISIZE、SHA256 和取消检查全部保留。
- 新工作均在后台存储或读取路径。本轮采集、事件监听、动作时间轴、特效采集及跳转调度源码未改；保留约一秒独立页面、按需读取、1 GiB／64 页缓存和独立特效历史。

节点模板限 8 MiB／128 个实例，等待提升最多保留 32,768 个哈希，共享目录最多 32,768 块。超限回退保存完整数据，不丢帧、不延长引用链；没有新增常驻的解码对象缓存。

新录像为 Schema 17、完整录像容器 v4，继续读取 Schema 10–16 和完整录像 v1–v3。

## 真实录像体积

对照使用本机原 43 分钟、1,551,309,244 字节录像，只读原文件，并向新的检查目录写入抽样文件。旧版为本轮开始前保存的 0.8.11 源码，使用相同测试运行时重新编码；新版使用相同输入帧。以下 MB 均为 1,000,000 字节。

主要样本覆盖 0、300、900、1800 秒附近各约 30 秒，包含完整相交页：**124 页、7004 帧、122.849 秒有效内容**。时长计算排除未采样的长空档。

| 项目 | 0.8.11 | 0.8.12 |
|---|---:|---:|
| 总字节 | 19,246,598 | 17,553,771 |
| 总体积 | 19.247 MB | 17.554 MB |
| 按有效覆盖时长折算 | 9.400 MB／分钟 | 8.573 MB／分钟 |
| 主页面区 | 15,019,380 B | 15,000,666 B |
| 共享状态区 | 3,515,455 B | 1,864,819 B |
| 独立特效历史区 | 513,562 B | 513,577 B |
| 索引 | 193,901 B | 170,409 B |

总体减少 **1,692,827 字节，约 8.80%**。压缩后的特效历史区字节略有变化，但解码后的全部特效字段一致；页头版本及压缩流输出可以改变压缩字节数。

另保留此前的短样本口径：18 页、977 帧、17.180 秒有效内容，从 4,319,278 降至 4,125,766 字节，减少 **4.48%**。短样本承担更多首次目录、外观和索引成本，因此不使用其约 14.4 MB／分钟作为主要估计。

这些是同内容的抽样重写结果，包含初始化成本，不能直接推算整场新录制大小。离线重写没有执行 0.8.11 的事件驱动采集，不测量事件休眠对新录制的额外收益。

## 动作和特效完整性

主要样本全部页面反向打开，并追加 24 次固定随机读取，核对所有帧字段和独立特效历史。反向读取检查 1,718,784 次骨骼节点采样时刻，随机读取另检查 331,776 次，时刻按 double 位模式比较，全部一致。

预期人物姿态由冻结的 0.8.11 骨骼编码器生成，沿用原有量化；这证明新编码没有进一步改变原编码结果，不意味着旧录像人物姿态重新量化是位级无损。对象节点字段和实际骨骼采样时钟另做严格核验。

最终读取器的跨版本对照再次验证 698 帧全部序列化字段及 163,712 次骨骼时钟。合约检查覆盖外观变化、灯光、拓扑改变、物品消失和重入、静置状态提升、绳索状态、效果历史及反向跳转。

## 读取性能与限制

最终对照在同一 .NET 8 进程中运行真正的旧版与新版读取器，各自位于独立、相同策略、不可回收的加载上下文中，均不使用默认上下文。两边各预热所选 12 页一次，然后固定顺序交替读取三轮，共 36 对；原始首次触达记录也保留。计时仅包含页面 Load，不包含反射设置、内容核验、场景构建或特效预滚；不强制回收、不清空系统缓存、不删除慢样本。

| 指标 | 0.8.11 读取器／文件 | 0.8.12 读取器／文件 |
|---|---:|---:|
| 每页中位耗时 | 139.896 ms | 135.789 ms |
| 每页 P95 | 214.647 ms | 166.920 ms |
| 每页最大耗时 | 217.164 ms | 178.321 ms |
| 每页中位线程分配 | 11,160,528 B | 11,140,064 B |
| 36 次读取期间累计 GC 暂停 | 92.001 ms | 152.409 ms |

整体中位数略低，但逐对耗时比值的中位数为 **1.0054**，第三轮新版本中位数比旧版高约 3.05%。因此结论是**离线读取总体接近旧版，不能宣称稳定加速或完全没有慢页**。GC 暂停是进程级诊断量，也不能据此宣称全局 GC 改善。共享块额外往返读取已消除，快速跳转仍只依赖目标页及直接共享块，不需要从前面逐页重放。

骨骼解码另做 36 个真实页面、三轮交错、每次重复 20 次的隔离验证：旧 v1 中位 3.048 ms／页、新 v2 中位 3.040 ms／页；P95 为 3.272／3.344 ms，未出现稳定显著退步。该部分不能替代整页或游戏帧率测试。

离线重写总耗时（包含原录像解码）为 32.72／39.91 秒，未隔离编码器耗时且不是同进程配对结果；不能把文件变小解释为录制 CPU 同比下降。新增处理留在后台，主线程采集路径未增加工作，但线程竞争和全局 GC 对 Unity 的实际影响仍需实机测量。

开发阶段的早期跨版本工具使用了不对称加载上下文，其约 23.7% 的表面改善不作为结论；最终数据以 `paired-versioned-symmetric/paired-versioned-decode.json` 为准。

## 构建与交付

构建零警告、零错误，**1142 项合约检查通过**：ReplayContract 962，其余九个项目合计 180。新增的读取测试覆盖 1–7 字节短读、非零目标偏移、尾部缓冲复用、相邻压缩块边界、截断、CRC／ISIZE 损坏和取消。

生产源码审计覆盖 128 个文件，本轮 12 个文件有变化，变化集中于格式、后台编解码、版本号和注释。采集、骨骼时间轴、特效及播放调度保持本轮开始时的内容。

候选包位于 `BepInExTemplate-main/output/PeakReplayLab-0.8.12/`，包含 DLL、此报告、校验清单和检查记录。证据原件位于 `local/checks/appearance-clock-20261011/`：

遵照要求未安装到游戏，因此没有新的 Unity 主线程耗时、帧率、画面或全地图玩法验收结论。本轮确保抽样中已经采到的动作和特效不因新存储丢失，不会补造旧录像未采集的数据，也不扩大此前声明的游戏行为覆盖范围。
