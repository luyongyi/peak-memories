# 0.4.2：滚动窗口完整性、放置炮台、绑头气球与物品减负

## 范围与约定

按用户要求，人物录制本体不变：60 Hz 目标、基础 clip 时间/权重、六个持物手臂定位点、朝向与库存读取均保留。VisualActor 只增加只读头部挂点供气球显示。未知背包归属、手持/投出物的轨迹不降采样。已经通过用户测试的绳索形状、碰撞节点、骨骼及采样阈值也不变。

本次是物品/场景呈现改进，不是完整确定性游戏仿真。未启动或控制游戏；测试不能证明 Unity 画面、GPU 或整机 FPS 已通过。

## 120 秒窗口为何不会丢掉出生更早的物体

保存的并非只有最近 120 秒的事件队列。每个录制帧引用该时刻仍存在实体的完整不可变状态，静态状态共享同一对象。旧帧淘汰时，仍由新帧引用的状态不会释放；保存时输出第一帧完整基线，其后才做差分和明确删除。

例如 0 秒放炮，300 秒按 F6：保存起点是约 180 秒，炮的完整资源、位置、朝向及必要状态仍在第一帧，不需要重新执行 0 秒的放置动作。动画和气球 Started 时间同步减去窗口起点，允许负数，避免把早已存在的物体误当作刚出生。

新轨道开始采集时会进行一次已有实体扫描，随后使用被动原生生命周期通知；不是每秒全场搜索。暂时采样失败保留上一份有效状态，不伪造销毁；真实销毁后移除。未收到且从未观察到的实体、超过明确上限的对象，仍不可能无依据重建。

## 呈现补齐

### 放置大炮

原生手持 Item 放置后生成非 Item 的 ScoutCannon，旧物品轨道只记录了使用动作。现加入 `scoutcannon_placed` 原生模型：固定根姿态、Cannon 子节点安装角度、CannonLight/CannonFire 原生片段的时间锚。

静态根/炮管采用事件唤醒与约 2 Hz 错峰兜底；点火短窗口约 20 Hz 检查单个 Animator，未变化时共享动画锚，不逐帧遍历整棵层级。回放只克隆允许的渲染组件与受控动画图，不调用点火 RPC、随机生成、施力或真实 FireTargets。暂停、倒拖、窗口前已开始的动画均按录像时钟恢复。

### 绑头气球

普通气球与气球束生成的是独立 TiedBalloon，而非手持道具本身。逐实例保存所有者、原生颜色索引、头部偏移、绑定时刻和活动状态；支持多实例及气球束三个不同颜色。初始化等待原生异步绑定真正完成，避免错误归属。

回放使用本机 tiedballoon 网格、character 中六色材质与原生 LineRenderer 设置，绑在回放头部；摆动由实例身份及录像时间确定，反复 seek 不依赖物理积累。每渲染帧最多创建四个视觉对象，暂停后也继续补齐；新的 seek 替换旧请求，退出清空请求。真实气球爆裂的粒子/音效出生入口本次尚未补齐，不能宣称该细节已完成。

## 采集减负与格式

- 仅在原生装备背包、真实 GUID/物品 ID/槽号、已知库存及穿戴状态一致时复用物品固定姿态。不再因穿戴者走跳读取、保存包内物品的重复世界运动。每帧保留轻量存活/归属边界检查，实际事件立即唤醒；动态子节点和状态约 0.45–0.626 秒错峰检查。
- 脱包、取出、转交、销毁、库存变化会及时退出固定状态。地上容器及未知身份物品仍使用原策略。策略测试中稳态 10 秒约 22 次读取，不是实机 FPS 数据。
- 绳索变化点构造不再先创建三组默认数组再覆盖为观测数组，减少临时分配，不改变数值。
- Schema 8 对 Points/Bones 使用节点索引与字段掩码无损差分；拓扑变化写完整数组。旧 Schema 2–7 仍可读。差分只在保存/读取工作线程执行，不在 60 Hz 采集路径压缩 JSON。
- 不把已锚定反重力绳强制冻结。它的物理绳段仍可能真实运动，不能用“固定锚点”推断整个形状不变。

## 验证结果

- Release 全量重建 `-t:Rebuild -warnaserror`：0 警告、0 错误。
- 286 项数据/策略测试、19 项视图状态契约测试通过；后者用内存替身，不模拟 Unity 画面。
- 回归包含连续 300 秒滚动后保存 120 秒：窗口前已有炮台、气球、绳索与掉落首帧仍在；出生事件已不在窗口；正确时刻移除；倒拖恢复；负时间动画/气球相位保留；内存预算淘汰同样保留基线；Schema 8 gzip 文件完整往返。
- 新格式拒绝缺失基线、坏索引/重复点、错误掩码/长度/拓扑，以及把炮/气球无声降级保存成旧格式。历史 Schema 7 蘑菇缺少新 Animation 字段时兼容默认 null。
- 对本机约 94.418 秒、5543 帧 Schema 7 片段只读对照重编码，全部人物、物品、绳索节点等字段一致，原文件未改写。相同 .NET 8 序列化与压缩设置下：Schema 7 为 24,856,605 B，Schema 8 为 23,783,881 B（约 -4.3%）；未压缩 97,942,665 → 68,267,723 B（约 -30.3%）。这是同条件重编码比较，不是与 Unity 原始文件直接比较，也不是采集 FPS 测量。
- 一次测试的后台保存 2025 → 1638 ms，Schema 8 读取 1994 ms；运行环境、缓存和 JIT 会影响结果，不承诺固定加速比例。

## 游戏内验收

1. 新录一段放炮、调整角度并点火；使用普通气球及气球束，回放核对头部连接、颜色与数量。
2. 放炮后等待超过 120 秒再 F6，回放第一帧就应有炮；气球原生寿命通常不足 120 秒，其“窗口前仍存在”的裁剪场景由契约测试覆盖，不通过延长原生寿命伪造实机测试。
3. 背包放物品后走跳，随后取出、转交、把背包拿在手里，检查无错误固定或消失。
4. 暂停并向前/后拖到生成、点火、消失两侧；确认状态不残留、不重复生成或施加玩法效果。
5. F9 分别查看采集与回放 CPU/分配指标。若仍卡顿，依据分模块数据定位，不将文件减少比例当作帧率改善。

旧录像缺失的炮台或气球无法补回，需要新片段。日志、录像、游戏资产与反编译材料均未发布。
