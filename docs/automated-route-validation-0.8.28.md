# 0.8.27／0.8.28 原生路线自动验证

日期：2026-10-13。测量对象为游戏内安装的 `PeakReplayLab 0.8.27.0`，MVID 为 `d3ebeea4-b0a8-42f7-a4fd-48e9bab29c14`。本报告的成功结果来自 `route-growth-level0-0827a`，不把较早的烟测或尚未完成的变体路线混入统计。

自动传送、篝火推进和定点停留可以验证实际发生的采集边界，也能区分首次建档、静置、事件活动和切关后的开销。它们不能替代所有生物攻击、所有道具用法及多人网络场景。当前离线验证结果为 `Passed=true`，完整覆盖标记仍为 `CoverageComplete=false`。

## 路线与原生操作

测试使用游戏实际烘焙的 `Level_0`，依次经过海岸（Shore）、雨林（Tropics）、荒漠（Mesa）、火山（Volcano/Caldera）、熔炉（TheKiln）。熔炉的原生 Biome 仍为 Volcano，因此统计同时保留关卡槽序号，避免把最后两段合并。

每关先等待地图和角色初始化，传送至经地面检测的安全篝火附近，等待准入稳定，再执行以下阶段：

1. `BaselineIdle`：海岸设定停留 150 秒，其他关设定 45 秒。
2. 在当前实际活动地图中发现普通行李箱，用原生 `Interact`、等待原生交互时长、调用 `Interact_CastFinished` 完成开箱。
3. `EventObservation`：观察约 18 秒；当前地图确有相应陷阱时，触发游戏自己的事件，并独立观察实际原生特效出生。
4. 传送离开事件地点，`FarIdle` 停留约 45 秒，观察是否收敛至静置状态。
5. 用普通篝火交互点火，等待游戏自身完成下一关启用、旧关主体关闭，再开始下一关。

传送使用游戏 `WarpPlayerRPC`，篝火使用普通交互路径；不通过直接设置地图根活动状态或改变 AI 状态伪造结果。普通路线停止于熔炉，尚未覆盖 Peak、Void/Nadir 等终局流程。新一版驱动已将最后一个 `FarIdle` 延长至至少 120 秒，下面这次成功结果使用的是原来的约 45 秒窗口。

测试在独立离线完整录像会话中运行。启动器备份并校验现有快速存档与 BepInEx 配置，伴随探针阻止本次测试覆盖它们及提交成就。本次结束后回到 Title，`RestorationConfirmed`、`QuicksaveUnchanged`、`ConfigurationsUnchanged` 均为 true。私人备份、配置、原始游戏日志及游戏资产不属于可分发报告。

## 成功路线的体积与主线程开销

完整录像持续 **738.834 秒（12.31 分钟）**，实际文件为 **31,147,490 字节（29.70 MiB）**，整体平均 **2.41 MiB/min**。43,802 个接受帧全部写入 747 页，未写帧为 0，封盘状态为 completed。录像帧间隔大于 100 ms 的记录有 55 次，大于 500 ms 为 0，最大间隔约 0.167 秒；这些是采样时间间隔，不能当作渲染帧卡顿次数。

|---|---:|---:|---:|---:|---:|
| 0 / 海岸 Shore | 149.5 | 1.756 | 0.395 | 98.155 | 255.929 |
| 1 / 雨林 Tropics | 43.6 | 2.116 | 0.373 | 108.464 | 255.963 |
| 2 / 荒漠 Mesa | 44.8 | 2.864 | 1.106 | 3.827 | 255.602 |

| 4 / 熔炉 TheKiln（Biome=Volcano） | 43.6 | 1.664 | 0.265 | 1.993 | 255.996 |

`SampledCapture` 计量 `RollingCapture.Tick` 中实际接受录像帧的调用；它包含该次采集及主线程提交的耗时，不是单个场景对象的采集时间。未到采样时刻的空调用不计入这一平均值。玩家和场景采用不同采样时钟，不能据此把场景采集说成 60 Hz，也不能把平均值直接解释为整游戏 FPS 改善。Harmony 计时仍包含少量探针开销。

低平均值没有掩盖长尾：海岸、雨林基线仍出现约 98–108 ms 的单次峰值，海岸和熔炉的 `FarIdle` 也有约 110–113 ms 峰值。本轮结果不能宣称短卡顿全部消失。诊断快照、原生观察和 JSON 序列化调度也有独立 `Probe` 计量；1 Hz 快照在主线程取读数，序列化在后台执行，不能把测试进程的全部卡顿归因于录像采集。

离开事件地点后的 `FarIdle` 增长依次为 1.765、2.154、2.971、2.433、1.645 MiB/min，与各关基线接近。荒漠较高的持续量包含仍在活动的蚁狮、水豚和风滚草；玩家站着不动不代表全关物体均静止。整轮录像观察到了 2 个蚁狮、4 个水豚和 7 个不同风滚草身份；单个时刻的活动目录数可能更少。

这是单玩家、以停留为主的受控路线。多人、持续攀爬、道具使用和不同地图生成内容会改变体积，不将 2.41 MiB/min 当成所有实际游玩的固定预算，也不据此外推此前 40 分钟录像的精确大小。

## 缓存、后台队列与静置读取

**256 MiB 是本次录制的滚动录像缓存预算；1 GiB 是回放按需解码的页面缓存预算。** 两者用途不同，不能把前者的读数理解为回放缓存被降回 256 MiB。

海岸最初建立缓存时从约 42 MiB 上升，到预算后反复淘汰旧内容。海岸最后 30 秒的滚动缓存拟合斜率为 -0.017 MiB/min，各关基线结束均在约 256 MiB 内。到达预算前的正常填充不能作为泄漏证据。

写入队列预算 `QueueBytes` 在各关基线约为 7.00、6.89、14.14、2.38、2.08 MiB，窗口内没有持续上涨。该预算包含最近帧所引用的共享状态基线和进行中的写入，`QueueFrames=0` 时仍可非零；不能把这些字节全部解释成待写积压。本轮各基线的真实待写 `QueueFrames` 起止均为 0，逐秒观察到的峰值依次为 1、1、3、1、1 帧。最终封盘的 accepted/written 对账及 UnwrittenFrames=0 证明完成落盘。逐秒读数及阶段峰值保留在 JSON。

本轮已观察到以下工作计数：

- 各基线窗口的绳索 `PointReadCount`、`BoneReadCount` 增量为 0。海岸仍有轻量可见性检查；不能把“不读几何”说成“完全没有检查”。
- 雨林 200 个孢子陷阱初态存在，但基线 `Creatures.GeometryReads` 和 `BoundaryReads` 增量均为 0；未触发时没有持续重读其姿态。
- 静态互动对象的几何、外观、灯光读取在这些基线均为 0；熔炉存在独立的实际动画检查。
- 所有已测窗口的 `NativeParticleStateReads` 为 0，读回录像的粒子状态检查点及其字节数均为 0。特效仍记录原生资源、发生时间及必要参数，真实动画参数或发射器位置变化仍可能读取。
- 物品的保守回查仍存在，例如海岸基线 `FallbackReads=9,906`、雨林 `FallbackReads=3,025`。物品活动、外观及安全回查需分开统计，不能声称所有静态物品原生读取已经归零。

管理堆和 Unity 分配读数包含游戏、其他模组、资源与 GC 垃圾，不是录像系统独占内存。有限的数分钟窗口及阶段末值不足以证明不存在长期泄漏；需要更长静置、重复往返和 GC 后低水位对比。当前数据证明滚动缓存受预算限制，以及本次写入队列能正常收尾。

## 已核验的完整性与仍未覆盖的内容

本次成功路线完成了以下核验：

- 5 次原生普通开箱，在原生完成时间附近都能找到“此前关闭、随后打开”的录像状态。
- 4 次普通篝火点亮和真实关卡根切换；离线检查允许切换边界 2 秒过渡宽限，之后没有发现已关闭旧关主体继续出现在物品、箱子、生物及互动轨道中。
- 雨林两种孢子原生事件各触发一次，独立观察到 `VFX_PoisonExplo` 和 `VFX_SporeExploExplo` 实际出生，录像均有对应事件资源与新身份。其他关没有这些原生对象时标为不可用，不当成测试通过。
- 747 页全部按反向顺序独立读回，43,802 个不同帧与写入数一致；独立特效历史与同时间的页面特效数据一致。
- 10 次跨关正向和反向跳转，测得就绪时间 0.302–0.470 秒，诊断中的物品缺失和玩家骨骼缺失均为 0，恢复后游标继续推进。该结果不能证明每种特效的视觉和音效听感都已人工验收。

原生盘点中的 2 个蚁狮逐对象匹配成功。火山盘点的 3 个老鹰记录了组件 ID，却未记录其 GameObject ID，而预制体型录像按设计不保留场景路径，因此逐对象关联为 `unresolved`；本轮录像确有 condor 轨道，但不能凭种类存在代替这 3 个实例的逐对象通过。后续驱动已补记 GameObject ID。验证器明确报告 `NativeCensusMissing=0`、`NativeCensusUnresolved=3`，没有把 unresolved 算作缺失或完整覆盖。

物品归属检查使用持久保存的生产绑定诊断，将可关联的物品状态与原生关卡根比较；这不是独立的全物品出生清单。未知或全局归属观察仍单列，前一篝火、全局天气及角色随身物品也不能按旧主体简单清除。

本轮没有覆盖森蕈/雾沼的全部内容、蜘蛛抓捕及返回、甲虫完整睡眠唤醒循环、青蛙吐舌/烹饪、老鹰抓放、童军长追击、绳索真实部署和施力、全部物品使用、继续冒险、多人同步及终局地图。未真实出现的行为不得以“读回无错误”替代动作和特效验证。详细待测矩阵保存在测试工具目录的 `coverage-oracle-checklist.md`。

## 工具与复现

可复用工具根目录为 `tools/NativeRouteValidation`；本轮历史会话仍保留在本机 `local/checks/automated-route-audit-0.8.27-20261013`。工具目录包含：

- `driver/RouteAuditProbe.csproj`：显式参数启用的测试伴随插件，原生路线、独立动作观察、1 Hz 指标和保护恢复。
- `driver/NativeRouteActions.cs`：真实地图选择、地面检测、传送和普通互动入口。
- `launch-route.ps1`：检查游戏已退出，备份存档和配置，安装测试探针并启动隔离会话，支持 `GameRoot`、`SavePath` 和 `RepositoryRoot` 参数。`watch-route.ps1` 在 120 秒无进度或超过 1500 秒总期限时终止本次测试进程，并保留失败记录。
- `analyze-route.py`：分阶段时间、缓存、后台队列、CPU 计时、内存和原生工作计数。
- `recording-composition.py`：物理文件对账和压缩前字段字节组成。
- `verify/RouteVerify.csproj`：反向独立逐页读取、帧数对账、原生事件与关卡归属检查。

从仓库根目录运行。每次测试使用新的 `Label`，且先退出 PEAK：

```powershell
dotnet build tools/NativeRouteValidation/driver/RouteAuditProbe.csproj -c Release --nologo -v quiet
& tools/NativeRouteValidation/launch-route.ps1 -Label route-growth-level0-new -Scene Level_0 -FirstWait 150 -LaterWait 45 -FarWait 45 -Biomes 5
```

等待会话生成 `summary.json` 且游戏完全退出，再运行较重的解码与组成分析，避免争用游戏测量期间的 CPU：

```powershell
python tools/NativeRouteValidation/analyze-route.py tools/NativeRouteValidation/sessions/route-growth-level0-new
python tools/NativeRouteValidation/recording-composition.py tools/NativeRouteValidation/sessions/route-growth-level0-new/summary.json tools/NativeRouteValidation/sessions/route-growth-level0-new/analysis

dotnet tools/NativeRouteValidation/verify/bin/Release/net8.0/RouteVerify.dll tools/NativeRouteValidation/sessions/route-growth-level0-new/summary.json tools/NativeRouteValidation/sessions/route-growth-level0-new/analysis
```

测试伴随 DLL 不用于日常游玩。测试结束并退出游戏后，应将 `PeakReplayLab.LocalRouteAudit.0827.dll` 从游戏插件目录移至本地留档目录；保留正式 `PeakReplayLab.dll`。启动器和探针源码、构建及报告应一起留存，避免日后只剩某次统计结果而无法复现路线。

本次数据源位于 `sessions/route-growth-level0-0827a/analysis/` 下的 `route-analysis.json`、`recording-composition.json`、`route-verification.json`，原始动作与恢复结果在会话 `summary.json`。

## 变体路线后续状态

为实际覆盖森蕈和雾沼，另选游戏原生烘焙的 `Level_9`（Shore → Roots → Alpine → Swamp），未在运行中篡改地图变体。

首次 `route-variants-level9-0827a` 已进入雪山，随后检测到 `invalid-data: Invalid full-body joint pose` 并停止路线。没有保存到具体失败字段；后两次经过雪山未重现，因此本轮不声称已修复该偶发错误。0.8.28 给现有骨骼校验补充失败节点编号和字段，正常路径不新增字符串，校验条件未放宽；测试探针另在失败时保存纯关节数值。

第二次 `route-variants-level9-0827b` 正常经过雪山，在进入雾沼时因 `Invalid replay item` 停录。随后使用原生篝火快速推进的 `route-swamp-repro-0827c` 独立重现，并捕获原生 Frog（ItemId 172）的 `Uses=100,000,000`，其他字段合法。原生 `Item.Start` 将 Int32 `totalUses` 原样放入数据项，正常使用会递减到 99,999,999 等值；这不是只允许一个固定值的特殊标记。旧录像校验对世界物品与背包统一限制 Uses<=1,000,000，错误拒绝了游戏合法值。

0.8.28 改为保留原生 `Uses>=-1` 的 Int32 标量；仍拒绝 <-1、JSON 整数溢出和小数。计数不用于数组长度或内存预算，不新增采样、对象扫描或格式字段。5 项针对性回归覆盖世界物品、物品栏、背包、正常递减值、两种解码器和 65 帧跨页倒序读取。完整 ReplayContract **1208 项通过**，Release 解决方案按警告视为错误构建为 0 警告／0 错误。

修复后的 `route-variants-level9-0828final` 已完整完成四关：**462.868 秒、26,701／26,701 帧、488 页、92,998,286 字节（88.69 MiB）**，未写帧为 0，488 页反向读回及独立特效历史一致，5 项实际开箱／孢子事件检查通过，未发现已退役地图普通轨道泄漏。16 次游戏内跨关及事件附近跳转全部恢复推进，就绪时间 **0.302–0.694 秒**，物品及玩家骨骼缺失为 0。存档与配置 SHA 校验不变。
