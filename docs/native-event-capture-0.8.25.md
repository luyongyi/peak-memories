# 0.8.25 原生事件采集与回放

日期：2026-10-13。本页记录代码策略及受保护的游戏内验证；下述体积和耗时不是所有地图、联机人数或整场游戏的保证值。新录像使用 Schema 23、完整录像容器 v4，读取继续支持 Schema 10–22。30 Hz 非玩家场景采样、本地玩家配置频率、队友原生网络频率和 1 GiB 按需解码页缓存保持原有边界。

## 采集和回放边界

| 对象 | 新录像采集 | 跳转后的恢复 |
|---|---|---|
| 原生粒子特效 | 保存资源、出生／结束、种子、运行时模块初态与真实参数变化；移动发射器保留必要姿态。默认不读取粒子数组、不写粒子 checkpoint。 | 以原生粒子资源在纯视觉副本中恢复发射相位；预热窗口最多 60 秒，并受共享分帧预算约束。旧 Schema 23 实验录像中的粒子 checkpoint 仍可读取。 |
| 静态物品、箱子、行李、气球、机关 | 初态完成后以原生拿取、开启、生成、动画和状态事件唤醒；静置时停止几何、外观与灯光的重复读取。持续变化和未知行为保留受限观察。 | 保存真实显隐、材质、灯光、动画时钟及出生／消失边界，按绝对录像时间求值，不执行玩法脚本。 |
| 生物与绳索 | 休眠、挂网或静置时保留原生待机语义；抓捕、受击、攀爬等真正持续动作按最高 30 Hz 观察。 | 原生待机资源与真实活动样本并用；旧录像未采到的动作不能补造。 |
| 声音 | 原生声音池的创建、播放、停止通知维持目录；已知空闲池无需每帧查询原生播放状态。短音效按实际事件边界保存。 | 只准备跳转目标处仍需播放的声音；临时音效及目标处已结束的音效不占用准备队列。 |
| 关卡归属 | 以游戏实际选定且激活的 `segmentParent`、独立篝火和原生 `Biome` 包络判定归属；同一 `Biome` 下位于 `segmentParent` 外的静态物也归属该关。 | 关闭旧关时清除实时采集目录，历史页面保留；带出的物品和无法可靠判属的根级网络对象按独立生命周期处理。 |

原生 `Biome` 包络只在地图根目录建立和变化时确认，不逐帧扫描关卡。包络由该关实际选中的 `segmentParent` 激活；上一关仍激活的篝火不会放行整片旧关，未选变体也不会被当作全局物品。该修复针对早期候选发现的异常：森蕈续档初帧曾包含 8 个未来 `Gloom` 火炬特效，它们位于序列化关卡根之外。修复后新录的森蕈 61 页逐页读取，没有任何 `Biome_4` 资源。新增原生根时的重绑定也改为只查受新边界影响的对象；已采入对象当帧核对，其余对象每帧最多核对 64 个并受约 0.35 ms 的协作预算约束，真实事件发生前仍会先核对归属。

## 跳转准备与剩余短卡

43 分钟、1.55 GB 的旧完整录像在最终 DLL 上完成六次远距离交替跳转，每次目标状态就绪约 0.356–0.725 秒，六次后仍能继续播放；测试内至少包含 0.3 秒的观察等待，不能把该数值当作纯解码时间。页面缓存最高约 450.2 MiB，未在打开时预分配 1 GiB。原录像、存档和配置的哈希在测试前后相同。

旧候选的一次首跳出现约 141 ms 的 `AudioApply`，同帧启动了 4 个未加载的原生音频片段，其中原生播放调用合计约 118 ms。新版在显式跳转和重新缓冲时先筛选目标声音：只有目标处尚在播放的声音进入准备；每个渲染帧最多调用一次 `AudioClip.LoadAudioData()`，即使同步返回也等到下一帧再恢复世界和声音。受抑制的短音效、尚未开始或已结束的单次声音也不做无用的原生样本定位。准备期间暂停回放时钟，并显示“正在准备声音资源…”。单次原生加载不可抢占；加载超时 5 秒后允许继续并记录提示，避免无限等待。最终同源复测中 `AudioPrepare` 最大 38.2439 ms，`AudioStart` 最大 6.5635 ms，没有慢速声音启动。`AudioApply` 最大 77.6316 ms 的调用与全局 GC 完全重叠；排除 GC 重叠的调用最大为 9.0395 ms，不能把 77.6316 ms 归因于原生声音播放。

最终候选还把跨关跳转的地图根、虚空与日夜切换移到缓冲阶段：先按目标状态制定切换计划，每个渲染帧最多执行一次昂贵的原生切换；画面遮罩和提示覆盖尚未完成的场景，控件仍可操作，随后再提交播放。同关跳转保留同步路径；连续改选目标会取消旧计划，并从原生对象当前的实际激活状态重建。上一候选的 `PlaybackWorld` 播放提交阶段最大约 44–58 ms，最终候选最高 0.3057 ms；移出的 `PlaybackWorldPrepare` 单次仍最高 47.3567 ms，这个 Unity 原生调用不可抢占。六次远跳共有 21 帧超过 33 ms、0 帧超过 100 ms；最长帧 87.5722 ms，其中 12 个慢帧与全局 GC 重叠。上一轮同源测试为 28 帧超过 33 ms，运行间存在波动，不能把差值全归因于分帧处理。嵌套计时不能相加，GC 重叠也不证明 GC 独占耗时；尚不能承诺完全没有短卡。

## 游戏内结果

以下三项均使用受保护的本机游戏和独立测试录像。续档通过主菜单原生“继续冒险”，切关走原生篝火与地图根切换；测试阻止存档、设置和成就写入，原存档 SHA-256 在测试前后相同。跨关与旧录像远跳的最终测试载入 DLL 模块版本 `88446bc9-cd4b-49ec-9170-d58ca4fdffd3`；森蕈续档载入较早的候选 `5c6afd77-a620-450b-91b5-4699e46f271b`。中间候选 `38d0f83f-58fa-4e61-bfcf-97a583f6402d` 曾验证跨关与远跳，但未包含最终的地图分帧准备及播放热路径修整，因此以下最终跳转数据只来自 `88446bc9-cd4b-49ec-9170-d58ca4fdffd3`。

|---|---|---|

## 回归与边界

Release 解决方案构建通过且无警告；主回归 1202 项、回放界面 27 项、静物播放 50 项、原生关卡归属 78 项、特效事件 29 项、原生静态事件 24 项、声音准备 10 项及原生声音池 4 项均通过。界面合约覆盖缓冲遮罩与控件层级，游戏内跨关和远跳验证了最终 DLL 的恢复播放；这不等于逐帧视觉审查。当前存档和路线的续档、跨关及长录像远跳均已实测；森蕈续档仍是较早候选，最终 DLL 新增的地图分帧准备和播放热路径修整未在该路线单独重跑 60 秒续档。尚未逐一走遍所有地图、所有生物和多人同步组合。旧录像没有记录到的动作无法事后补回；原生特效视觉重建不运行玩法脚本，也不承诺逐粒子精确一致。
