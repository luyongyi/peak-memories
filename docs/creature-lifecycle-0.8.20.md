# 0.8.20 甲虫休眠与蜘蛛挂网采集

本轮仅生成候选 DLL 与验证资料，没有安装进 PEAK。游戏内原有 0.8.19 DLL 和输入录像保留原样。

## 原生逻辑与采集策略

原生 `Mob.UpdateSleeping` 在甲虫入睡时隐藏可见模型并关闭 Animator。休眠并不把 Rigidbody 设为运动学刚体，隐藏根节点可能轻微漂移；本策略保留隐藏检查点，醒来后重新读取完整当前位置与姿态，不假设根节点物理冻结。

首次登记与每次入睡保存完整状态。睡眠期间仅检查缓存的托管睡眠字段及原有对象激活状态，停止完整骨骼与外观读取。原生 `UpdateSleeping` 完成后通知采集器，唤醒边沿绕过采样截止时间，立即恢复 30 Hz 活动采集。

蜘蛛原生状态分别为 `Idle`、`Dropped`、`Grabbing`、`LetGo`。按本轮追加要求，挂网待机保存末态后停止几何采集，腿部与蛛丝的待机摆动固定在最近状态。初次激活与真实事件有固定 0.25 秒高频初始化窗口，随后保存末态并进入事件休眠；细微姿态变化不能续期。

`Dropped` 下落、`Grabbing` 抓捕、`LetGo` 松手返网均持续按 30 Hz 采集。`BonkRPC` 可在 `Idle` 内播放受击动作而不改变状态，因此同时使用原生 RPC 通知与缓存的 `_stunnedTime` 字段，受击和整个眩晕阶段维持 30 Hz。抓捕、松手、下落、受击 RPC 均使用原生执行完成后的通知，不调用攻击或伤害逻辑。

组件只在登记时查找一次；热路径不新增层级遍历、Animator 查询、距离搜索或逐帧反射。其他动态生物维持原有 30 Hz 策略。声音、粒子及玩家蛛网包裹仍由各自轨道保存，不受蜘蛛事件休眠几何时钟控制。

## 回放与快速跳转

Schema 20 保存生物实际观察时间和活动模式。每次成功读取均更新时间，即使几何未变也保留该次观察时间；骨骼、外观和蛛线数组继续共享。休眠或未激活时保留同一观察，不生成伪采样时间。

播放在真实观察点之间插值，避免全局重复帧造成走一步停一步。动作、采样模式、显隐、层级与蛛线拓扑变化切断插值；对象缺席后重新出现也不跨段插值。活动最大插值间隔 0.15 秒；事件休眠期间直接使用检查点，不为静置蜘蛛等待未来页面。超过活动插值范围时保持检查点。

观察索引复用既有后台分页索引，并计入缓存预算。每页有完整基线，活动插值只读取既有有界后页窗口；休眠对象不追溯出生或唤醒历史。保留按需载入、1 GiB 缓存及分帧构建预算。精彩片段与滚动缓存同步平移观察时间，允许片段开始前的历史检查点。

旧 Schema 10–19 仍可读取；没有观察时钟的旧生物沿用原播放路径和原内存计费。旧版本不能读取新增的 Schema 20，旧录像不会被自动改写。

## 验证口径

合同检查覆盖原生 Harmony 通知、睡眠跳过骨骼读取、唤醒边沿、蜘蛛四种状态和同状态受击、观察插值、缺席重现、片段时钟平移、旧格式与独立页面跳转。

最终生产 Release 使用 `-warnaserror` 构建，零警告、零错误。13 个合同项目共 1,386 项检查通过，其中 ReplayContract 1,096 项、原生生物通知 53 项、生产静态/生物播放调用点 37 项；发布验证工具另有 29 项自测通过。独立审查未发现新增阻塞。

同源离线对照使用最近的完整录像、相同全局帧时间与当前写入器。源录像没有记录原生 `_stunnedTime` 或完整 RPC 回调时刻，离线模型无法识别所有同状态受击窗口；须结合原生通知合同验证，不能将离线轨迹比较当作全部动作的实机证明。工作计数衡量几何、节点和蛛线读取次数，不是 Unity 主线程毫秒或 FPS。

候选尚未进行游戏内画面与帧耗时验收。

## 同源体积对照

最近完整录像长 503.653 秒，共 29,466 个唯一全局帧。使用同一个 Schema 20 写入器，保留全部全局帧时间及其他轨道，基线为 56,184,187 B，蜘蛛挂网事件休眠候选为 45,825,351 B，减少 10,358,836 B（18.44%）。折合这份离线样本约 6.69 → 5.46 MB/分钟，采用十进制 MB。

输入原文件为 Schema 19，大小 51,168,891 B；不能把跨格式原文件与候选的差值当成此次优化收益。上面的 18.44% 使用相同写入器基线。这里只调整蜘蛛，甲虫轨道保持原样，未把旧录像无法识别的睡眠状态估算成实录体积收益。

调度模型的蜘蛛完整几何读取由 15,059 次降为 3,531 次（减少 76.55%），节点槽访问由 893,761 降为 209,486，蛛丝顶点访问由 602,360 降为 141,240。轻量状态检查两者均为 3,005,532 次，没有计作已消除；节点槽数也不等同于 Unity getter 次数或主线程耗时。纯策略代表场景中，连续挂网 60 秒仅初始化和末态共读取 9 次；连续睡眠甲虫 60 秒读取一次，均为合成调度场景，不是新游戏实测。

全部 510 个候选页逆序独立解码、32 个随机页 / 96 次有界跳转、29,466 个唯一全局帧及独立特效历史对照通过。基线与候选的非生物、非蜘蛛解码字段相等，输入原录像哈希未变。源、基线、候选分别有 510、511、510 页，按实际全局时间对齐，不要求物理页边界相同。源到基线只允许已通过生产关节编码往返核对的四元数规范化，最大朝向差异约 0.003458°；其余源字段相等。这不表示序列化文件字节相同。

独立动作对照确认该实录 222 次非待机实际几何变化均保留，观察时间一致，姿态、蛛线和外观按运行时 float32 位模式相同。样本均为 `Dropped`；`Grabbing`、`LetGo` 和同状态 `Bonk` 的采集路径由合同检查覆盖，仍需实机动作验收。挂网待机腿部和蛛丝摆动按本次要求固定，不声称待机动画与原录像相同。

固定待机姿态的差异不能全部称为微小误差：该离线样本的可见骨骼端点世界位置差异 P95 为 0.17545 米，最大 0.40479 米（前左腿末端）；局部旋转差异 P95 为 8.04°，最大 17.50°；蛛丝点差异 P95 为 0.01891 米，最大 0.02694 米。这里使用父子 TRS 组合后的骨骼位置代理，未计算加权蒙皮顶点或屏幕像素误差。旧记录缺少眩晕字段，不能断言所有 Idle 均无受击动作；生产版本用真实眩晕字段和原生 RPC 唤醒保护这条路径。
