# 0.7.1 持续录制队列溢出

用户截图对应 `queue-overflow`。原日志中持续录制接受 312 帧、写入 312 帧、未写帧 0，随后因为队列准入拒绝停止，保留 509,776 字节的 `.peakrun.partial`。后台没有记录磁盘写入异常。

## 根因与真实样本

旧 `FullReplayWriter` 和 `ContinuousReplayWriter` 为每帧累加 `RollingBuffer.Estimate(frame)`，把相邻帧共用的物品、箱子、放置物与生物快照当作独立副本。实际样本每帧估算约 12.10 MB；第一页 301 帧的全量累加约 3.64 GB，而生产解码器保守共享预算为 67.10 MB，相差约 54 倍。

原文件由生产 reader 逐页只读检查：两页共 312 帧。256 个生物目录成员实际为 86 只蜘蛛和 170 个静态孢子陷阱，全部样本尚在未启用区域。陷阱与后续新生物共享 256 个名额，会导致新生物无法进入目录。

同一真实样本、60 Hz 生产者、首段写入停顿约 1 秒的对照：旧版第 12 帧拒绝，队列估算 133,148,006 字节；新版 60 帧全部接受并写入，峰值 51,784,524 字节；完整 312 帧全收全写，峰值 51,837,036 字节，无 fault、未写帧 0，队列最终归零。新输出均用生产 reader 独立逐页回读通过。

证据在 `../../local/verification/queue-overflow-proof-20261006/comparison.json`。原文件 SHA256 为 `ED502D5E04A40C5CAC441D3BE5A7D994C0D2C55D83443DA52F37FDD288083068`，检查前后相同。录制停止后的游戏过程没有进入文件，无法从这份文件补回。

## 修复

`ReplayQueueBudget` 按保留的不可变对象图计量，记录每个对象和共享子数组的引用数，同时计入预算缓存自身开销。新增对象将超限时立即回滚，不遍历完整超大图；共享数组不重复遍历。队列帧和正在写入的帧共用租约，序列化 finally 与失败清理均释放；文件和 JSON 工作不持预算锁。

上限保持 128 MiB／360 帧。真正的唯一数据增长、长期写入停顿或帧数超限仍会停止，诊断包含触发值、限额和已接受峰值。采样率仍由原设置决定。

静态陷阱另有最多 8192 个名额，动态生物最多 256 个；旧详细陷阱仍最多 256 个，不能借新的静态 allowance 塞入数千个完整骨骼模型。紧凑静态记录只保存场景路径、根 TRS 和 `activeSelf`，每个 tick 检查显隐，根 TRS 低频检查；父关卡显隐由已有 WorldFrame 驱动。回放原模型的渲染标志与变换退出恢复，不激活原生玩法根节点。只有原模型已停用而录像要展示爆炸前状态时，才按需使用无脚本副本，最多 256 个同时使用及 16 个闲置；超过上限显示诊断。

原生资产重新核对：`Forest_SporeFungus`、`Jungle_SporeMushroom`、`Jungle_SporeMushroomExplo` 对应三种准确的孢子／毒气爆炸资源，均为单次触发、生成特效、停用自身。`SporeShroom` 是模型子树。资产证据在 `../../local/checks/creature-directory-assets.json`；打包资产数量包含模板与多个场景，不代表当前场景数量。
