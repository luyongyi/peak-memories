## 原因与修复

写入端错误地把一页所有共享内容的展开字节，累加后与**单条 JSON 的 8 MiB**上限比较；页面写入处又重复进行“实际 JSON＋共享展开量不得超过 8 MiB”的检查。读取端一直将 JSON、共享块及整个页面分别限制，因此合法的大场景即使引用后的单条记录很小，也会在第一帧被写入端拒绝。

现在按每页唯一共享块 ID 计费，与读取端一致。重复使用同一块不重复花费展开预算；下一页重新独立计量。修复只调整预算的适用对象，没有扩大数值上限：单条 JSON/单个共享块仍为 8 MiB，整页唯一共享内容展开仍为 128 MiB，解码内存仍为 64 MiB。既有独立页、按需加载、共享块格式和跳转构建路径不变，新增计费在保存线程完成。

完整录制失败改为独立保留的文字状态，普通提示与七秒超时不会把它消除；原生加载界面结束后仍可见，菜单也明确显示已停录。F4 重新创建录像或明确关闭完整录制后才清除。复用原有非交互文字层，不增加周期对象扫描。提示只说明最近片段内存缓存仍保留，不承诺它已经写成文件。

同时修复录像头一直沿用 `PeakReplayLab/0.8.12` 的过期版本标签，新录制写入实际 `0.8.18`，旧文件保留原样。
