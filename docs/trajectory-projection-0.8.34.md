## 省下的工作

常规 JSON 先经过选择性扫描，丢弃字段的名称保留、值替换为 `null`，随后仅构建所需字段。不会解码玩家骨骼二进制，不构建生物、道具、绳索、特效、音效、材质、物品栏或环境状态树。玩家补丁如果只含无关变化和身份，则复用先前的轨迹状态，避免因 60 Hz 骨骼补丁再次分配玩家对象。

跨页共享只允许按需解析玩家排序使用的 kind 9 字符串数组，不解压无关模型／骨骼／生物共享块。原有最多 4 路分页后台解码、128 MiB 批次索引估算预算、通常单遍生成及超限按成员分包保留。该预算不包含全部运行时内存。

对于转义字段名、特殊 Unicode 或字段顺序不同的 JSON，仍通过选择性读取器读取原始输入；识别 Type／结束记录时也不会先构造整棵 JSON 对象。已有回放读取默认关闭此模式。

## 完整性与边界

保留容器索引、页面长度及 CRC、帧数量与时间范围、头部一致性、已登记玩家身份、增量基线、移除冲突、排序排列和实际路线字段校验。`RouteState` 的省略继承、显式空值及部分更新沿用原来的增量规则；不会用默认存活状态替代缺失证据。Schema 10–27 与现有容器版本使用相同兼容判断；新录像仍为 Schema 27／容器 v4。

未读取的轨道不再执行语义校验，其共享内容也不加载。轨迹导出成功仅说明本次所需数据可读，不能视为整份录像的全面播放检查。

现有压缩页混存多种轨道，因此仍需顺序解压主页面、扫描其 JSON 结构并核验页面 CRC。本轮减少的是对象构建、骨骼解码、无关共享块读取和相应临时分配；没有声称完全避免录像读取或解压。若将来要跳过这些主页面字节，需要另设独立轨迹流／索引，属于存储格式改造。
