# 0.8.0 完整录像轨迹上传与验收

以下为 2026-10-07 上线前的本地适配验收记录，文中的 DLL 哈希与线上状态属于当时快照。公开版本以 [GitHub Releases](https://github.com/luyongyi/peak-memories/releases) 的源码标签、构建清单和校验文件为准；服务端启用另需按配套部署说明完成权限安装。

## 使用范围

只适配「持续录制」封存成功的完整录像 `.peakrun`。120 秒回忆片段、录制中的文件、异常 `.partial` 及伪装成最终文件的异常录像均不能上传。

这里的完整录像指一次持续录制封存的文件，不要求打完全部关卡。例如走完海岸、森蕈后结束游戏，仍可投稿；网站只选取每个人有完整起终点及状态证据的已完成关卡。

游戏主菜单操作：

1. 回忆录 → 完整录像 → 录像详情 → 上传轨迹。
2. 后台筛选完成后，核对目标站点、姓名、人数、关卡／难度、点数和实际压缩大小。
3. 点击确认上传。成功显示投稿编号、审核状态及地图匹配状态；失败保留筛选包供重试。
4. 管理员审核通过且对应地图匹配后，打开 Web 首页 → 进入地图 → 顶部「返回」旁的「路线与热力」→ 线路图层，切换「大家的路线」或「热力图」。在对应关卡的现有 3D 地图中按难度、每人显隐及高度层查看。默认收起侧栏并只显示地图，再次点击该按钮可收起并关闭图层。

上传是用户主动操作；录制时没有自动上传、直播连接或新的场景扫描器。上传和筛选限主菜单执行，退出、切场景和关闭插件会取消等待。

## 采集与本地筛选

新录像写 Schema 14，继续读取 Schema 10–13。新增地图元数据在原有地图准备门限之后读取一次：真实构建、场景、轮换编号、已选场景布局、关卡顺序、原生进度平面及 Ascent／自定义／Mini 难度。

每人中心坐标借用已有角色采集，最多 10 Hz；死亡、复活、离开、传送及个人胜利状态变化立即记录。原人物姿态、环境及回放采样策略保持原实现。导出再限制每人至少 100 ms 一个实际观测点；低频录像和缺口不插值补成 10 Hz。

原生 RunId 和共享计时器可能在开局数秒后分开同步。导出使用最后观测到的有效共享身份与时钟锚，保留开局坐标；共享时间原点允许小幅负值。没有共享身份或时钟时，按录像作用域去重，不猜测同局关系。

从原文件按页顺序解码、去除分页重叠并释放页面，只生成单独的 `trajectory-v1` gzip 包。白名单内容为：

| 内容 | 表达 |
| --- | --- |
| 录像／共享对局身份 | SHA256，原生玩家 ID 不外传 |
| 地图／难度 | 构建、场景、布局散列、关卡顺序与可用边界、难度或未知 |
| 每位玩家 | 作用域散列 key、姓名、是否本机观测、状态证据是否完整 |
| 轨迹 | `[录像内毫秒, X厘米, Y厘米, Z厘米]` 整数数组 |
| 少量事件 | 加入、离开、死亡、复活、断点、传送、个人关卡完成 |

原录像、骨骼、外观、物品、声音、特效、体力条、Steam／Photon 原始 ID 不进入上传包。坐标量化误差每轴不超过 0.5 cm。

本地缓存为 `BepInEx/PeakReplayLab/TrajectoryExports/`。包先写独占临时文件再原子完成；失败或取消只清理本次临时文件，不修改原录像。HTTP 仅发送完成包，固定同一只读文件句柄，最多 3 次临时错误重试；取消可结束等待，重复提交由服务端幂等处理。

接口配置为 `cn.mylus.peakreplaylab.cfg` 中 `Routes.UploadEndpoint`，默认 `https://peak.mylus.cn/api/route-uploads`。正式地址要求 HTTPS；本地开发允许 loopback HTTP。上传不跟随重定向。

## 服务端与展示

接口、持久存储及审核命令在配套 `PeakTrailPlatform/server/trajectory-README.md` 中说明：

- `POST /api/route-uploads` 接收 gzip 白名单包，默认 `pending`。内容相同的重传返回已有投稿，不新增存储。
- 按录制当时的构建、场景、布局与关卡顺序分地图组；上传当天的日图不替代旧录像地图。
- 按每个玩家、每次关卡尝试独立筛选。起点、出口、存活和连续性须有证据；中途加入、死亡、传送、离开及大缺口中断尝试，队友通关不替本人补证据。
- 旧录像的难度、个人状态或边界缺失保留为未知，可接收但不冒充完整有效路线。Nadir／Void 没有连续递增的原生 Z 门限，目前不自动统计其完整关路线。
- 只有 `approved` 的完整个人关卡路线进入公开接口。管理员 `hide/reject/pending` 后，下一次查询撤回路线和热力贡献。
- 同局、同玩家、共享时间重叠的记录合并，优先本机角色观测；同名不同人保持独立。没有共享时钟时不跨录像合并。
- 热力按每条完整路线经过的 2 m 三维空间格计一次；保留高度，断点不连接。地图的「线路图层」提供大家的路线、立体热力、高度层和每人显隐；只展示当前具体关卡，山体总览不合并关卡统计。

网页「直播」入口及相关后台轮询默认隐藏，旧实现保留。路线和热力直接作为图层接入「进入地图」的现有 3D 场景，不再使用独立路线收集页；图层不生成角色模型、物品动画或新的渲染循环。地图版本、场景、布局及关卡顺序必须匹配；与录像地图不匹配时显示 `waiting-map`，保留投稿等待对应地图，不向当前地图叠加轨迹。客户端提供的过关证据用于投稿筛选，不是反作弊证明。

## 容量与后台预算

| 限制 | 当前值 |
| --- | --- |
| 单包压缩／解压 | 12 MiB／64 MiB |
| 单包人数／时长 | 16 人／4 小时 |
| 导出点／事件保留预算 | 约 93.2 万点／5 万事件；达到预算明确拒绝 |
| 私有投稿存储 | 2 GiB、10,000 投稿、100,000 路线；孤立文件也计容量 |
| HTTP 工作队列 | 最多 4 个处理中或排队的请求、单个 worker 串行处理、单个接收中的上传 |
| 限流 | 每来源每分钟 20 次上传、120 次公开查询 |
| 单次公开路线 | 最多 200 条、200,000 点；截断明确标记 |
| 热力格数量 | 最多 250,000 三维格 |

大包解压、验证、分关、索引及聚合在后台 worker 执行，不占 HTTP 主事件循环。新 Linux 服务模板将单服务内存限制从 512 MiB 调整为 768 MiB，存储使用静态站点之外的 `peaklive:peaklive 0700` 目录。

合成端到端用正式完整录像写入器、导出器和 C# HTTP 上传器生成／发送：12 秒、2 位同名玩家、242 个点，gzip 1,875 字节、解压 6,160 字节。起点齐全的玩家生成海岸／森蕈有效路线，中途加入的玩家被排除。默认待审核不公开、重复包不增存储、审核后公开、隐藏后路线与热力撤回、并行查询和持久化均通过。

服务端另用延迟退出的任务回归验证：超时或错误事件不会提前释放队列，必须等旧 worker 的实际 exit 才启动下一项。更新代码并重启本地服务后，合成投稿、审核状态和分关计数仍保留，C# 上传器重复提交获得原 approved 回执。

3D 图层保留每段连续路线的起终点标记，不改变原坐标或跨断点连线。GPU 对象在关闭图层、换图、切关或退出时释放；每人显隐复用已生成几何。厘米坐标转米、场景原有 Z 镜像与高度缩放、断点、三维热力格及资源释放已通过 CPU 合同测试，实际画面仍以浏览器验收为准。

浏览器已验证进入地图默认「仅地图」、两条明确标为「仅测试」的合成海岸路线、热力、难度／高度筛选、个人显隐、切换到无数据关卡、关闭图层及返回首页／个人回放。热力用透视空间格避免地形完全遮住线路，保持实际高度，侧栏明确说明。此次样例 233 个热力格，合成门限只覆盖连续海岸区域，不等同于真实整关通关证据；真实投稿仍按原生门限和个人状态筛选。

日图过期提示的原因是更新源使用官方已拒绝的 `2.4` 接口，静态快照停留在 9 月 27 日。已按当前 `2.6.b` 游戏的匹配规则统一使用 `2.6`，本地 `/api/daily` 实测 200，轮换 479 对应 `Level_17`。网页优先同源日图接口，不依赖隐藏的直播功能；保留原有过期判断和跨凌晨 1 点的缓存失效，不修改旧快照日期。

以上大小是合成样例，不代表真实多人长录像的压缩比。没有将真实私人录像发往测试或生产接口。

## 线上状态与待验范围

截至本次只读检查，正式网站仍运行旧提交，轨迹 API 返回 404。本机 SSH 登录可用，但 owner 的 `sudo` 要求本人交互授权；现有身份无法安装 root-owned unit／launcher 和私有目录。

配套项目已准备 `deploy/enable-trajectory-service.sh` 和 `deploy/trajectory-enablement.md`：先审查并执行 `prepare`，只备份及准备目录，不替换服务；发布独立测试的本功能提交后，`activate` 核验精确提交再安装，失败恢复原配置。现有 Web 工作树包含其他相机修改，需从远端 main 隔离本功能提交，不能直接发布整个工作树。

因此当前默认正式地址尚不能成功收录；Mod 会显示失败并保留筛选包。线上启用后还需以新版实际录制验证原生菜单布局、多人中心轨迹、各关边界和上传体验。游戏 FPS、1% low／0.1% low 及 Unity 显示尚未实测，不能以合同测试代替性能结论。
