# 0.8.35 游戏内轨迹验收与部署状态

2026-10-15。按用户要求，在真实图形 PEAK 的 Unity/Mono 进程中测试已安装 DLL，并合并、部署 Web 优化。此前独立 .NET 8 测量见 [轨迹实测报告](trajectory-validation-0.8.35.md)；下列原生结果另列，不能与 .NET 8 时长混用。

## 游戏内测试

使用 [显式启用的伴随工具](../tools/NativeTrajectoryValidation/README.md)，从真实 Title 场景打开录像库，等待真实可播放卡片，调用生产轨迹准备、生产菜单任务完成处理、上传确认和回执路径。未伪造录像卡片或放宽条件。图形设备为 Direct3D12；测试发生在主菜单，不能替代游玩期间的 FPS 测量。

唯一测试改动是将本次导出目录和内存中的上传地址指向新的本机私人会话目录及 `127.0.0.1` 接收服务。正式解码、压缩、HTTP 和回执代码照常执行。写入保护先于内存地址修改，正常退出后逐一核对原生存档、配置和正式 DLL；未将真实测试轨迹上传到生产站点。

基线为 0.8.33，候选为先前已经测量并安装的同字节 0.8.35。两版各启动一个独立游戏进程，先运行候选再运行基线；系统缓存和其他后台程序未控制。近期录像每版各两次，大录像候选一次，不属于多轮交替中位数。

旧版大录像轮次在约 187.83 秒处以 `OperationCanceledException` 结束，生产菜单没有得到成功包，整个旧版会话明确记录为 **Passed=false**。取消来源未确定，不能把该时长当作完成耗时，也不能以此计算大录像游戏内加速倍数。两个已完成的近期录像轮次可以独立比较。新版全部四轮均通过。

新版大录像仍需约 100.5 秒，明显长于独立 .NET 8 的 29.9 秒。现有主页面仍混存大量旧数据，必须解压、扫描文本及校验；本轮没有分离独立轨迹流。这项原生结果保留了剩余限制，不能以离线数字代替游戏内表现。

## 操作与接收结果

- 近期录像正常导出、上传和本地回执均成功；接收端首次返回 201。
- 同一录像再次导出／上传正确识别为重复，返回 200，未新增索引。
- 新版大录像在实际后台工作尚未结束时执行取消，约 2.028 秒确认原任务已取消并清空；随后重新准备成功，完成上传和本地回执。
- 接收端共核验五份成功原生导出包，最终只有两份不同录像索引；存储的全部白名单内容与对应输入一致。
- 两种录像解压后的完整 JSON SHA-256 与先前 .NET 8 对照相同；Mono 与 .NET 的 gzip 字节长度有差异，未将这种压缩实现差异误判为轨迹内容变化。
- 测试结束后两个游戏进程均退出，原生存档仍保持原来的不存在状态，全部原有配置摘要一致；仅正式模组配置的注释版本头发生过变化，退出监视器确认设置完全相等后恢复原始文件。
- 临时伴随 DLL 已移除，内存里的上传地址已恢复；最终正式 DLL 为 **0.8.35**，SHA-256 为 `30919677FEC9A00F78BAC39FEBB62A4F8283EEC759DE8BF7515885D54B91CCCC`。

## 工具审查修复

原生测试工具的退出监视器补充有界 `WaitForExit`：请求终止后必须由原进程句柄确认退出，才能恢复配置或移除伴随 DLL。15 秒内无法确认时保留文件并写出清理延后失败，避免把异步停止误报为已经退出。该修复只涉及测试工具，正式 DLL 没有重新编译或改变。

原始日志、实际包、配置备份和录像均保留在被忽略的本机私人目录。提交中只包含工具源码和不含玩家身份／坐标的汇总报告。
